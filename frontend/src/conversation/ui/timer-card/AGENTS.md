# Timer receipt presentation

`index.ts` composes a supplied recovery presentation and selects five newest
polls. `header.ts` owns state/identity/tier; `metadata.ts` owns instruction,
command and cadence; `poll.ts` owns the bounded reason preview and complete
failure evidence. `labels.ts` owns predicate verdicts and countdown text.
`contracts.ts` owns display types and preview policy. `interactions.ts` owns
card-local disclosure and in-place countdown paint, with no owned listeners.

The scheduler, recovery cache and shared demand-scoped ticker stay external.
A due timestamp is a hint, never trigger authority. Do not reverse-copy the
complete poll log, classify readiness from prose, or introduce another timer.
Collapsed/invalid countdowns release ticker demand; expanding a card reuses the
existing demand port. Static actions read their own row rather than global IDs.
Poll ID/number keys the line and detail so new checks cannot inherit reader state.
The three `08-timer-receipt-*` style owners own paint and caret state; icons
carry no inline presentation style.
All fields stay escaped; raw parse failures, tools and command output remain
available as evidence. Content owners cannot import the facade or runtime globals.

Verify typed owner/countdown/interaction tests, Timer ID and predicate/i18n fault
harnesses, real-browser checklist/Timer fixture, then `npm run check:frontend`.
