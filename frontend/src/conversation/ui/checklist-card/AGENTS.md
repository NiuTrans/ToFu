# Checklist presentation

`index.ts` composes one native disclosure from same-occurrence metadata.
`items.ts` reads each status once, projects SVG states and counts completed
items in that pass. `details.ts` owns verdict notices, the complete explanation,
breadcrumbs and accepted revision history. `contracts.ts` describes display
inputs; header controls are demanded only for a visible card. `segment-timeline/checklist-history.ts` derives accepted display history; the
retained dispatcher coordinates the context rail.

Never classify rejection from prose, hide rejected/noop occurrences, merge
unrelated calls or move the explanation into the header. No DOM, timers,
network, state store or content-to-facade imports belong here. The retained
rich adapter disappears with core dispatch migration.

Verify the typed owner tests, checklist explanation/revision and wire-parity
harnesses, real-browser checklist/Timer fixture, then `npm run check:frontend`.
