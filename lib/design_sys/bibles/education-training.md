# Education & Training Bible

> Courseware, job-skill training, operation guides, public education,
> onboarding. The reader's task is not to glance — it is to form
> understanding they can retell, methods they can execute, actions they can
> transfer. **Design the learning first, the pages second.**

## The learning task comes before the style

Write down before producing: the learner (level, prior knowledge, confusable
terms), the usage (projection / self-study / print), the entry state (what
they cannot do yet), the exit capability (what they can explain / judge /
operate afterwards — observable), the material boundaries (external facts vs
team inference vs fictional practice material), and the real task where this
gets applied. Every visual choice must answer: it helped the learner SEE
which relationship, REMEMBER which step, or COMPLETE which judgment.

## The teaching loop

Default path: **orientation → comprehension → demonstration → practice →
feedback → transfer**. A short deck may compress stages, but a missing stage
must be a decision, not an accident.

- Titles foretell the takeaway: question sentences, conclusion sentences, or
  "action + object" — never "Background" / "Overview".
- One page = one primary learning action (concept / method / process /
  demonstration / practice / feedback). Key definitions, steps, and answer
  criteria are ON the page — never delegated to a presenter's live fill-in.
- Practice material may be fictional but is LABELED "practice scenario".
  Answer pages and question pages are distinguishable at a glance.

## Density: full content; whitespace has a job

- Courseware is not a poster and not a shrunk script. Default medium-leaning-
  full: ~60%+ of a body page's main area carries meaningful text, figures,
  flows, or exercises (a guardrail, not a hard ratio).
- Body pages have ≥ 3 layers: learning question/conclusion title → one main
  exhibit → one explanation/task/check/source layer.
- No consecutive "one sentence + big blank" pages except covers, section
  openers, key manifestos, and closing pages — and those need an explicit
  teaching reason (pause, memory anchor, emotional close).

## Division of labor (nothing impersonates anything else)

- Text explains meaning/boundaries/conditions; graphics reveal real
  relationships (flows for sequence, nesting for hierarchy, parallel regions
  for comparison, chains for causality — cycles only when a genuine loop
  exists); examples lower abstraction with their teaching role labeled;
  exercises test mastery.
- One structural diagram = one primary relationship. Every connector has a
  direction or a meaning. Delete decorative arrows and filler nodes.
- Images only when seeing beats describing; each image labeled with its
  purpose (evidence / operation / situation). Without reliable data, use
  schematic structures or qualitative comparison — never invent
  realistic-looking precise values.

## Visual system minimums

- One main content area, one title anchor, one left axis, fixed
  page-number/source positions; page-type variants share the grid.
- One first visual entry per page: question/principle first, main exhibit
  second, explanation/task/source third.
- Body text ≥ 4.5:1 contrast; insufficient contrast is fixed by changing
  text or background color — never patched with shadows/strokes.
- Without brand guidelines: neutral ground + ONE structural color + ONE
  low-frequency semantic color. Colors carry fixed meanings (chapter, role,
  state) and are ALWAYS redundantly encoded with text/shape/position.
- Cards only for genuine grouping/operable regions; rounding, strokes,
  capsules chosen ONCE and held. Default Office charts, rainbow palettes,
  thick table frames are redone.

## Motion notes (video)

- A video beat maps to ONE learning action: concept beats use label+subject,
  process beats use step chain, practice beats hold on the task. Reveal in
  the teaching order (question → exhibit → check), and let the answer arrive
  AFTER the question has been read — the pause is pedagogical, not dead air.

## Final cut

For every element ask: "if I delete this, what does the learner lose?" If
the answer is only "the page looks emptier" — delete it. What fills a page
is definitions, examples, judgment criteria, exercises, feedback, transfer —
never decoration.
