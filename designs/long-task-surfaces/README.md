# Chat 与工作室中的长任务

交互设计提案，2026-10-26。依据本机运行中的 Tofu 前端与现有组件预览，
不是已上线功能或新的 API 合同。所有原型内容均为合成示例；无真实任务、
网络 API、模型调用或本地持久化。主题与字体引用现有源文件。

## 打开与演示

从仓库根目录运行 `python3 -m http.server 15175 --bind 127.0.0.1`，打开
`http://127.0.0.1:15175/designs/long-task-surfaces/`。

- `#chat`：同一项目中的任务对话；默认视图。
- `#workbench`：同一任务的工作台。
- 顶部“查看状态”切换合成示例，不是任务命令。
- 选择 A/B 后切换视图，问题和操作回执保持一致。
- 在 Chat 点击“补充任务要求”再发送；取消定向后发送普通消息，工作台不继承它。
- 打开文献对照或实验草案，可关闭回到来源、展开工作台，或引用到当前输入框。
- “任务控制”区分本轮后暂停与停止整个任务。
- “新目标”展示精简表单和创建请求预览，不启动任务、不继承示例成果。

## 实际观察

实测入口为运行中的 `http://127.0.0.1:15000/`。检查了桌面 Chat、模式菜单、
Coordinator、工作室、研究入口、长期探索创建页、论文工作区，以及 390px
工作室。另检查了源码组件的 populated program 预览，后者只有合成数据。
截图留在 `output/playwright/long-task-design-20261026/`，不作为持久契约。

| 实际页面 | 观察 | 对设计的影响 |
|---|---|---|
| Chat | 已有项目与会话两栏、项目 Coordinator、工作清单和输入区模式菜单 | 复用当前导航层级，不增加第三层任务树 |
| 桌面工作室 | 中央办公室场景占据主要空间，任务进展在右侧窄栏；角色、家具入口与工作阶段并存 | 将当前判断、待处理问题和成果作为默认工作区；场景保留为可选视图 |
| 移动工作室 | 任务面板已排在场景之前 | 保留这一优先级并推广到桌面 |
| 研究入口 | 切入后原工作室导航消失；空状态没有明显返回控件 | 所有领域视图保留项目上下文、返回对话和同一任务标题 |
| 研究模板 | 两个按钮显示 `evolution.research.template2/3` | 独立的文案缺失问题；产品落地前修复，不将其解释为设计选择 |
| 长期探索创建页 | 首屏为目标、验收、目录、模型、失败策略、推进方式组成的长表单 | 目标优先；范围和验收按需展开；明确展示推进节奏 |
| 论文工作区 | 已有论文库、阅读区、右侧问答/报告等工具区和返回对话 | 复用阅读与预览能力；把产出工具关联到统一工作记录 |
| 当前等待中的一个工作室任务 | 阶段标签为“正在记录结果”，等待计算的文本出现在“交付成果”中 | 等待原因、执行状态、成果可用性和验收结果必须分别投影 |

最后一项是页面观察，不推断后台执行是否异常。没有启动新研究、实验或模型请求。
页面正常读取本身可能包含应用既有的恢复行为，检查未验证其所有后台副作用。

## 决定与替代方案

**问题：** 相同目标分散在 Chat Goal、Studio Run、Program、Research 与 Paper
中；用户切换时失去原来的项目和会话位置，也看不出操作对哪一次执行生效。

**决定：** 以现有项目与会话为导航骨架，展示同一目标的两种布局。
Chat 保持约 760px 的阅读尺度，用顶部轻量状态条、阶段汇报、成果入口和问题卡
承载长任务。工作台默认展示当前判断与不确定性、方案比较、已确认里程碑；
下一步和任务交流在相邻区域。窄屏将需要处理的问题放在内容之前。
工作列表替换第二栏的当前视图，不增加第三栏导航。

**替代方案：** 新增全局任务产品和独立状态库会制造第二个来源；把完整后台
控制台塞进 Chat 会压缩阅读空间；保持办公室场景为唯一默认主区会让成果和
判断持续处于次要位置。办公室可作为用户选择的团队视图，原型未重建场景。

**问题：** “发消息”“暂停”“完成”在不同入口含义不同。

**决定：** Chat 补充带明确任务范围，普通消息不修改任务；工作台输入默认指向
所选任务。已接收与已采纳分开。暂停描述为“本轮结束后暂停”，停止指整个任务；
中断后新尝试保留历史；成果已生成不表示验收通过。原始阶段汇报不随当前状态
被改写。原型的状态切换仅用于比较布局，不代表后端已支持这些共同能力。

**替代方案：** 根据最近打开页面猜测消息归属可能改变错误任务；所有恢复都叫
“继续”会掩盖重做副作用；一个 completed 状态不能同时证明产出、评审和科学结论。

## 复用和实施边界

- 共用投影与渲染：`lib/production/work_unit.py`、
  `frontend/src/conversation/ui/work-unit/`、普通 Turn 呈现和任务事件。
- 项目工作区与 Coordinator：
  [现有产品设计](../project-coordination/README.md)、
  [当前运行契约](../../docs/PROJECT_COORDINATION.md)。不增加项目负责人或角色层级。
- 工作室与领域视图：`frontend/src/features/evolution/`；论文阅读和预览：
  `frontend/src/features/paper/`。生产按钮、主题、i18n 和生命周期沿用原有 owner。
- 当前 Chat Goal 的新用户消息可能抢占旧执行，参见
  [执行模式](../../docs/TASK_EXECUTION_MODES.md)。自由继续聊天与后台长任务共存，
  需要明确复用现有 durable run 的生命周期和消息投递，不能通过界面伪装完成。
- 当前通用任务列表主要读取 live registry，不能单独成为长期历史来源。
  统一列表应投影各领域持久记录，并关联现有 owner，不能复制新的执行状态机。
- 仅在 owner 提供真实能力时显示相应控制；program pause、研究恢复、运行取消
  保持各自语义和权限，前端不可退化成直接停止一个子 task。
- 不在本提案中迁移历史、改变预算或资源规则、修改事件 schema、运行模型，
  或宣称领域进度与任务消息已经接通。

## 视觉与浏览器验证

保留 Tofu 的 `#F7F1E6` 纸色、`#F1EADC` 导航底色、`#FFFEFA` 阅读面、
`#8F5126` 焙茶色动作，以及 Sora/系统中文字体。继承主题 tokens，
避免在研究页突然换成另一套冷灰导航。突出“当前判断→依据→下一步”的内容层级。

检查两视图同步、普通/定向消息隔离、原文预览与返回、键盘 tabs 与 dialog、
五种示例状态，以及桌面和 390/320px 横向溢出。原型检查不能证明真实后端恢复、
真实实验质量或生产前端已完成改造。

本次 Chromium 实测的 31 项检查通过，完整结果见 [verification.json](verification.json)。
检查覆盖 1440、1024、768、390、320px；没有 JavaScript 错误或 API/修改请求。
脚本使用显式页面就绪等待与独立 fixture 重载，防止把切换视图误当作重置任务。
本机 CLI 包装脚本缺少执行位，通过 bash 启动；浏览器指定已安装的 conda
中文字体配置，修复截图环境的缺字。没有把缺字视为应用缺陷；其他操作系统的
字体度量仍可能不同。六张合成截图约 0.8 MB，不增加运行时存储或后台服务。
