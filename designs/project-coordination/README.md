# 项目 Coordinator 产品设计

Coordinator 是用户的项目入口。用户提出诉求后，它创建独立的普通 Worker 对话，分工、等待结果、审阅、安排后续工作并主动汇报。用户通过聊天调整方向，通过节点图理解工作和进入任意 Worker。

本目录记录产品决策与交互设计。已实现的行为、资源边界和验证入口以 [PROJECT_COORDINATION.md](../../docs/PROJECT_COORDINATION.md) 为准；机器接口以其中链接的契约为准。早期分阶段计划保留在 Git 历史，不再作为当前能力说明。源码合入、隔离验证和在线加载是三个不同的交付事实。

## 产品决策

问题：逐个建对话、搬运结果和催办，会让用户继续承担项目负责人工作；只有完成／失败卡片也无法解释分工和下一步。

决定：沿用一个 Coordinator 普通对话，负责拆分和决策；Worker 是可直接访问、有独立历史和执行身份的普通对话。聊天保留目标与用户反馈，图形工作区展示 Coordinator、Worker、依赖和返工关系。选择节点后查看依据、交付和对应对话；不引入第三层侧栏。

排除的方案：隐藏临时子 agent 代替 Worker；新增私有执行循环；将普通消息当成新的真人授权；让用户为每个 Worker 重复点击批准。

### 决定：请求不设花费上限，以完成任务为目标（2026-10）

问题：每条请求原有 200 万 token、128 次模型调用、4096 次工具调用和两小时的共享上限，每个 Worker 最多 16 次模型调用。真实请求（`coordinator-1a390889…`）在约 9 分钟内全部停下：Worker 因“先前的模型用量尚未确认”被拦截，失败的尝试又按整份额度计费，Coordinator 随即报告“需要新的预算”。用户必须反复回来解释和授权，违背了“交代一次、之后离开”的目标。

决定：Coordinator、Worker 和续跑都不设 token、模型调用、工具调用或时长上限；用量只记录和展示，不再拒绝工作。缺失的用量回执只记为下限，不阻止下一次调用。仍然保留的边界不是花费：并发数跟随机器容量；用户的 Stop、取消和解绑；每个 Worker 的独立工作区和发布门禁；未知外部效果不自动重放。

排除的方案：保留可选上限但默认关闭（用户明确要求完全移除）；只调高默认额度（只是推迟同样的失败）；按失败重新申请预算（仍需用户在场）。

## 当前完整路径

1. 用户在项目 Coordinator 中提出诉求。当前真实输入、项目归属、绑定版本和能力配置构成派工边界。
2. Coordinator 在第一条消息上就把诉求整理成具体计划，并自动创建普通 Worker，给出范围、验收标准和上下文。并行数量跟随实际机器资源；用量只记录，不设上限。开放式诉求先落成可完成的具体计划，其中至少包含一项高杠杆、有突破性的工作，而不是只做零散修补。
3. 等待走既有任务通知，不靠付费模型轮询。已完成的确切结果可成为依赖；待审阅或待发布时，下游保留原授权并等待。
4. Coordinator 审阅证据，安排下一阶段或关联返工。代码使用已有隔离工作区和发布门禁，结果完成与实际交付分别记录。
5. 有意义的里程碑、阻塞、决定和交付进入 Coordinator 的规范助手消息，产生侧栏未读。浏览器离开、重连或丢失推送后仍可恢复；通知不代表用户已读或同意。
6. Worker 结果自动恢复 Coordinator，没有期限。失败的 Worker 由 Coordinator 重新委派（缩小范围或换方法），而不是交给用户。恢复同一真人输入保留原任务、能力和去重键；新的真人消息可查询、审阅和取消当前绑定下的旧工作。自动续跑只控制原请求。
7. 需要用户决定时，Coordinator 发出带推荐选项的决定报告并登记等待期限，其他独立工作继续。期限内用户回复则按回复执行；超时未回复则按推荐选项继续，并在报告中说明。
8. Coordinator 连续多轮没有新进展（含自身失败）时按退避间隔重试；退避用尽仍无进展，才发出阻塞报告请用户介入。
9. 只有已审阅、实际交付的未取消工作全部满足要求，才能提交完成回执。

## 用户体验与成本

节点工作区优先展示具体任务和联系，完成历史按页读取；选择、缩放、回到最新和进入对话沿用共享控件。输入始终是自然语言，详细授权与交付操作保留在按需展开的区域。窄屏和三主题的实际组件浏览器测试是布局依据。

请求不设花费上限。界面只展示本次请求 Coordinator 与 Worker 的合计用量（token、模型调用、工具调用），用量回执缺失时标为下限。报告应说明结果、影响和下一步，避免重复播报普通状态。

持久分段存储移除了旧的项目终身 128 条派工限制；单页最多 32 条。当前请求的预算聚合仍读取该请求的证据，完整恢复仍有历史扫描，不能把单任务点读的性能结果当作所有操作的固定成本。

## 边界和演进

普通自动 Worker 目前面向本地 Git 项目。远程／非 Git 工作区和跨项目协作不属于已验证能力。Worker 代码由 Coordinator 审阅后自动发布到当前分支；发布仍经过隔离验证，规范检出有未提交改动或其他对话正在使用时会暂缓并自动重试。有限责任与明确授权工具保留各自契约，不能借 Coordinator 扩权。未知外部效果不自动重放，Stop、解绑和撤销不能被迟到消息恢复。

验证使用真实任务、工具、存储和浏览器边界，昂贵模型传输采用受控替身；不以此宣称所有模型都会做出理想拆分。当前高级全项目范围撤销保留 128 个精确目标上限；超过时明确拒绝部分撤销并保留逐任务入口。
