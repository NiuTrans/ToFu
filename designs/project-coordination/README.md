# 项目 Coordinator 产品设计

Coordinator 是用户的项目入口。用户提出诉求后，它创建独立的普通 Worker 对话，分工、等待结果、审阅、安排后续工作并主动汇报。用户通过聊天调整方向，通过节点图理解工作和进入任意 Worker。

本目录记录产品决策与交互设计。已实现的行为、资源边界和验证入口以 [PROJECT_COORDINATION.md](../../docs/PROJECT_COORDINATION.md) 为准；机器接口以其中链接的契约为准。早期分阶段计划保留在 Git 历史，不再作为当前能力说明。源码合入、隔离验证和在线加载是三个不同的交付事实。

## 产品决策

问题：逐个建对话、搬运结果和催办，会让用户继续承担项目负责人工作；只有完成／失败卡片也无法解释分工和下一步。

决定：沿用一个 Coordinator 普通对话，负责拆分和决策；Worker 是可直接访问、有独立历史和执行身份的普通对话。聊天保留目标与用户反馈，图形工作区展示 Coordinator、Worker、依赖和返工关系。选择节点后查看依据、交付和对应对话；不引入第三层侧栏。

排除的方案：隐藏临时子 agent 代替 Worker；新增私有执行循环；绑定角色后无限自动花费；将普通消息当成新的真人授权；让用户为每个 Worker 重复点击批准。

## 当前完整路径

1. 用户在项目 Coordinator 中提出诉求。当前真实输入、项目归属、绑定版本和能力配置构成派工边界。
2. Coordinator 自动创建普通 Worker，给出范围、验收标准和上下文。并行数量跟随实际机器资源；付费调用和工具使用共享本次请求额度。
3. 等待走既有任务通知，不靠付费模型轮询。已完成的确切结果可成为依赖；待审阅或待发布时，下游保留原授权并等待。
4. Coordinator 审阅证据，安排下一阶段或关联返工。代码使用已有隔离工作区和发布门禁，结果完成与实际交付分别记录。
5. 有意义的里程碑、阻塞、决定和交付进入 Coordinator 的规范助手消息，产生侧栏未读。浏览器离开、重连或丢失推送后仍可恢复；通知不代表用户已读或同意。
6. Worker 结果可在原请求预算和期限内恢复 Coordinator。恢复同一真人输入保留原任务、能力、去重键和额度；新的真人消息可查询、审阅和取消当前绑定下的旧工作。自动续跑只控制原请求。
7. 只有已审阅、效果已确认、实际交付的未取消工作全部满足要求，才能提交完成回执。需要决定、额度耗尽或连续没有可验证进展时，明确汇报原因。

## 用户体验与成本

节点工作区优先展示具体任务和联系，完成历史按页读取；选择、缩放、回到最新和进入对话沿用共享控件。输入始终是自然语言，详细授权与交付操作保留在按需展开的区域。窄屏和三主题的实际组件浏览器测试是布局依据。

每次新请求的默认共享额度为 200 万 token、128 次物理模型请求、4096 次工具调用和两小时，可在设置中调整后续请求的默认值。已经接受的请求不因刷新、恢复或改默认值补充额度。结果不确定时保留花费预留。报告应说明结果、影响和下一步，避免重复播报普通状态。

持久分段存储移除了旧的项目终身 128 条派工限制；单页最多 32 条。当前请求的预算聚合仍读取该请求的证据，完整恢复仍有历史扫描，不能把单任务点读的性能结果当作所有操作的固定成本。

## 边界和演进

普通自动 Worker 目前面向本地 Git 项目。远程／非 Git 工作区、跨项目协作、无人授权的长期使命和自动续期不属于已验证能力。有限责任与明确授权工具保留各自契约，不能借 Coordinator 扩权。未知外部效果不自动重放，Stop、解绑和撤销不能被迟到消息恢复。

验证使用真实任务、工具、存储和浏览器边界，昂贵模型传输采用受控替身；不以此宣称所有模型都会做出理想拆分。当前高级全项目范围撤销保留 128 个精确目标上限；超过时明确拒绝部分撤销并保留逐任务入口。
