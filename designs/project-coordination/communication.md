# Coordinator 通信与恢复设计

当前行为由 [PROJECT_COORDINATION.md](../../docs/PROJECT_COORDINATION.md) 和其机器契约定义。本页解释产品决策；过去的协议草案保留在 Git 历史。

## 消息和执行

问题：把消息送达等同于执行，会造成重复派工、越权唤醒以及“收到”被误解为“已完成”。

决定：同项目普通消息是持久上下文，有自己的考虑回执，不自行唤醒 Worker。派工通过已有授权、command、Turn、Attempt 和 task 完成；主动面向人的报告通过规范助手 Turn 发布。所有路径携带明确 owner、project 和对话身份，不建立另一套任务状态机。

排除的方案：私有 Coordinator 轮询循环；将通知当用户输入；把结果正文的“完成”当成正式交付；用临时内存 inbox 代替耐久证据。

## 一次请求的推进

真实用户请求确定 Worker 能力、模型、预算和期限。每次派工具有稳定去重键，确认丢失时重试同一个命令；不额外创建执行。Worker 使用普通对话和隔离工作区，结果保持确切 Turn/Attempt 及 revision。

Coordinator 使用任务终结通知等待，不消耗模型轮询请求。上游结果固定 grant/result revision，代码同时固定 checkpoint；下游等待审阅和真实发布。返工是带原审阅版本引用的新授权，旧结果和审阅不被改写。

Worker 结果、交付通知和启动恢复可触发原请求的有限续跑。自动输入保持 synthetic 身份，只继承原来的不可变策略。并发唤醒与确认丢失使用同一授权和普通执行入口。

物理重试同一真人输入保留最早派工身份、能力和共享额度；用户的新指令可以查看同绑定下的项目历史并处理已有 Worker，不能因为换了物理 Attempt 就把项目当作空白。自动续跑可以读历史，但不能控制另一条真人请求的任务。

## 主动汇报和未读

`report_to_user` 发布有意义的进展、阻塞、决定和验证后的交付。报告正文属于普通对话投影；辅助记录只保存重试意图和最新报告／已读指针，不保存第二份聊天历史。

侧栏未读依据耐久指针，推送只提示重新读取。离开浏览器或断线不丢报告；显式展示并确认后才推进已读水位。重复报告命令幂等，晚到旧确认不能清除新报告。已读不构成同意或扩大权限。

## 停止、失败与成本

停止某个 Worker 撤销其精确授权并取消关联 Attempt，结果和已发生改动保留。用户输入优先于自动续跑；停止、解绑、原始来源失效后不得恢复旧权限。取消不等于回滚。

完成回执要求全部未取消 Worker 有确切已接受结果、已结算效果和实际交付。缺少人类决定时发布决定／阻塞报告；期限或额度耗尽，以及连续没有新工作、审阅、交付证据时明确停止续跑。等待仍在运行的 Worker 不算无进展。

初始 Coordinator、Worker、物理重试和续跑共享预算。未知模型用量或未知工具效果保留预留，不盲目重放。并发按机器容量探测，耐久用户证据不因缓存回收而丢失。

## 验证

当前权威文档列出独立派工、结果驱动续跑、Stop、重复确认、预算守恒、主动报告和三种存储的测试。模型传输采用受控替身；真实 native 流程覆盖普通文件／shell 工具、隔离工作区、发布、重启和未读恢复。付费模型质量与在线部署需各自的证据。
