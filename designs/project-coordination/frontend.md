# 项目三级协作前端更新规格

状态：部分交互已实现；尚未提供的派工、依赖与持续责任操作仍为待实施规格。依赖[总体计划](README.md)与[通信语义](communication.md)。面向现有 Tofu UI 的渐进更新，优先复用项目、普通对话、工具证据和交付入口。


首批采用“项目工作区”按需抽屉，复用现有聊天画布和两级侧栏；绑定及真实工作投影的权威见[当前模块文档](../../docs/modules/conversations_project_brain.md)。[交互比较原型](preview.html)提供固定入口、标题双模式、工作抽屉三种方案；它使用明确标记的演示数据，不承担真实派工。`capture.py` 用真实 Chromium 对三主题和 1440/390/320 宽度生成截图并验证键盘、返回焦点与工作跳转。三级职责不映射成三级树；专家入口仍只在普通对话内按需展开。

### 当前通信披露

`frontend/src/features/project-message-receipts.ts` 只在用户展开时读取当前对话的消息预览，不轮询、不派工。输入状态与明确考虑决定分别显示，正文最多 256 字符；更早消息使用稳定 ID 向前分页，存储失败不得表现为空邮箱。关闭／切换项目或同项目会话后，迟到结果不能混入新上下文。

`/api/v4/project/coordination/messages` 是 owner/project 校验的只读投影；严格字段来自 `contracts/project_messages_v1.json` 并由生成器派生 TypeScript。演示原型只使用标记的假数据；Chromium 验证的是实际组件渲染、输入／考虑差异、历史分页、无横向溢出和键盘返回，不证明在线服务已加载，也不验证未开放的自动派工。

## 1 信息架构与视觉层级

项目是工作入口。项目内有一个明确标记的 coordinator 主对话，其下的普通对话显示承担的工作，普通对话内部再按需展开 subagent。人随时可以找 coordinator 或任一普通对话主 agent。

```text
项目
  项目协调                  当前目标 · 需要我决定的事项
  前端改进对话              正在执行 · 等待后端接口
    专家与子任务（按需展开）  稳定身份 · 本次执行状态
  后端优化对话              结果待验收
  性能验证对话              空闲 · 上次结果可继续
  共享文件与交付物           来源 · 版本 · 验收 · 整合
```

名称以工作内容为主，角色和模型为辅助。默认不显示一整棵不断闪烁的 agent 树，也不要求用户理解 Swarm session 或物理 task ID 才能处理阻塞；诊断详情仍可查看稳定 ID。

### 1.1 三个稳定入口

| 入口 | 主内容 | 辅助内容 |
|---|---|---|
| 项目协调 | coordinator 主对话与输入 | 当前工作、需要决定的事项、近期交付 |
| 普通对话 | 原有主 agent 对话与输入 | 任务来源、项目约束、相关通信、subagent 与交付 |
| 文件与结果 | 项目长期文件、候选修改与产物 | 来源、版本、验收、整合位置和相关对话 |

它们是同一权威数据的投影，不另建一套浏览器任务库。默认项目工作概览可以嵌在主对话旁；是否采用抽屉或双栏由现有壳层和屏宽决定，不先引入全局 Tasks 页面。

## 2 项目协调界面

主对话持续可输入。Worker 执行不让输入框保持全局 busy；发送中的单次命令显示自己的提交状态。Coordinator 的回复和后台报告分清来源，不把报告冒充人类发言。

工作概览按“需要我决定”“正在推进”“等待”“近期结果”组织。每项显示工作名称、负责对话、当前事实、最后更新时间和下一步；完成数量可以统计，不用估算百分比制造精度。

| 项目工作卡字段 | 展示规则 |
|---|---|
| 目标与负责对话 | 点击进入对应普通对话，返回仍保留项目位置与草稿 |
| 状态与原因 | 同时表达执行和阻塞原因；长工具运行有真实活动证据 |
| 最近进展 | 摘要关联来源，缺少更新只显示时间，不推断已卡死 |
| 依赖 | 显示等待哪项具体结果；可展开相关任务 |
| 消息传播 | 新指令已提交/已投递/已考虑的实际状态 |
| 结果入口 | 原始文件、预览、diff、验证和交付回执 |
| 操作 | 打开、补充说明、处理请求、取消；按后端能力与当前权限显示 |

Coordinator 解释用普通语言：“两个实现任务在运行，验证任务等它们的结果；接口变化需要你决定。”日志和内部阶段名在详情中。

### 2.1 指派与复用

用户可以自然语言要求 coordinator 找某个已有对话，也可从对话菜单选择“交给此对话”。显示目标对话、任务范围和验收概要；授权范围内的正常派工直接提交，不默认强制每次弹确认。

新建 worker 对话时保留项目归属并明确新上下文来源。复用已有对话时告知“沿该对话继续”，不清空它的历史。接收者忙碌时显示排队或当前支持的拒绝原因；不能假装已经开始。

## 3 普通对话界面

保留现有聊天体验。增加一条紧凑的责任摘要：来自哪个项目/协调请求、正在负责什么、有哪些有效约束。只在有实际关联时出现，普通独立对话不增加空白协调面板。

| 动作 | 预期行为 |
|---|---|
| 用户直接发消息 | 沿当前对话上下文交流，按现有 human-steer 优先级处理 |
| 回复 coordinator | 发送有目标和关联的消息，显示提交与处理回执 |
| 找另一个 worker 咨询 | 从项目候选列表选择，标明咨询目的；首版不隐含给同级派工 |
| 修改项目范围 | 告知哪些关联工作待同步，展示传播结果 |
| 查看任务结果 | 跳到对应产物与证据，不只定位一句“完成了” |
| 回到项目 | 恢复原来滚动、筛选和未发送草稿 |

通信可以表现为带来源和目标的紧凑事件行：“项目协调发来范围更新”“已回复性能验证对话”。展开后查看原文、时间、关联任务、回执与证据。主对话保留可读结果，通信详情只显示同一条记录，不追加重复消息副本。

## 4 持久 subagent 入口

位于普通对话的“专家与子任务”展开区。分清稳定身份和本次运行：身份名字、专长、记忆 scope、最近工作、当前 assignment、状态与证据。

| 操作 | 规则 |
|---|---|
| 查看上次结果 | 按 owner/scope 精确读取，失败输出标为部分证据 |
| 让它继续 | 经当前主 agent 发出新 assignment，保留 checkpoint 与新的权限绑定 |
| 查看最近上下文 | 有范围的摘要/原文读取；不将全部上下文复制到主对话 |
| 取消本次执行 | 明确当前 run，取消不删除身份或记忆 |
| 重置记忆 | 独立操作，说明旧记忆将不能用于续交，遵循既有 reset 语义 |
| 归档身份 | 阻止后续指派，保留结果；忙碌时遵循既有服务规则 |

“让它继续”默认是主 agent 代理的交互，不新增一个和用户平级聊天的第三层窗口。忙碌、未知结果、记忆已重置和旧 scope 不可访问分别显示原因。

## 5 文件记忆与交付

共享文件入口显示文件用途、路径、版本、更新时间、来源与读取入口。先展示索引，不预取所有文件正文。支持从消息引用直接打开精确文件或候选改动。

长期知识采用“候选结论”“已采纳决策”“过期引用”等内容标记，标记必须有来源。项目执行状态不能从文档中的自然语言推断。Charter、checker、普通说明文件和研究假设不混成一个同权威的记忆列表。

结果卡区分以下事实：worker 生成结果、局部验证结果、整体验收结果、候选整合状态、实际交付位置。未整合的工作树结果仍可浏览，但不可写成“项目已更新”。

材料、分析和失败实验也可作为产物保留；它们不因有文件存在而获得成功判定。

## 6 六条必须跑通的用户路径

### A 在同一项目启动并行工作

用户在项目主对话提出目标 → coordinator 选择现有 worker 或建立新对话 → 显示指派回执 → 各对话独立执行 → 用户继续问进度 → 结果汇总、检查和交付。

验收：输入始终可用；发送不重复；每个工作卡能定位真实对话与产物；项目结果不提前标完成。

### B 去 worker 深入交流再返回

用户打开前端 worker → 沿已有上下文指导细节 → 主 agent 判断影响范围 → 必要变更回报 coordinator → 用户返回项目查看更新。

验收：不丢草稿/滚动；主 agent 的局部指导不中断无关工作；传播待确认状态真实可见。

### C 再找上次的专家

用户要求主 agent“继续找上次研究该模块的专家” → 显示已有身份 → 空闲时恢复上下文并新指派 → 结果回到主 agent → 主 agent 决定是否上报项目。

验收：不误造新身份；不复用旧权限；busy 不并发覆盖记忆；旧版本发现失效时说明。

### D Worker 之间咨询

前端 worker 询问后端接口 → 对方在安全边界收到或空闲时唤醒 → 回复关联原咨询 → 请求方继续 → 影响公共接口的决定通知 coordinator。

验收：用户能看见消息来源和处理结果；咨询不自动扩大修改授权；重复回执不形成聊天循环。

### E 修改范围并停止一项工作

用户说“先暂停前端，只保留性能分析” → coordinator 解释目标范围 → 调用相应取消命令并发送约束更新 → 各工作卡显示实际处理结果。

验收：未确认执行不得显示已停止；在途工具与已发生改动可查；其他任务不误停；晚到结果不复活任务。

### F 重启或刷新后继续

用户关闭页面或服务重启 → 再打开项目 → 从权威 snapshot 恢复消息、任务、产物与取消状态 → 显示需要检查的未知结果。

验收：没有重复派工；内存 inbox 丢失不丢持久消息；部分输出保留；不存在的 live worker 不显示运行中。

## 7 空态、故障与操作反馈

| 情况 | 展示与操作 |
|---|---|
| 尚未启用 coordinator | 项目说明与启用入口；现有对话照常可用 |
| 没有合适 worker | 推荐建立对话或用户选择，不自动批量创建 |
| 消息提交失败 | 保留正文与幂等关联，显示公开错误及重试入口 |
| 消息已提交但结果未知 | 展示待确认，允许查询状态，避免盲目重发 |
| Worker 拒绝/权限不足 | 原因、影响和解决入口；不显示运行 |
| 等待用户决定 | 具体问题、选项、影响和证据；解决后显示关联恢复结果 |
| 后端或设备离线 | 使用现有可用性权威，解释哪个执行资源不可用 |
| 部分失败或未整合 | 保留成果、失败证据、检查或返工入口 |
| 旧记录缺少新字段 | 显示已知事实与“未记录”；不凭标题/正文推断消息状态 |

## 8 前端实现边界

新增行为使用 TypeScript、现有 transport、typed registry 与会话 snapshot/event 接口。建议在现有 feature 体系下形成项目协作 application/presentation/UI 边界；最终目录 owner 在 P0 决定并写入适用 AGENTS，不先创建另一套全局事件总线。

从 [Project Brain](../../docs/modules/conversations_project_brain.md)、[会话架构](../../docs/FRONTEND_ARCHITECTURE.md)、[Swarm overlay](../../frontend/src/conversation/application/swarm-presentation-overlay.ts) 和 [协作概览控制器](../../frontend/src/features/presence-summary-controller.ts) 找复用点。它们负责不同投影，新增组合层不抢原有订阅和结算所有权。

所有控件使用 [设计系统](../../docs/DESIGN_SYSTEM.md) 的 factory 与 tokens，语义样式进入既有 source owner。修改 retained 区域只改源码，生成 bundle 由构建产生。实现 UI 时应用仓库的 tofu-frontend、tofu-design-system 与 tofu-browser-testing 技能。

选择、筛选、展开状态与草稿是前端局部状态；运行、消息送达、验收与交付是服务端事实。Push 触发失效/增量更新，重连后按权威 revision 重建；丢失 push 不能丢工作。

## 9 性能、可访问性与小屏

- 首屏只读协调绑定和有界概览；对话正文、subagent 记忆与产物按需求取。
- 长列表分页/虚拟化，订阅随可见范围释放；隐藏页面不为每个 worker 建轮询 timer。
- 重复进度只更新对应行，不重绘主对话、不抢滚动、不覆盖输入焦点。
- 人类输入与检查结果的请求不被大量状态刷新淹没；采用已有 single-flight 与资源调度机制。
- 桌面允许主对话旁查看工作，窄屏逐层进入并保留返回位置；不挤出不可读的三栏。
- 键盘能打开 worker、查看请求、发送回复、返回项目；状态不只用颜色表达。
- 提供本地化、屏幕阅读器标签、reduced motion 和明确焦点恢复。
- 模型、effort 与用量只在有明确实际 route/ledger 时显示；全项目合计不重复计子调用。

## 10 前端交付顺序与浏览器验收

第一批：三级身份与真实状态投影、项目入口、关联跳转、证据查看。第二批：持久派工、回复、咨询、指令传播与精确停止。第三批：重启恢复、共享记忆版本与订阅。

每批先测试 DOM-free presentation/application 语义，再跑相邻会话同步和事件契约，随后构建 retained 源与前端。在本地启动应用，用真实浏览器验证上述 A–F 路径；不能仅凭 unit tests 宣称布局和交互通过。

浏览器覆盖桌面与代表性 320/390 宽屏、明暗主题、键盘操作、快速项目切换、草稿保留、长任务、重复报告、断网重连、服务重启和 Stop。至少保留关键路径截图、错误日志、结果回执与性能测量。

前端完成标准：用户能从概览回答“谁负责、在哪里执行、正在等什么、我该做什么、结果在哪里、是否真正交付”，并且每个答案都能追溯到真实权威数据。
