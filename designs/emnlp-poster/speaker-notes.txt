TOFU — EMNLP 2026
English speaking notes for the current-system poster

30-SECOND OPENING

ToFu connects papers, code and manuscript writing with an agent harness you
can inspect and change. The poster follows three engineering decisions: how
much context the model sees, which data transformations run beside the tools,
and how a long history is reconstructed from storage. TofuDB makes verified
continuation a storage operation. We show the mechanisms and their tradeoffs,
including a case where the SQL control is faster.

90-SECOND WALK-THROUGH

Start with the central loop. Research applications share a runtime. Complete
results and accepted task state are kept separately from the model's current
view. The context composer can expose a recoverable preview, trim the working
view, or summarize older history. Request Inspector records what was injected,
where it came from, its token budget and the reason for inclusion.

The cache table explains why fewer tokens alone are a poor cost objective.
These are two adjacent observed requests: nearly the same input and output
size, but 19% versus 97% cache reads and a 5.95-fold cost ratio. This is not an
ablation and not a claimed compaction saving. It motivates weighing future
savings against the summary cost and the disruption of a cached prefix.

The program example shows deterministic filtering beside a tool. The complete
rows are available to isolated JavaScript; the model gets the selected failure
evidence. This is an illustrative transformation, not a measured token saving.
Programs require explicit opt-in. Ordinary and JSON tools remain the default,
and every subcall retains its normal permission checks. Semantic judgment goes
back to the model.

The bottom section follows the same principle into storage. The native context
reader avoids redundant serialization and parsing. After authenticating a
prefix, continuation can validate the terminal and the new suffix. A two-turn
extension checks three headers in the tested histories. Compaction commits the
accepted view, archive and receipt before switching model context. Finally,
read the latency table: most displayed native paths are faster, but SQL objects
win on full reads of escaped evidence. That distinction matters.

WHY TRY TOFU IF I ALREADY USE CODEX OR OPENCODE?

The fit is a researcher who wants paper and writing tools connected to a
modifiable runtime, with context decisions, tool execution and continuation
available as experimental surfaces. Open source, model choice, MCP and skills
alone are not exclusive advantages; those systems are capable and extensible.
We invite researchers to use the workbench for a real task and inspect or alter
the harness while preserving the surrounding application workflow. The poster
makes no unsupported claim that competitors lack any single component.

WHY A TOFUDB LAYER? WHY NOT SQLITE?

SQLite already has transactions, WAL recovery and snapshots. Those properties
do not justify writing a new physical engine. The concrete motivation is to
remove repeated work at the application/storage boundary: reconstruct exact
model context, validate a growing history incrementally, and acknowledge durable
progress through one semantic operation. The four-arm control keeps this claim
honest. It compares production Rust TofuDB to the same Python SQL semantic
implementation exposed as a Sidecar, in-process JSON, or in-process objects.
It does not isolate Rust from Python or the engine from its adapter.

In the 1 KiB fixture, continuation takes 0.173 ms in native versus 1.032 ms
through the SQL Sidecar and 0.675 ms through in-process SQL objects. For the
64 KiB escaped full read, SQL objects take 22.220 ms versus native 29.799 ms.
A Rust semantic layer on SQLite remains a legitimate alternative. These are
storage-operation results, not measured increases in completed agent tasks.

WHAT EXACTLY DOES “3 HEADER CHECKS” MEAN?

An authenticated, same-epoch continuation checks the terminal and two added
headers. Focused fixtures retain N = 8, 128 and 2,048 turns. Initial certification
scans the prefix; earlier semantic edits invalidate reuse; an authority reopen
requires reauthentication. Advancing checkpoint saves have the same suffix-work
property. Full selected output must still be materialized. This is not a claim
that arbitrary full-history reads or whole agent tasks take constant time.

DATA AND PRESENTATION SCOPE

The latency table selects the six XFS rows of the later eight-case four-arm
matrix recorded on 2026-10-19. Each cell is P50 over two fresh processes with
200 requests each. The full matrix has 12,800 exactly validated responses. The
host had 63 affinity CPUs, Python 3.12.13 and SQLite 3.53.4. Full reads were warm
authority context rebuilds. Measurements were not rerun for poster production.
