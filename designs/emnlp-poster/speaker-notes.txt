TOFU — EMNLP 2026
Asynchronous tools, persistent collaborators, and durable state

30-SECOND OPENING

A research task mixes quick file reads, long experiments and parallel agents.
ToFu gives background work a handle and delivers its result separately, so the
main agent can keep working. A useful child can also become a persistent
colleague: later assignments reuse its saved working context, while no worker
stays resident between assignments. TofuDB supports the growing history below
these lifecycles with native context reads and verified continuation.

90-SECOND WALK-THROUGH

Start with the swimlanes. Normal tools return one result. A background command
or a Swarm child returns a handle and continues independently. The main agent
can do other work, inspect or wait through poll, or stop one command or child
through kill. A pending handle is not a successful outcome. Completed evidence
enters the delivery path and is incorporated at a model-round boundary. A
finished provider turn may still have required child results awaiting delivery;
optional exploration does not have to hold up those required dependencies.

The second figure follows one colleague through two assignments. It first reads
a paper and explains the method. Its working dialogue and result are committed,
and the identity becomes idle. Later, asking that same colleague to design an
ablation restores its context instead of creating a fresh worker with no
knowledge of the previous exploration. State survives between assignments;
a worker is present only when there is work. Current model, tool and budget
authority are bound anew, rather than inherited as permissions from old text.

An idle persistent colleague can be activated with a message. A busy colleague
receives steering in its current owned assignment. The same identity admits
one active assignment; different identities can work in parallel. The child
commits its final working context before returning to idle. Lost launch replies
and late completions have explicit reconciliation and generation checks.

The bottom section explains the storage cost this creates. TofuDB builds exact
model context at the storage boundary and avoids redundant JSON work. An
authenticated continuation reuses the unchanged history prefix. The table shows
scoped storage measurements and includes a case where SQL objects are faster.
These mechanisms support durable research workflows without a claim that every
agent task is faster or that a new physical database is the only option.

SYNCHRONOUS VS ASYNCHRONOUS TOOLS

Ordinary tools remain model-synchronous: one returned result. Progress frames
are presentation, not extra successful results. Explicit local
run_command(background=true) returns pending work with a handle. A foreground
local shell command can also hand off after 60 seconds of actual subprocess
time, or through an authorized per-command handoff; the process is not killed.
Automatic handoff excludes stdin-waiting, no-subprocess and unattended/headless
calls. Foreground handoff remains tied to the current server process.

Only explicit local background launch writes the restart record directory,
file-backed output and wrapper exit sentinel needed to reattach a still-running
process or recover its finished result after a server restart. This is not a
promise to rerun a dead external command. Remote-worktree explicit background
is rejected before execution. There is no model-authored run_command timeout;
Stop/kill own cancellation and process cleanup.

poll uses the same interface for command, agent and cross-conversation task
handles. A no-ID poll is an immediate snapshot. A handle wait is clamped to
60 seconds and returns the running snapshot if capped; results remain readable.
For multiple Swarm child handles, mode=any/all controls the wait. kill targets
background commands or running Swarm children; another conversation's task must
be stopped through that conversation. Controls remain subject to the live
executable catalog, scope and permissions.

COMPLETION, INTEGRATION AND DELIVERY

Background acceptance is pending. Completion evidence has an owned durable
queue/inbox route with duplicate-identity handling and receipt publication.
An active turn consumes available evidence at a complete round boundary. Ending
the foreground turn does not itself terminate detached work. Required running
or unread children remain delivery dependencies; existing completion callbacks,
not extra model rounds just to poll, wake eligible continuation. Normal budget,
cancellation and unattended-continuation gates still apply.

Receiving a child result establishes delivery to parent context, not that the
parent has synthesized it correctly or that the user's entire goal is complete.
The swimlane positions are schematic, not measured duration or speedup.

PERSISTENT COLLEAGUES

manage_agents create stores an idle scoped identity. promote copies a settled
child's working checkpoint. assign reserves the identity atomically, launches
an ordinary child with its saved dialogue plus the new objective, and binds the
current caller's model/tools/policy/budget. Completion commits saved dialogue
and result before releasing to idle. Ordinary spawn_agents remains temporary
by default. Ownership is project- or conversation-scoped, with tenant and owner
checks. Retention is an explicit choice.

Stable-ID messaging may activate an idle retained colleague or steer its busy
assignment. Exact-run messaging only steers that exact invocation and never
wakes a new one. A lost launch acknowledgement retains busy ownership until
reconciled; absence of a callback does not authorize another worker. Reset or
abandon changes the generation and fences a stale worker's memory publication.
Old dialogue is context, not an execution grant.

Restart restores durable identities and evidence. In-flight continuation is
permitted only under the accepted original attempt/Continue lineage, current
scope and cancellation checks, and a resolved effect frontier. Unknown external
effects do not get silently replayed. Persistence is not universal exactly-once
execution or unrestricted autonomous restart.

WHY TRY TOFU ALONGSIDE AN EXISTING CODING AGENT?

The research fit is a workspace that connects paper reading, experimentation
and writing to an inspectable execution system: long work remains controllable,
completion is separate from acceptance, and a useful specialist can retain its
own working context across assignments. The poster demonstrates these concrete
mechanisms rather than claiming competitors lack async tools, memory or
extensibility. Its integration and behavior are the invitation to try it.

WHY TOFUDB? WHAT DOES THE TABLE ESTABLISH?

Durable agent identities, pending outcomes, receipts and transcripts require
storage. TofuDB's particular case is reducing repeated work at that boundary:
native model-context materialization and authenticated incremental continuation.
SQLite already provides transactions, WAL recovery and snapshots; those facts
alone do not establish that a separate physical engine is necessary.

The table retains six XFS cases from the later four-arm semantic control:

For 1 KiB evidence, native continuation is 0.173 ms vs 1.032 ms in the Sidecar
and 0.675 ms in SQL objects. For the escaped full read, SQL objects win at
22.220 ms vs native 29.799 ms. This is workload-specific storage evidence.
