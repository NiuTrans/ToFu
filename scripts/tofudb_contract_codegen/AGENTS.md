# Storage contract generator

`../gen_tofudb_ir_contract.py` is the CLI. The input contracts remain the
authority; `generation.OUTPUT_PATHS` declares all generated artifacts.
See `docs/modules/data_tier.md` for the architectural decision.

- `inputs.py` captures each JSON file once per invocation. Keep this lifetime
  local, including after failures; projections must not reopen input files.
- `validation.py` preserves the order of format, receipt, migration, engine,
  catalog and table checks. `validate_*.py` owns the named domain guards.
  Exact compatibility literals are intentional and must not be weakened to
  make a changed contract pass.
- `native*.py`, `paper.py`, `python_outputs.py` and `search.py` own output
  projections. Worker and automation validation live in `auxiliary.py`.
- `generation.py` builds the complete output map before publication. The CLI
  retains normal sequential writes and a read-only `--check`; this is not a
  multi-file transactional publisher or an atomic cross-file input snapshot.

Start with `tests/tofudb/test_contract_generator_inputs.py` and
`test_native_search_volume_contract.py`, then the generator drift checks in
`test_tofudb_pre_authority.py`. In the isolated checkout, run the CLI write path
and `--check`; a structural-only change must leave all generated bytes unchanged.
Use the function-size and architecture gates after the source tree stabilizes.
