# Task engine
`lib/tasks_pkg/` executes one model/tool attempt. It is an executor, not a conversation repository or browser transport. Explicit application tool delivery uses `lib/tasks_pkg/tool_delivery.py`: one verified successful sole-call round binds an application-owned durable verifier and exact model-supplied reply, closes the existing checkpoint, and reaches the ordinary terminal sink without another model request. It preserves the physical provider finish and usage; the port owns no durable store, acceptance, replay or model loop. Handler exceptions settle the tool round as an error and preserve the exception type and cause. Problem: unconditional schema correction advice misclassified environment failures. Decision: admission owns schema errors; the executor adds no invented recovery instructions. Alternative: treating every ValueError as bad arguments also misclassifies authority failures. Verify with tests/tasks_pkg/test_handler_runtime_failure.py.

Live file-change stamps in `commit_round/_derive.py` are best-effort presentation; settlement rebuilds from the authoritative journal. Unexpected registry misses and stamp failures emit WARNING with a short task identifier and bounded state/exception-type metadata, never file entries or exception text. A miss probes state afterward (not an atomic witness); terminal/aborted late callbacks stay DEBUG. Problem: DEBUG-only failures hid missing live cards. Decision: use the existing incident/coalescing pipeline without new per-task log state; warning on every late callback was rejected as routine lifecycle noise. Specs: `tests/tasks_pkg/test_commit_round_derive.py`.

## Boundary
A text-only round may carry `None` tool schemas: discovery treats this as an empty tool set and retracts unavailable private-input directories before prompt admission. Keep the original schema carrier for provider compilation and token evidence; normalizing every consumer would change those contracts to repair discovery. Input is an API-ready message list plus task configuration. Output is a stream of typed task events and cumulative executor state. For conversation work, the task is bound to a durable `(turnId, attemptId, userId)` before execution. Fatal and BaseException exits hand the loop-retained messages back before terminal capture; ordinary terminal errors use the shared terminal stamp before DONE/persistence, preserving tool evidence and measured elapsed time without replay or reconstructing earlier compaction.

Queued cancellation in the demand Agent executor removes the job under the scheduler lock, then invokes Future callbacks outside that lock. Removed Futures complete the executor cancellation handshake so `wait()` and `as_completed()` observe a terminal result without waiting for a worker that will never consume the job. Direct Future cancellation and shutdown retain the same rule; running and quarantined workers keep their existing lifecycle.

The authoritative flow is:

```text
turn command
  -> pending generation attempt
  -> claim + bind executor task (pending/queued) -> worker entry + fenced start (running)
  -> model/tool loop
  -> append_event -> bounded task FIFO (executor continues)
  -> ordered background turn.event.record (revision patch + carried task event)
  -> v3 conversation sync
```

`manager.prepared.restore_prepared_task` rebuilds server-owned headless input via
normal construction without hooks; domain proof and CAS own recovery/admission.
Per-task identity locks reuse only identical unstarted carriers; independent
restores have no global lock or 500 ms busy refusal. Waiters retain the same
lock through construction, and idle keys disappear from the weak lock pool.
Same-identity recursion is a lifecycle error. Metadata marks restorable tasks
before publication; failed persistence signals local resources but returns an
error instead of a durable receipt.

The required terminal port may prepare bounded opaque domain context for the owned result CAS; preparation failure retains debt, and rejected ownership suppresses delivery. The task result table is recovery/diagnostic storage, not a second transcript; renderable content and settlement stay in turn authority. Normal and Flow chat share demand execution: independent accepted work prepares physical workers immediately, resource hints size idle reuse, and settlement retains actual worker ownership.
The root executor starts accepted work on demand; its short handoff deque owns cancellation before worker entry, with no active-count or queue-capacity gate. Launch worker settings size idle reuse. Proven-wedged threads keep physical ownership and retire on return without blocking unrelated submissions. The registered `executor_queued` phase describes transient handoff evidence; legacy configured-capacity fields are hints, not Agent slots. Per-task ordering keeps late queued observations from overwriting `workerStarting`. Provider backoff retains `retrying`. `worker_executor.py` accepts an optional state publication port so production pools aggregate live owners without overriding one another; the ordinary root snapshot remains unchanged.
After settlement, only terminal `round_committed` and `preference_learned` observers use standalone task replay; their dedicated settled-Turn CAS owns projection enrichment, while every other late frame retains the zombie fence. Detached swarm frames (`swarm_phase`, `swarm_agent_phase`, `swarm_agent_progress`, `swarm_agent_complete`, `swarm_agent_tool_call`) join them on a terminal task: a spawned sub-agent outlives its settled spawning turn, and its pure panel/replay frames must persist standalone rather than re-enter the closed attempt and trip the fence into force-cancelling the swarm.

Automatic translation is triggered only after Turn authority settles. Its already-target skip is a whole-document identity decision: dominant-language classification of the raw buffer is insufficient because a target-language opening may hide foreign-language sections later, and because technical Chinese is often identifier-heavy (inline code, URLs, API names). Terminal root, Flow-visible child, and incremental segment paths share the conservative `lib/translate/skip_policy.py` predicate, which inspects prose after masking markup/code/URLs; mixed English prose proceeds to translation, while symbols, bare paths/URLs, and genuinely monolingual target prose may be committed as an explicit no-op. Literal `<think>` mentions in source or translated text are document content, not MiniMax reasoning wrappers, and must not truncate the rest of the message.

Pending task binding alone does not prove queue residence: cold/live presentation uses `executor_preparing` until the executor publishes explicit queue evidence. A committed running attempt retires a stale `executor_queued` phase even if the next phase write failed. Startup stage histograms distinguish persistence and context preparation from real executor wait. Birth and running diagnostic checkpoints share a 500 ms budget across parent/witness reads, writes and one CAS conflict refresh, with no transient-pressure retry; terminal durability keeps its existing retries. Version/status witnesses use owner-scoped compact `task_results.replay_get`, avoiding cumulative-result blob hydration, while the atomic checkpoint preserves abort tombstones and owner/parent/status fences.

## Internal stop provenance

**Problem:** physical abort also stops silent/deadline-expired invocations;
misreading it as user Stop suppresses failure diagnostics and bounded delivery.
**Decision:** `invocation.py` stamps cause/error before signaling; `turn_verdict`
derives failed `invocation_stalled` / `invocation_deadline` ahead of client-abort
evidence. Swarm preserves this on normal/exception exits, with isolated parent
state and committed receipts. Explicit Stop retains its no-auto-wake gate.
**Alternatives rejected:** longer timeouts hide stalls; waking cancelled agents
violates Stop; a new UI status forks authority. Specs: Swarm invocation/failure
continuation and turn-verdict tests. See [execution modes](../TASK_EXECUTION_MODES.md).

## Native durable execution composition

**Problem:** the native process could acknowledge an arbitrary host callback
without binding the application's task/Turn recovery and delivery owner.
**Decision:** `lib/tasks_pkg/native_execution.py::run_native_task` combines a
single-use v2 route with `NativeTaskTerminalPolicy` and the existing
`persist_task_result(..., _defer_heavy_release=True)` writer. Explicit principal,
task, operation ID, candidate byte budget, terminal projector and lifecycle-owned
executor are required before route consumption. The application projector uses
existing text/round/accounting/Turn owners once; failed commit ACKs retry that
frozen projection without model/tool reexecution. Changed candidate, task owner
or projected outcome fails closed; a proven recovery ownership fence rejects
rather than retries. Failed settlement may persist an error, never success.
Cancellation joins the physical writer before releasing serialization. Heavy
state remains available through native publication and is released by the
application's existing terminal lifecycle. **Alternatives rejected:** direct SQL
would fork storage fences; rerunning projection can duplicate terminal effects;
detached executor futures can write after cancellation has apparently finished.
This explicit entry is not the production default. Full protocol/context/tool
policy and process-loss reconciliation still belong to their existing owners;
the adapter does not infer paid usage or replay unknown effects.

Tests: `tests/agent_core/test_native_task_terminal.py`,
`test_native_task_execution.py` and `tests/storage/test_native_task_terminal.py`.
The storage tests use disposable authorities. Real native success, stream
failure and cancellation must commit their matching task/Turn outcome; cancellation
joins persistence before process admission returns to zero. These cases require
`TOFU_NATIVE_TERMINAL_TEST_ARCHIVE` pointing to a verified archive. When testing a
worktree test against the current application, use pytest importlib mode from the
application root and set `TOFU_NATIVE_TERMINAL_TEST_APPLICATION_ROOT`; the test
checks the imported execution owner. Native engine tests retain source identity
verification and require `TOFUDB_BIN` to match that application source exactly.

## Selected native application checkpoints

**Problem:** durable native rounds need the selected authority and terminal debt
ordering without a Python journal. **Decision:** NativeCheckpointPolicy delegates
load/begin/complete/finish to the existing embedded storage port on the supplied
executor. Explicit recovery restores financial/time policy; cancellation joins
physical calls and retains an acquired capability. The shared Rust journal fences
terminal work; C ABI finish freezes status/Suspend before retries. Only completed
Suspend plus Aborted preserves recovery, and release additionally requires the
canonical terminal writer's accepted ACK. Failed/unknown acquisition or terminal
save never grants takeover. Joined cleanup forgets volatile metadata and preserves
the original exception. **Alternatives:** releasing before canonical commit opens
unfinished task recovery; a Python transition owner duplicates Rust authority.

Verify tests/agent_core/test_native_checkpoint_policy.py and
tests/storage/test_native_checkpoint_policy.py with explicit private library,
binary and source SHA environment variables from the checkpoint SDK test. Native
checkpoint capability is optional and selected embedded only; SQL/daemon/default
production execution promotion and full application performance remain pending.

## Shared ReAct lifecycle
`run_agent_loop` is the sole LLM/tool round-loop authority for root chat, swarm workers, timer and research engines. It owns round numbering, continue/stop sites, three abort placements, timeout counting and the post-tool checkpoint. Root request building, anomaly policy, budget/protocol gates, event projection and semantic loop detection are typed `_root_agent_loop.py` hooks returning `LoopDirective`; they never own another LLM/tool `while` or infer completion from response text. FlowExecutor owns graph iteration only; role execution delegates through the shared agent runner.

Independent guards bound non-recovering tool loops. The shared no-progress guard runs only after tool execution and fingerprints the ordered calls, world version, and exact model-visible result snapshot. It accumulates only when all three are unchanged in consecutive completed rounds; a changed result, changed operation, changed world, verified success, or missing/incomplete result evidence resets and fails open. Read-only work and elapsed rounds alone are never stall evidence.
Stable `nonretryable_failure_signatures` accept only a canonical non-retryable typed error (the sparse model error or a legacy full `tofu.tool-result/v2` record) plus the concrete tool/argument identity. Swarm halts after three equal terminal-failure rounds with `exit_reason=nonretryable_tool_failure`, then performs one tool-less wrap-up. Any success, mixed/retryable/malformed or legacy result, or changed operation resets the streak; unknown results fail open.
Root post-dispatch policy also distinguishes byte-identical call/outcome loops from semantic no-progress no-ops and already-covered reads, gives one `_isMeta` safety correction, then stops continued waste.
For V2 partial results, the guard reconstructs its server observation from sparse `toolContent` plus the non-model `tofu.tool-result-evidence/v1` round sidecar (and still reads legacy full envelopes). Range/cursor/limit and presentation-only changes retain one resource identity across registered idempotent tools; only the model-visible summary/items/error projection counts as evidence, so new pages remain productive but new artifact IDs cannot disguise an identical projection.
The guard first directs the model to `read_tool_artifact`/`search_tool_artifact` or a visibly advancing narrower read, then stops one continued no-progress episode.
Productive serial calls never trigger efficiency/adoption prompts or automatic gateway-only exposure: call count alone proves neither independence nor waste. Actual safety corrections and stops are recorded through `record_injected_note` as ordered `system_note` segments. Repeated identical successful verification ends explicitly incomplete, not as proof that the user's task is complete; genuine background-task acceptance retains its separate handoff semantics.
Engine-authored stall/stream-continuation corrections and pure peer/swarm evidence are likewise transparent to current-user extraction; an inbox row containing human steering is not.

Flow convergence policy follows the same evidence hierarchy. Similar critic or virtual-user wording is an advisory signal only: it may inject one strategy-change directive but cannot terminate a run. The same is true when a complete structured `[PROGRESS]` signal stays flat across edit-shipping turns with overlapping targets: a complex fix may need several incremental edits before a criterion becomes fully resolved. The zero-deliverable hint explicitly permits focused read-only investigation and forbids mutation merely to satisfy the guard. Hard boundaries remain transparent finite iteration/turn budgets. The manager's `stuck_no_progress` reaper is separate infrastructure liveness policy: it requires both the real-event clock and dispatch heartbeat to be stale, exempts live human/model waits, and interrupts a silent subprocess before escalating to task failure. Terminal stdin prompts retire on text, EOF, timeout and wait failure; cleanup clears prompt metadata, emits the existing resolution event, and preserves a concurrently installed terminal round status.

One provider response is an ordered occurrence list. Every response position is an independent model action even when tool name, arguments, caller, or provider call ID are byte-identical.
Blank, recycled, or duplicate IDs are reminted before history/settlement so each assistant call retains exactly one adjacent result; equality never elects one physical owner for sibling positions.
Only a byte-identical transport retransmission proven to target the same stable stream slot may be suppressed before execution. Across provider responses the same payload is likewise a fresh model action governed by ordinary evidence/world-state guards.

Continue replay groups history by ordered `(attemptId/taskId, llmRound, contiguous occurrence)`, never a Turn-wide `llmRound` dictionary. Root Continue advances logical model/tool counters from retained chronology, including historical resets; private producer identities still distinguish batches. Merging equal historical numbers fabricates a provider batch, reorders history, multiplies checklist/tool context and can induce repetition.
Legacy unstamped rows use contiguous order and observable `roundNum` resets without inventing ownership. Continue, checkpoint, segment, and cold-history reconstruction share one causal-prefix validator: explicitly superseded provider-attempt artifacts and identity-free display rows are transparent; any other identity-bearing malformed row stops replay before dependent calls.
Exact result text is the execution receipt regardless of `done`, `error`, `rejected`, or `aborted` verdict, and structured arguments are canonicalized without mutating durable audit rows. A malformed supplied `toolHistory` fails the request before any partial history reaches a model.
Resume text, tool rounds, checklist state, usage, and file metadata are validated and detached as one preflight before project setup or prefetch; hydration begins only after the whole snapshot is valid. `todo_write` is a Codex-style full-plan snapshot: the same call creates, updates, replaces, reopens, or clears the list, with optional `explanation`. Items contain `content` and `status` (`pending`, `in_progress`, `blocked`, `completed`); operation selectors, item IDs, nesting, revision preconditions and mandatory replan reasons are not model protocol. The bounded flat v3 current state stores `todos`, `explanation` and `update_count`; raw tool rounds remain the durable audit rather than a copied stack/history. New snapshots allow 24 items × 512-character steps and a 2,048-character explanation; the schema stays within 325 tokens. Valid legacy v2 checkpoints migrate all ancestor and child lists in order (up to 144 rows), preserving their work and historical blocked statuses without resuming stack semantics. Invalid checkpoints fail before task mutation. Legacy `sync/replan` calls are full-snapshot aliases; stale child-only `push` calls are rejected with a full-list hint rather than silently losing parent work. Checklist progress is advisory: it neither re-drives a normal stop nor establishes task success. Existing stream, cancellation, wait and verification verdicts retain authority. Specs: `test_todo_tool_schema.py`, `test_todo_continuation.py`, `test_checklist_context.py`.
Checkpoint resume reconstructs its interrupted assistant/tool rounds through the same canonical wire projector used by the next ordinary conversation rebuild, inserts that suffix before the optional resume prefill, and separately retains the raw rounds for durable settlement. The resumed request therefore keeps tool evidence and remains a byte-stable cache prefix for its successor. Resume snapshots carry no round-count or serialized-byte ceiling: oversized histories are folded by working-set compaction before dispatch, never rejected. `continuation_rounds.py` derives the root model/tool frontier from ordered retained batches, keeping gateway child ordinals separate. The shared chassis accepts that frontier without inventing paid dispatches or breaker credit. Resume config also carries the accepted checklist and usage/API ledger; live and failed resumed requests preserve cumulative accounting. Spec: `tests/tasks_pkg/test_seamless_continuation.py` and the root-adapter continuation regressions.
Swarm history is durable on the `spawn_agents` tool round: the returned handle identifies that wave, while `_swarmSnapshot` carries each agent's status, full result preview, token/timing/file counters, and bounded tool-call timeline. Agent callbacks stamp incremental/final snapshots when the handle is already visible. Tool settlement is the mandatory race-repair boundary: once it writes `toolContent`, it immediately reconciles the still-authoritative active session onto that exact round. This closes fast-agent completion before handle publication; the monotonic snapshot version and equality check make callback/settlement/replay writes idempotent. A detached CAS writer remains responsible only after the owning attempt settles.

Swarm push preserves canonical `conversationId`; subscription `taskId` and producer `executionTaskId` are distinct transport identities, leaving durable task events unchanged (see [push identity](../contracts/EVENTS.md#push-transport-identity-is-not-task-event-identity)). Swarm completion records canonical child evidence before presentation callbacks; sink or snapshot failures cannot lose a result or prevent waiter notification. Inbox insertion is fenced against await/get/inbox delivery under the session result lock, while UI and persistence callbacks run outside it. Repeated completion callbacks are idempotent and delivery receipts remain bounded by completed session IDs. Terminal `swarm_phase:complete` denotes driver settlement, not universal success: `outcome`, fixed `outcomeCounts` (completed/failed/cancelled/stalled/unknown), and bounded `reasonCodes` distinguish cancellation, liveness stops, and missing evidence. The `swarm.driver_done` structured log carries those same aggregate fields without objectives, prompts, result text, or free-form errors.

### Delegation contract (spawn parameters)

`spawn_agents` accepts a per-agent `tools` allowlist (intersected with the role scope and `SUB_AGENT_DENYLIST` — narrow-only), so the orchestrator can hand a worker exactly the tools a task needs — including MCP tools it has never used itself — while keeping those schemas out of its own context. The cross-harness `task`/`agent` envelope maps a known `subagent_type` onto a spawnable native role. Completion payloads carry the agent's FULL natural-text result: the `<swarm-update>` inbox message and `await_agents` entries never truncate, so no second `get_agent_result` round trip is needed for non-trivial results (the durable per-agent log remains the audit copy; re-reads use `get_agent_result`). Workers load their own skills through the ordinary `search_skills`/`load_skill` tools — there is no spawn-time skill preloading. Approval delegation (`set_approval_delegate`) follows [TOOL_EXECUTION_POLICY.md](../contracts/TOOL_EXECUTION_POLICY.md#approval-delegation-set_approval_delegate); the tool ships in the swarm ToolSpec but is stripped from sub-agents and read-only waves. Specs: `tests/swarm/test_swarm_delegation_contract.py`, `tests/tasks_pkg/test_approval_delegate.py`.

Swarm snapshot matching is execution-scoped: the spawn handle's `swarm_run_id` retains the original session task across follow-up turns; `swarm_id` remains the launch-task alias. Snapshots carry the stable session identity in `swarm_id`. Legacy receipts match only by exact known identity, never by the conversation lookup key or reused agent names. Follow-up waves restrict snapshots to their own launch roster; a snapshot from another execution must never overwrite a prior run.
The persisted `toolContent` is usually the SPARSE `summary_items` model projection (`{"summary", "items": [handle]}`), from which `lib/tools/result_envelope.py::_model_projection` intentionally drops `contractVersion`; every reader recovering the handle (snapshot matching, elision-stub salvage, frontend panel recovery) must unwrap through `sparse_result_items` / the swarm panel's equivalent — gating on the v2 marker alone recovers zero agents and renders an empty panel over fully-persisted data.
Every resume operation (`continue`, `checkpoint_resume`, `answer_guidance`) also inherits the settled projection's `modifiedFiles`/`modifiedFileList` as `checkpointModifiedFiles`/`checkpointModifiedFileList`, so the resumed attempt's commit merge unions pre-gap edits with its own instead of the settled card listing only resume-window files. When a restart settled the orphaned attempt before its live file-change stamps were folded (the durable projection has no list to carry), attempt dispatch derives the turn-scoped list from the conv-isolated modifications journal — entries at or after the turn's creation across the primary and extra workspace roots.

Explicit Stop propagation, interruptible waits, child evidence, and honest terminal timing follow [TURN_SETTLEMENT.md](../contracts/TURN_SETTLEMENT.md#explicit-user-cancellation).

Native model-route delegation: **Problem:** a detached swarm child inherited the
parent's ephemeral hard pin, but the parent execution session disposed those
slots on turn settlement, leaving a live child with no dispatchable slot.
**Decision:** the swarm persists the parent's owner-authorized model selection
and routing policy (not its pin); each child uses `create_task` to mint and bind
its own owner-scoped route group. Its execution session releases the group at
child cancellation/completion/discard. An incompatible child model override is
rejected as `model_route_unavailable` before minting; it never escapes to the
global credential pool. **Alternative rejected:** leasing the parent's group
would couple detached lifetimes to the parent and require cross-session lease
accounting. Legacy pin-only callers retain their existing pin behavior.
Spec: `tests/tasks_pkg/test_child_invocation.py`.

Conversation-backed `await_agents` also yields for pending operator steer or background-command completion at its existing ≤100 ms wait checks. The result carries `yield_reason='pending_input'`, not timeout or agent completion; it consumes neither inbox evidence nor agent results and leaves children running. Cancellation wins. Injection still follows normal tool settlement, so a blocking sibling tool or an in-flight provider call is not preempted. Headless callers retain ordinary agent-status waits. Specs: `tests/swarm/test_swarm_inbox_yield.py`.

Background acceptance (`exitCode='background'`) is pending, neither failure nor success; a failed sibling still warrants correction, but failed execution never proves absence of side effects. Explicit `run_command(background=true)`, owner-requested per-command handoff, steer handoff, and automatic handoff after 60 seconds of actual subprocess time reuse the durable completion queue/inbox lane below: ending the foreground turn does not finish the command. The automatic threshold returns a pending handle without killing the process, leaving room for another provider request before a typical five-minute prompt-cache expiry. Commands already awaiting stdin stay foreground; commands with no subprocess and unattended/headless calls do not auto-handoff. An owner-requested handoff targets the currently running subprocess only, never the next command on the same task; it neither interrupts that process nor alters whole-turn Stop. If completion, interruption, Stop, or stdin wait wins the race, the request is refused or the command settles in the foreground instead of fabricating a background handle. The handed-off command remains owner-scoped and queryable/killable in the current server process. Because it began as a foreground subprocess, its pipes cannot acquire a restart-surviving record after spawn; only explicit local background commands write a durable record directory under `data/background_commands/` (output streams to files, exit code to a wrapper-written sentinel), so after a server restart the boot sweep delivers finished results, reattaches still-running processes with their poll/kill controls intact, and reports only processes that actually died with the server — the model never learns about the restart otherwise. Remote-worktree explicit background is rejected before execution. Complete publication envelopes and byte-budget receipt cursors follow [Storage operations](../STORAGE_OPERATIONS.md). The unified `poll` tool absorbs all background waits (background commands, swarm agents, cross-conversation tasks): `wait_s` blocks mid-turn clamped to 60 seconds, a capped wait returns the running snapshot and is safely re-called because completed results stay re-readable, and an unknown handle is answered with the caller's live handles. `kill` stops a background command's process tree (SIGTERM then SIGKILL) or aborts one running swarm agent; killing one handle cannot cancel unrelated foreground work, and cross-conversation tasks are refused (use that conversation's Stop). The retired `check_background_command`/`kill_background_command`/`await_agents`/`await_task` names stay dispatchable for conversation-latched schemas, and name repair routes fresh mistakes to `poll`/`kill`. `run_command` has no model-facing timeout: commands run to completion unless killed or stopped by the user. Decision (owner ruling): one async-handle contract instead of per-family wait tools plus no time-budget abandonment — defeated alternatives are keeping three single-family wait schemas (one mental operation, three surfaces) and timeout-based kills (models cannot predict durations; stopping work is an explicit act, not a guess). Decision (cache continuity): elapsed-time handoff at 60 seconds instead of a command-name heuristic or forced five-minute timeout; command names cannot predict runtime, and a timeout would destroy ongoing work.

Background command admission has no application count ceiling, including foreground handoff and restart reattachment. Problem: the shared 32-entry registry rejected new execution when live commands or undelivered results filled it, after creating a durable record. Decision: retain all active/unpublished controls and prune only delivered/headless completed history using the launch-probed tool receipt cache budget, at settlement. Actual worker-start failure removes its control and durable record. Alternatives rejected: raising the fixed ceiling repeats saturation; evicting active or unpublished entries loses cancellation or delivery. Measurement: with a two-result history budget, 40 simultaneous workers stay controllable, drain to zero live workers and retain two completed controls; 40 failed publications remain retryable and do not block a new command or handoff. Specs: `tests/background/test_background_commands.py`. Publication retry identities, bounded late-twin fences, delivery status and verified-provider ACK follow [CONVERSATION_SYNC_V3.md](../contracts/CONVERSATION_SYNC_V3.md#background-command-completion-evidence). Specs: `test_background_completion_publication.py`, `test_llm_round_delivery_acknowledgement.py`.

## Task carrier
The in-memory task dictionary is a process-local execution carrier. Important field groups are:

- identity: `id`, `convId`, `_turnId`, `_attemptId`, `_userId`;
- configuration: `config`, `model`, feature/tool flags;
- request-local orchestration: `_toolOrchestration`, `_ptc_local` (recomputed before each wire request), bounded `_toolOrchestrationDecisions`; historical adoption/round-trip witnesses remain readable but no longer trigger prompts;
- cumulative projection: `content`, `thinking`, `segments`, `toolRounds`, `programRuns`; `modifiedFiles`/`modifiedFileList` are live-stamped from the modifications journal at record time (listener fold seeded from `_checkpointModifiedFileList`, terminal tasks refused) while settlement rebuilds the authoritative dedup;
 `segments` mirrors wire order even at mid-turn checkpoints: while the trailing tool batch is still live (`LIVE_ROUND_STATUSES`) and its pre-tool prose stamp has not yet landed (it lands at dispatch-parse time), the accumulator narration is placed ahead of that batch's first tool card rather than at the tail, and `parse_tool_calls` refreshes the mirror immediately after the prelude discard so the just-stamped narration never blanks between the structural-write and round-end checkpoints;
- lifecycle: `status`, `finishReason`, `error`, `aborted`;
- accounting: `usage`, `apiRounds`, cost/fallback metadata;
- event delivery: `events`, sequence/cursor locks, and the launch-derived `TaskRuntime` terminal-record/event-count/serialized-byte policy. Probe failure retains 64 records per kind, 1,024 events and a 2 MiB ordinary tail/4 MiB complete event per task; the 8 GiB reference uses 128/2,048/4/8 and distributed 512/4,096/8/16, with hard caps. Explicit constructors only lower those ceilings. Byte/count pressure drops the oldest contiguous suffix and reports a cursor reset; one valid event may occupy the window alone, while a larger/unencodable event advances the absolute cursor and resets only reconstructible memory replay. Terminal chat dictionaries use a separate launch-derived 600..1,800-second personal TTL (600 seconds on the 8 GiB/probe-failure profiles, 3,600 distributed, 60..86,400 explicit bounds); active tasks are never TTL-evicted. `retention_stats` and Prometheus expose occupancy and every ceiling; **HTTP prefix reads — Problem:** bounded HTTP pages copied the complete retained suffix before projecting 128 events. **Decision:** retain the canonical full-suffix poll seam and plugin/injected poll implementations. **Alternative rejected:** a locked prefix plus one lookahead event preserves pagination, but the [controlled comparison](../evidence/system_event_http_prefix_rejected_20261009.json) records 18 latency/CPU guard failures and two plugin-override HTTP failures; modest long-window gains cannot authorize the new default. Specs: `tests/tasks_pkg/test_task_poll_extension.py`.

## Persistence discipline
Managed root `append_event` admits a detached snapshot without waiting for storage; its ordered writer persists before push/hot replay and may carry the exact task event plus a revision patch in the same Sidecar transaction; the event envelope never repeats the cumulative projection. An oversized carried frame — the Sidecar payload cap or the 64 MiB wire frame — retries once with cumulative text and opens a 30-second full-projection probe circuit, keeping raw-event durability exact.
Writes without that carrier fail closed; a later full probe or terminal settlement converges the Turn document. Terminal events may also settle slim, and a toolRounds lane crossing its frame budget (`TOFU_TOOL_ROUNDS_FRAME_BUDGET_BYTES`, default 16 MiB) elides the oldest settled rounds' free-text payloads with replay identity intact. Projection normalization copies an explicit L1/frame placeholder into only its uniquely identity-compatible segment mirror, so a stale render copy cannot restore old bytes; ambiguity leaves evidence untouched. A `spawn_agents` round without a durable snapshot first donates its handle to a minimal roster snapshot (status `unknown`, version 0), so the reloaded swarm panel still expands to an honest roster instead of a dead header.
If even the text-only frame is rejected the worker is cooperatively aborted (`storage_frame_overflow`) instead of burning tokens on unpersistable events. A non-retryable `database_integrity` rejection at the same conversation-authority boundary likewise raises to the caller and stamps `storage_authority_integrity`, stopping provider/tool work at the next existing abort gate; it is never retried as if transient storage pressure could repair corrupt durable state.

Pure text progress may be coalesced. Structural events, interaction requests,
and terminal events persist immediately. The next structural/terminal write
carries cumulative text, so coalescing changes cadence, not final state.

Executor diagnostics use `tofu.task-results.checkpoint.guard/v1`: task birth retains owner-scoped parent/compact-version preflights and caches the returned version only after an exact Sidecar echo; confirmed checkpoints become one command instead of two queries plus one command, while an old peer retains that safe three-RPC path. Warm rounds stage at most two positive integer cache facts; an independent cache-settings-v1 echo folds them into that command, while an old peer retains the serialized per-fact settings fallback. The guarded transaction takes the conversation delete/purge lock then the task-result key lock and enforces parent/task ownership, terminal regression, abort tombstones, and CAS. `False` is reserved for a proven fence; admission or CAS pressure raises instead of suppressing later durable work. Birth and running diagnostics share one 500 ms budget across preflight and CAS; running writes use maintenance priority, birth uses user priority, and only terminal diagnostics retain five bounded attempts. Turn settlement remains render authority and commits before terminal diagnostics, so shedding running recovery state cannot lose a settled answer. A turn-native task therefore keeps content/thinking diagnostics in `task_results` but does not rewrite its growing segments/tool-result timeline there; the atomic Turn projection plus replay log already own it, while inline/headless tasks retain their only structural copy. Durable turn-source maintenance uses one exact read-pool expiry/list probe and enters the queue-repair writer only when a lease is actually expired; startup force recovery and old Sidecars retain the repair command.

Provider text coalesces at most 100 ms/256 characters; structural boundaries flush memory replay. Sidecar/push/presence/DB probes cannot block upstream ingress. The first post-provider event restores cumulative durable-before-visible state and one sampled checkpoint; crashes can lose that pending window.
The 256-entry FIFO isolates persist→push. Normal completion drains for at most 30s; child cancellation/disposal allows 250 ms then revokes publication. Child worker/monitor admission derives from launch-probed swarm policy (1–64); stuck workers retain slots and overflow/incomplete delivery fails closed.
Chat content and runtime replay commits recheck authority under their mutation locks; deferred delivery retains its original context. The graph event bus propagates publication revocation rather than treating it as an optional observer failure. Fence locks cover bounded local mutations only, never observer or network calls. Arbitrary callbacks cannot be killed or committed storage rolled back: writes still need attempt/CAS fencing. Observer loss remains partial trace, not repaired by cumulative text; [trace evidence](../contracts/TURN_TRACE_CONTRACT.md#聚合工作预算与观察隔离) owns this distinction. Specs: `test_child_ingress_commit.py`, `test_provider_ingress_isolation.py`, `test_stream_delta_coalescing.py`.

Mid-turn injections (peer messages, operator steer, detached `run_command` completions) follow one dual-write delivery contract: the durable `message_queue` row is the delivery authority, while the conversation-keyed `agent_inbox` item is a volatile fast-path twin tagged with that row's `queueId`. A live turn drains the twin at its next round boundary and stashes it under `_peer_inject_pending` / `_steer_inject_pending` / `_bgcmd_inject_pending`; only after verified provider completion does the deferred flush acknowledge delivery — never at request submission. Background-command receipts and queue removals share the `turn.event.record` transaction and one accepted browser state update; the executor's `_bgCommandInjects` mirror is updated only after commit. Its frozen bounded retry record cannot leak through ordinary checkpoints. Peer delivery still emits its chip, accumulates `_peerInjects` and deletes the durable row through separate operations; a deletion failure can cause redelivery. Human steering retains `_userSteerInjects` and its existing committed block identity. All three display sidecars remain outside `toolRounds`. The forward race (inbox first) closes by that row deletion. If the turn ends first, its passive receipt remains visible in the queue. After every known command for that owner and conversation has published, one collective workflow wake starts an idle turn; an existing queued request takes priority. The turn rebuilds inbox twins from the rows and delivers a bounded batch. An abort before the flush leaves the rows untouched. Startup recovery rebuilds missed collective wakes. Steer availability is honest end to end. `injectMode: 'steer'` degrades to the durable queue — never vanishes — when the steer lane is unavailable, with the reason logged (`no_live_attempt` / `inbox_tombstoned` / `steer_window_closed` / `attempt_gone` / `commit_not_persisted`); the queued row is marked `_steerFallback`, surfaced as `steerFallback: true` on the command ACK, the `ConversationQueueItem` projections (`queue.list`, `conversation.get`), and the `get_queue` preview contract, so the toast and both queue renderers can say "insert window closed → queued for the next turn" instead of a bare "Queued #n". Terminal processing has one direction: stamp the task terminal once; settle its private `ExecutionSession` resource stack; emit the typed terminal event; commit Turn settlement; persist bounded executor diagnostics; release heavy in-memory fields; then notify projections and dispatch any durable queued successor. The session is not a second task state: `TaskRuntime.status` remains authoritative. It proves exact admission leases, request routes, billing holds, and other live resources were released or handed to a declared durable/TTL recovery owner. A non-recoverable cleanup failure converts proposed success to a typed terminal error before persistence/push. `TaskRuntime` raises a private terminalization fence before cleanup callbacks: a racing Stop cannot rewrite completed work, a second terminalizer cannot publish another verdict, and an already-failed session cannot later become task success.
Because chat task acceptance is durable-at-birth, every pre-worker billing, admission, binding, and spawn rejection settles the session, writes a typed terminal task row, and only then unregisters it. A failed terminal write leaves an eviction-fenced, lightweight durability debt; bounded maintenance retries it before TTL, capacity, or memory-pressure cleanup may remove the task, so no accepted task can be stranded durably at `pending`/`running` merely because its worker never started.

The normal root-chat path uses the same immutable terminal stamp as Flow/error/queued-abort paths. A configured model fallback and its pool rescue each use a finite actual-429 budget (default 3, hard ceiling 16); after all recovery fails, every exception shape returns a normal loop break carrying typed `task.error` plus `autoRetryExhausted`, so finalization emits `done(error)` and does not reset the bound through whole-turn replay. `finished_at` is the TTL clock and cannot be omitted or rewritten; cleanup never measures a successful long task from its creation time after it finishes.

Configured invocation token, tool and deadline stops publish `budget_exceeded`, retain the precise `execution-budget` reason and use the budget adjustment hint. Owner Stop retains cancellation. The shared account reserves model input/output before dispatch and settles reported consumption; unknown usage fences finite token admission, and provider underestimates can still exceed the allowance. After full pre-notice prompt measurement and before final admission, the registered `execution_allowance` event observes that same account at the first closed tool boundary and 50/20/5-percent remaining-consumption, tool-slot or deadline milestones; 6/3/1 comparable-input milestones use settled headroom and the same locally measured input, while unknown consumption has one additional observation. Displayed fit subtracts reservations and excludes output, the note, later growth/provider adaptation and other work; it never predicts actual dispatch. An appended note requires final remeasurement; ordinary rounds use one admission pass. Required artifact/archive/review handoffs remain original checks; working files/self-PASS cannot prove acceptance. The task holds only a monotone injection watermark, never a second budget or timer. Historical notes retain their round, live reservations reduce displayed headroom but cannot advance irreversible consumption milestones, and compaction does not reset the five-notice ceiling. Unbounded work gets no notice or new account. Original acceptance and role/tool permissions stay fixed; emission is not provider consumption, and every dispatch still rechecks authority. See [context injection policy](../CONTEXT_INJECTIONS.md) and [consumption limits](../TASK_EXECUTION_MODES.md#consumption-and-delivery-limits).

## Failure rules


Internal event-delivery failures are typed local failures, not provider failures.
Primary, reactive, configured-fallback and pool-rescue calls propagate them
without another model/key attempt; the fatal handler bypasses turn auto-retry.
The error envelope classifies `EventDeliveryError` as `server_busy` (revocation
or owner cancellation as `aborted`), reports `task-event-delivery` as its source,
and retains the explicit first cause in technical detail without classifying
provider-looking words in that cause. A later terminal publication or result
persistence failure is logged but cannot replace the original fatal envelope.
**Decision:** retain the original cause and use the existing settlement/recovery
owner. **Alternative rejected:** retrying a provider or masking the first failure
with a terminal-lane error cannot repair local durability.
`status: rejected` means the tool did not execute; the public `rejection` descriptor carries its stable kind, tool, reason, and known retryability. `_rejected` and result-level `rejected` are compatibility aliases. The descriptor survives the round, tool events, cold Turn projection, and activity timeline.
If it is the last terminal tool act, finalization emits a typed task error: `hallucinated` maps to `tool_not_available`; all other refusal kinds map to `tool_call_rejected` with original detail. Abort/interruption wins. Activity keeps status `skipped`, summary `blocked`/`unavailable`, and kind as `reasonCode`.
In the transcript the tool row owns the rejection inline (badge + the full, unclipped reason, kind code appended when absent), so the conversation view model drops the timeline's `blocked`/`unavailable` row whenever the matching round carries the descriptor; a trimmed or absent round keeps the timeline row as the last visible record.
Genuine failures follow the same rule: an error round owns its full tool content inline (no first-line/300-character clipping, line breaks rendered, no line clamp), so the view model drops the timeline's `failed` row — a log-policy-bounded excerpt — whenever the matching round renders the error lane; `execute_tools` gateway rows are exempt because they replay as child-validation rows, and a trimmed or absent round keeps the timeline row as the last visible record.

- Every durable terminal failure carries structured attribution. `lib/tasks_pkg/failure_attribution.py` stamps the loop's active dispatch round on the task; the failing seam (fatal handler, circuit-breaker envelopes) merges a bounded `failureAttribution {roundNum, phase, toolName, toolCallId}` extension onto the error envelope, and `turn_lifecycle._settlement` backstops any failed settlement still missing it (filling tool identity from the projection's last failed tool round). Diagnosis reads the failure record directly — never a post-hoc join of `toolRounds` and the turn trace. Transparent whole-turn auto-retries append a bounded receipt per discarded attempt (`_turnRetryChain`: kind, detail, backoff, attribution); the terminal settlement persists it as `retryChain`, so attempt N's error is never orphaned when attempt N+1 begins. A broken abort predicate fails loud once per signal instance (ERROR + incident-journal fingerprint `agent-loop.abort-predicate`), then throttles to DEBUG — the loop is never wedged and never silently continues.
- Never infer success from non-empty content.
- Never turn a provider/tool error into `done/stop`; an exhausted model fallback settles as `done/error` so browser, replay, and persistence consume the same terminal event.
- Only the typed result contract feeds the terminal tool-failure breaker; never infer retry policy from legacy text.
- Recovery crosses the stream-handler API as `RecoveryDecision`, never an open-ended dict.
- `TurnVerdict` derives durable completion fail-closed; missing evidence fails.
- Never push a frame whose authoritative write failed.
- Never retry a CAS conflict by rewriting a conversation-sized snapshot.
- Never bind after execution starts or report bound/queued work as running before physical worker entry.
- Carry the exact admission lease token through terminal settlement; release only its owned resources, exactly once.
- Fence stale attempts cooperatively; never let them emit indefinitely.
