# Ingest, papers, translation, and media
This domain turns uploaded or remote source material into validated text, durable paper/library state, derived reports, translations, audio, images, and video artifacts. It owns content-specific pipelines; generic task execution, storage, and model transport remain separate domains. The enabled `generate_image` schema stays within 400 tokens while preserving incremental source editing, exact saved-reference reuse, project/server and multi-root routing, aspect/resolution choices, and optional sibling SVG tracing.

## Ingest flow
1. Validate type and source authority before expensive work.
2. Stream or stage bytes through the upload boundary; never trust a filename as a storage path.
3. Select one parser through the file router.
4. Preserve page/section provenance and isolate page-level parser failures.
5. Canonicalize extracted text and metadata.
6. Commit the source row and required derived metadata atomically.
7. Start optional report, translation, podcast, or video work through a declared task runtime.

Remote fetches cross the shared URL/egress safety boundary. Parser fallback is explicit and diagnosed; it must not silently return an empty successful document.
## Chat attachment state
The owner-scoped Knowledge repository is the single persistence authority for chat documents/videos: one original, parsed chunks, and derived visuals. The chat layer has no parallel PDF-text store, video directory, or frame registry.

Scopes are `draft`, `attachment` (explicit ref), `library` (global retrieval), and `shared` (both, one source). Digest reuse changes scope instead of copying bytes; removing one side of a `shared` document demotes it to the other scope, and source plus derived assets are deleted together only when neither surface retains it.

New Turns carry complete server-resolved ref lists in `projection.attachments` and image ref lists in `projection.images`, never text, transcripts, frames, originals, or base64; missing/foreign IDs are rejected. Frozen historical inline images are not rewritten — only the conversation `refs` view swaps eligible duplicate bytes for an authenticated owner/revision/index-fenced lazy URL, leaving `full`, persistence, and model reconstruction unchanged. Native MCP image results are owner-scoped `attachment` documents: each image is capped at 8 MiB, each Turn at 40 MiB, and persistence failure does not fail the tool's text result. Continue/checkpoint-resume preserves existing image refs; regenerate owns a fresh list. At model-request time, relevant text shares a 96k-character request budget while bounded document visuals/model-aware video frames become request-local blocks. `att_media_<document-id>` and `/api/v1/media/attachments/<id>/source` reopen owner-authorized content without exposing its disk path.

Attachment text allowance is allocated in transcript order. Adding an attachment does not redistribute an older attachment's already-sent text. Exhaustion emits an explicit marker and recovery reference; the aggregate/per-document ceilings remain enforced. Completed-task replay retains admitted text and rechecks source availability before reuse. Tool screenshots use the same immutable media source store, with bounded `toolModelContent` references distinct from UI display text; model hydration checks the owner and returns a detached image block projection.
## Chat archive drops (source folders)
A `.zip`/`.tar(.gz)` dropped on the composer is treated as a *folder*, not a file: its value is the tree (`\input{chapters/…}`, figure paths), which only survives extraction to a real directory. `POST /api/v1/media/attachments/expand-archive` spools the upload and extracts it atomically via `lib.paper.archive` (path/link validation, complete streamed regular files and owned staging) into the managed chat workspace `uploads/workspaces/<stem>/` (`lib/chat_workspace.py`), then the client mounts the extracted folder as a project root through the normal `set_paths` path and — when TeX main candidates are returned — fires the paper-preview discovery hint. Unlike `POST /api/v1/project/upload-archive` (which requires an already-attached root), this works with no project set, so a ChatGPT-style 'drop a source zip on the input box' flows straight into a managed workspace. The composer chip is excluded from the model's document-attachment lane (no `attachmentId`, no text body) — the model reads the tree through the workspace tools, not the attachment budget.

Documents commit before `ready`. Videos reserve launch-probed worker capacity, TTL-reclaim scratch, and commit the original before analysis; turns may reference `processing` video. Frames/storyboard/transcript replace atomically; durable status survives worker registry expiry/restart. Transcript and storyboard calls each mint a bounded request-only model-routing v2 group for the attachment owner, hard-pin provider-only dispatch to that group, and dispose it after the background stage; they never borrow a process-global credential. Historical `pdfTexts`, `videos`, and `/api/videos/<filename>` are read-only compatibility. Classic local PDF extraction tracks unfinished work without count admission; independent pooled parses start in separate one-worker processes on demand. The launch probe governs idle reuse, while explicit parser/output policy stays at the parser boundary. Future timeout does not release still-running work or start a second parse; only construction failure before publication permits an inline fallback. An ambiguous submission joins its own executor before release. Knowledge holds that same lease across validation, text, OCR, visual/source persistence, and repository commit; per-image and input validation remain separate policies; aggregate visual bytes are file-backed and knowledge supplies no private extracted-text ceiling. One document create/replace publishes records, asset references and derived search terms in a single storage transaction. Aggregate search terms have no private transaction-write quota or proportional trimming; storage format validation and atomic rollback retain their own authority. VLM PDF transcription starts independent whole-document work on demand; launch-probed workers govern idle reuse. Separate page-call/rendering policy, task deadlines, actual 429 attempts and owner-scoped cancellation remain, while fresh terminal results are retained for their retrieval TTL without count eviction. Optional knowledge-asset vision descriptions start independent opted-in owners on demand. The launch probe governs idle reuse, each owner turn claims one durable asset, and restart recovery traverses every exclusive-owner-ID inventory page. Same-owner deduplication and stop/revive ownership remain; surplus idle carriers retire immediately. Before claiming an asset, each worker verifies the owner's runnable v2 vision routes; its paid description call uses a bounded request-only group under a hard pin and disposes that group in `finally`. This keeps image bytes in the repository instead of a memory queue and prevents one large corpus from starving another owner. Single-page classic fallback, expansion bounds, line/math normalization and cleanup live once in `text._extract_classic_page`; the caller retains document locking, global heading inference, admission, ordered progress and whole-document truncation. Problem: page jobs need identical page policy. Decision: share the serial helper; duplicating worker fallback/normalization risks diverging extractor provenance. This refactor alone changes no scheduling or defaults.
## Paper state
The paper library and derived records are owner-scoped Sidecar state. Normal browser shelf reads use one fail-open file snapshot, hydrate one owner/id detail, and retain two. Reader detail omits legacy Babel; metadata/QA writes serialize; hashes stay canonical. First content retries until ack; typed Report/Review state caps each language and validated reading-position map at 2,048 entries, retains 12 report snapshots, generation-fences same-paper starts, and hands provisional Stop intent to the returned task ID. At most 32 rebuttal drafts of 40,000 characters survive locally. Known papers start by hash: live/cache hits read no body, a true miss projects at most 120,000 owned characters, and only an explicit pre-dispatch source miss permits one bounded browser fallback. Reopen resolves live work plus preferred/fallback cache in one HTTP request; one owner-scoped Sidecar aggregate selects the base and returns only that language's Insight/termfill/checkpoint rows (four queries to one, at most eight offered siblings), without importing generation engines. Stale translation aborts, and cancellation-fenced tasks are never rejoined. **Translation Studio — Problem/Decision/Alternatives:** language-only fences could publish a former paper’s translation, and eager language/tab activation obscured paid intent. `babel.ts` binds the browser cache map to its source and freezes source id/hash/text/language per run; cache/start/poll/push/Stop and finally all check the same run. Source/session replacement or explicit Stop aborts known and late-created tasks, and abort acknowledgement comes from the retained API transport. `babel-reader.ts` shows source provenance, explicit language/Generate/Stop, actual progress, up to 32 artifact headings with paper Q&A, original-PDF access and clean Markdown/copy export. Only validated non-empty terminal text is saved/rendered, once; one reader scope owns listeners, one export URL/timer, and no background poller beyond the existing task. Rejected alternatives: guessed original-page links, partial-progress publication and a separate translator/Agent. Guards: `test_frontend_paper_babel.py`, `test_visual_paper_translation_reader.py`.

Long pipelines checkpoint at semantic stages (see Invariants). Abort closes runtime state and prevents later background callbacks from overwriting a terminal result. Auto-research overlaps its two independent primary judges behind a two-call ceiling; only material disagreement adds a third call, and final repository publication retries after every model-backed checkpoint. The survey boundary treats `open_gaps[].id` as a mechanical cross-stage handle: missing or duplicate model-authored handles are repaired deterministically after evidence verification, while the stage gate rejects any artifact still lacking a usable handle before ideation begins.

A completed auto-research direction opens an owner-scoped Research Foundry program. `contracts/research_program_v1.schema.json` is the authority for its falsification protocol, capability bindings, run/claim caps, LaTeX source tree, and compile/publication receipts. `PUT` uses compare-and-swap (409 on stale); submission readiness is derived, never a stored percentage. `research-action` jobs (`experiment`/`analyze`/`manuscript`/`compile`/`publish`) reuse the guarded Paper Agent loop with a narrower least-authority epoch: an MCP tool runs only when its exact namespaced name + schema hash are saved under a capability, and deterministic settlement requires a successful call receipt (model prose cannot assert a passing run/compile/publish). Report/Q&A/Deepen loops freeze one `PaperToolEpochV2` (provider wire projection + server-owned executable catalog); `tools.schemaBudgetTokens` applies the optional-tool cost target, and the fixed `search_tools`/`execute_tools` pair routes through the shared permission/validation/approval/settlement pipeline. These stages share one finite-progress policy: three identical call+world rounds halt before a fourth duplicate execution, and an aborted Q&A loop stays `aborted`.

**Execution reuse — Problem:** report generation already uses chat's `lib/agent_loop/agent_loop.py` through `agent_loop_policy.py`; Q&A and Deepen still duplicated full-catalog tool-round projection and feedback. **Decision:** both use `tools.make_paper_task_tool_executor`, retaining explicit workflow executor/event ports, the same owner-bound shim, raw argument validation, cancellation predicate, rejected status and bounded result feedback. Prompts/context fencing, model settings, draft resets, usage, cache/cost publication and terminal error/abort settlement remain with each workflow. Deepen round rows now retain the same optional engine/vertical metadata as their live events. **Alternatives rejected:** a new generic engine or routing Deepen through Q&A's terminal runtime would duplicate loop authority or erase distinct cache/cost and abort semantics. Guards: `tests/paper/test_paper_task_tool_executor.py`, Q&A/Deepen and full-tools suites. Shipped/default paper tools budget through an internal `ToolResultEnvelopeV2`, then put only its sparse semantic projection in the model message and retain the bounded evidence sidecar on the round. One result is at most 8,000 model-visible tokens and all results from one logical model round are at most 24,000. Oversized evidence is stored only through the semantic, owner-scoped artifact repository and continued with `read_tool_artifact` or `search_tool_artifact`; production paper application data never exposes a disk path or SQLite detail. Batched local file reads reuse the shared per-file projection contract, so every requested path remains represented even when a large first file exhausts preview space; paper adapters consume the same request-local sidecar before persisting their round state. Continuation tools join a non-empty paper epoch only for a positive owner, while owner-less compatibility calls stay bounded and return no invented recovery handle. The registered `tool_result_v2` experiment may explicitly select the bounded legacy adapter for its control arm. Such a run is request-local: it neither reads nor overwrites the canonical report/deepen cache, and its model+config fingerprint cannot join another arm's live task.

The reading workbench (`frontend/src/features/paper/workbench.ts`) is the default Paper entry. **Problem:** six peer tabs hide a useful reading order and scatter media discovery. **Decision:** show the selected source, a settled report's canonical thesis/excerpt, up to six real report headings, and a Studio shelf. Report lookup reuses the report owner with `readOnly`, so a pending regeneration intent cannot start paid work from the overview. Question actions reuse paper QA; Studio opens the existing podcast/video/translation/review owners. Media badges reflect only a matching paper hash and otherwise invite an explicit lookup. The kit owns navigation, keyboard behavior, and controls. **Alternatives:** a second summary generation/cache or media polling loop would duplicate authority and cost; neither is introduced. The workbench retains one DOM and no background poller. Canonical report excerpts remain identified as generated interpretation; the original stays visible in the paired PDF reader.

Q&A source checking (`frontend/src/features/paper/evidence.ts`) treats short answer blockquotes as unverified search queries. **Problem:** section references and model-generated page numbers do not prove that an answer matches the source. **Decision:** request at most three verbatim paper excerpts, distinguish report interpretations/external findings, and search the displayed PDF. Only actual PDF text matches receive page actions; a match confirms wording, not the answer's interpretation. Misses, unavailable text, truncation and failures remain explicit. Search shares the PDF reader's page/text/result budgets and normalizes whitespace/NFKC only; it adds no index, provider call or durable cache. One dialog/search is aborted on dismissal, paper teardown or replacement; source generation and selected-paper identity fence late results and navigation. Page actions show the source before layout-dependent navigation and restore reader focus after modal dismissal. At most six short quotes per settled bubble receive kit actions. **Alternatives:** trusting model page numbers or adding a second citation store would introduce unverified authority; fuzzy matching could misrepresent support. Neither is used.

**Report/review reader — Problem/Decision/Alternatives:** the desktop TOC disappears on phones and cached documents lack visible source identity. `report-reader.ts` adds the source, reading purpose, original-PDF action and a keyboard chapter menu bounded to 32 actual artifact headings; ready states use the shared factory with explicit generation. Source id/hash and teardown fence every control; the Report owner releases reader scopes, while retained rendering keeps audit cards, anchors, progress, notes and deepen. Rejected alternatives: inferred page citations, a second summary generator and replacing the existing task owner. Initial library hydration preserves the upload input node and newer source selection/optimistic rows; late results cannot clear them (`test_frontend_paper_entry_race.py`). Notes and deepen bind the clicked canonical document, freeze source/language across replies, fence late tasks and acknowledge cancellation; failed note mutations retain input in one kit dialog. XP projections retain only the current source, with weak view bindings; each depth job owns one cancellable wait/push, and source change releases jobs/editors. Verification measures 32 navigation items, one editor, and zero old XP projections across 100 same-id hash replacements. Guards: `test_frontend_paper_report_reader.py`, `test_frontend_paper_notes_deepen.py`, `test_visual_paper_report_reader.py`.

**Reading/Review model picker — Problem:** actions delegated on `document` share their opening click with the outside-dismiss listener; `stopPropagation()` cannot silence listeners on the same node. **Decision:** dismiss only clicks outside `.paper-report-model-picker`, let selection/toggle own dismissal, and close the sibling menu when opening. Keep model availability and defaults on the shared model projection. **Alternative rejected:** `stopImmediatePropagation()` would suppress unrelated document actions. Guards: `test_frontend_paper_model_picker.py` exercises the production action registry; `test_visual_paper_model_picker.py` repeats SVG-descendant selection in both reading views.

The reading experience projects one canonical experience manifest from report state. Section anchors are proposed by the model but resolved deterministically against the stored document. Cost/progress comes from recorded task/model usage, not a client estimate. “Deepen” is an explicit bounded task that starts from a resolved section; it does not hide a second report inside the first response. Localized metadata uses language-qualified semantic keys rather than duplicating the source record.

Podcast generation separates structured spoken script, deterministic formula, figure, and terminology validation, optional critic repair, TTS, audio assembly, and artifact publication. Script draft/revision/critic calls propagate task cancellation and use the finite production 429 budget. Short/full scripts admit at most 24/64 segments and 160 synthesis chunks; segment calls use a launch-probed 1..2 personal fan-out (distributed 4, hard ceiling 8), stop new admission after failure/abort, and retain at most 32 MiB per part / 192 MiB before ordered assembly. Motion-video topic/report scripts and scene authors likewise use two hard-error slot attempts plus the finite 429 budget; task-backed calls propagate cancellation through request waits and transient backoff. Director mode adds exactly one contrasting draft and at most one bounded critic after both deterministic gates; standard remains the one-call control, and mode changes checkpoint/dedup identity. Motion narration reuses the TTS fan-out for at most 16 scenes / 64 chunks, rejects scenes over 60 seconds or incompatible provider WAV parameters, removes failed partials, and binds text/timing/settings plus bounded file hashes in the immediately persisted resume manifest. Motion stock preflight admits at most one request per scene, 16 MiB per image or 32 MiB per video, localises bytes inside the job lifecycle, and writes bounded public attribution without credentials. Slide outlines/authors/QA use the finite text-model policy; independent pages overlap behind the 1..2 personal fan-out and only exact authored YAML with bounded size/hash plus zero-LLM validation resumes. Image preflight has a separate 1..2 personal fan-out, two hard attempts, finite 429s, six-image/20-MiB bounds, while caller and streamed remote images are capped at 20 items/40 URLs and 192 MiB per channel with exact crash caches. Invalid scripts never reach TTS; a partial audio file never becomes the published podcast or narrated video.

Ordinary server registration keeps only report, podcast, deepen, QA, translation, and recommendation task authorities; engines load on requests. A startup interruption sweep may load the podcast worker shell, but the LLM script and TTS/audio stages remain dormant until generation reaches each stage. The arXiv fetch/search routes retain only a lightweight typed query failure and patchable call seams; XML/Atom parsing, search activation, and HTTP title lookup load on the first real request. Review route registration resolves venue/prompt metadata but leaves deterministic review text processing and the shared language-detection cascade dormant.

The same `POST /api/paper/fetch-arxiv-stream` route also ingests a direct public PDF URL (any http(s) link whose path ends in `.pdf`). The landing input classifies arXiv reference vs PDF link vs title query and routes the first two through this one stream — a PDF link is never title-searched. `lib/paper/pdf_url.py` (lazily imported, like the arXiv seams) owns the structural check, a deterministic content-keyed cache name (`pdfurl_<sha256-16>_<basename>.pdf`), and a best-effort title probe (metadata `/Title`, else filename stem). A PDF link normalizes `arxiv_id` to `''` at every SSE stage and in the persisted row (never `null`), and downloads through the same SSRF-guarded `http_get` seam and byte ceiling as an arXiv fetch. Browser contract: a pasted PDF link emits exactly one `fetch-arxiv-stream` POST and zero `search-arxiv` calls (locked by `tests/e2e/test_e2e_journeys.py::test_paper_landing_pastes_direct_pdf_link_to_fetch_stream`).
## Translation
The SDK agent entry accepts `text`, `source_lang`, and `target_lang`, and forwards language options to the same asynchronous translation executor as the browser. It rejects invalid option types before task creation. A per-request `model` override is unsupported and returns HTTP 400 explicitly; the route does not advertise or silently ignore a model selection that the executor cannot honor. Translation retains its configured provider policy.

The shared work lane starts independent translation and whole-PDF jobs on demand. Launch-probed worker counts size only idle reuse; local task queues and translation-provider calls have no count admission quota. Fresh PDF results remain available for their retrieval TTL rather than being evicted by a burst. Actual provider health/billing policy, request deadlines and ownership remain authoritative. The lane detaches cancelled not-yet-picked-up jobs under its scheduler lock, then invokes Future callbacks after releasing that lock. Removed jobs complete the executor cancellation notification handshake, so `wait()` and `as_completed()` observe their terminal state even though no worker will consume them. Direct Future cancellation and lane shutdown use the same notification owner; cancellation racing worker pickup is counted once.

Translation separates language/direction detection, segmentation, LLM work, validation, and durable commit. Segment caches key canonical content plus source/target language and relevant policy. A refusal, wrong-language result, truncated or over-generated result is invalid and never cacheable. Literal `<think>` mentions in source documents are protected placeholders; only a leading MiniMax reasoning wrapper is stripped from a completion so a documented tag cannot truncate the rest of the translation. Incremental idle retirement and terminal consumption atomically close queue admission; late finalizers are rejected so the coordinator uses its whole-turn fallback instead of acknowledging work without a consumer.

**Completed-segment handoff — Problem:** five-minute idle retirement discarded validated preview translations, while whole-turn provider failure prevented reconstruction. **Decision:** the existing task-local preview state retains only completed source/translation pairs across worker retirement, under the same Turn call ceiling (32 preview entries on the reference personal profile, plus one terminal reasoning block). Sources are bounded at 32,000 characters, outputs at twice that; 33 maximal pairs retain at most 3,168,000 text characters, not the full task or an idle thread. Idle retirement best-effort commits only to a settled, owner-scoped Turn; a live Turn or transient write failure keeps that bounded cache for terminal handoff without another provider request. Stable attempt-scoped block IDs plus source equality are rechecked on every CAS retry, so edited/replaced blocks never receive old cached translations. Empty or already-translated deliverables still hand off cached segments. Finalize transfers the cache and cancellation invalidates it even if the queue already closed. **Alternatives rejected:** extending worker TTL retains threads for tool waits; editing live Turn projections bypasses executor authority; retaining an unbounded global cache or depending on whole-turn success recreates the loss. Live previews remain reconstructible, not durable-before-visible; process restart uses the owner-scoped bounded boot sweep (32 recently active conversations, seven-day age, up to 16 missing translations each), not the volatile cache. Settled-turn enrichment excludes translated/target-language/protected/cache hits and batches 16 segments or 6,000 source characters per call. Whole-turn success commits before task settlement; whole-turn failure records its durable `_translateFailed` verdict and terminal error first. Either outcome may then re-admit independent narration/reasoning enrichment behind the owner's existing bounded translation queue, with no independent durable lifecycle. Explicit abort and identity-invalid work do not schedule it; queued enrichment skips a Turn that has resumed generation. A segment-only commit never creates `_translateDone`, clears `_translateFailed`, or converts the failed task to success. It receives one shared 15-second wall budget, one upstream-429 attempt per call, and immediate-only shared-contention admission. Saturation may drop it; only a provider response that damages placeholder order/ownership may fall back to isolated validation, while dispatch/capacity failures skip the optional batch without fan-out and can never change the whole-turn task from success to failure. General, PPTX, settled-turn whole-output, and paper translation share one owner-fair lane (personal resource-probed root capacity (1..48 workers)/4..32 pending; distributed 16/128; idle retirement 60/600 seconds). The worker value FIFO-caps active MT/LLM calls across that lane, synchronous send work, and incremental accumulators; the queue value also caps provider waiters, with retryable fail-fast saturation and no local redispatch. Cache/identity/protected fast paths take no slot. Tasks remain `pending` until entry and queued abort frees capacity. A dispatch allows 4..8 actual rate-limit responses in personal mode (16 distributed, hard ceiling 64); capacity polls are free, exhaustion stops the workflow and later paper chunks. Non-terminal incremental previews additionally yield before transport to an already-active shared-contention gate; their call count and one-429 circuit live on the Task/Turn across idle accumulator retirement, while terminal reasoning, final/send translations, and interactive Agent dispatch retain their ordinary user-cancellable wait policy. Each LLM translation candidate also enters request-local strict billing-stop admission. A recorded key-wide 402 or matching model quota stop wins over a persistent manual-ON override for this optional work only; it cannot be last-resort promoted or bypassed through `smart_chat`'s direct default-key fallback. Healthy sibling models/providers remain usable, while a wholly rejected pool terminates before an upstream request, 300-ms cooldown poll, outer backoff, or per-segment fallback fan-out and projects as retryable `no_slot`/503. Attended Agent calls retain the ordinary Settings user-supremacy contract.

Paper and general translation share validation/cache/MT primitives but keep distinct provenance stores. Paper work packs 8,000-character semantic slices under 1,000,000-character, 128-slice, and two-hour ceilings; validated output stops at 2,000,000 characters/4,000,000 UTF-8 bytes, chunks retain only progress plus replay deltas, the browser renders the complete artifact once, and terminal polling carries either its done event or its caught-up snapshot rather than both. Automatic-model work may reuse cache/MT; `force` skips cache reads, while an explicit model stays strictly pinned. LLM slices fail closed on empty/no-op/wrong-language/truncated/over-generated output; a rejected slice, abort, deadline, or unconfirmed owner-repository write fails the whole task. Canonical reports require a non-empty body and confirmed write; request-local experiment arms explicitly suppress that write. Measured cost evidence stays in `CHANGELOG.md`.

General-translation route registration retains only constants, pure prompt transforms, the typed refusal identity, and the shared task authority. The `lib.translate` and `lib.translate.runtime` compatibility facades resolve the LLM/MT engine, worker, incremental commit path, and PPTX translator only when that operation starts. Adding a package-level export must preserve this focused import boundary; route discovery is not authority to initialize an engine.
## Media artifacts
Binary results are artifact references with MIME type, size, owner, lifecycle, and provenance. Text companions are retained where the UI or accessibility contract requires them. Audio/video clocks begin when meaningful processing starts, not at unrelated page load or queue creation.

Motion-video quality gates operate on declared creative plans, timelines, asset briefs, subtitle geometry, and render verdicts. A render process is not successful merely because it exited zero; required output and quality contracts must pass.

**Continuous-film authoring — Problem:** Tofu's scene pipeline can reset the visual world at clip boundaries. **Decision:** opt in with `continuity.json` beside `index.html` to author one persistent HyperFrames/GSAP stage through the existing low-level `motion_video_check` and `motion_video_render` tools; see the [continuous-film guide](../../lib/motion_video/guide/CONTINUOUS_FILM.md). `lib/motion_video/_continuity.py` samples declared carriers' DOM identity, visibility/geometry and reverse-seek pixels in the render owner's killable worker and produces boundary contact sheets; rendering refuses failed or unavailable evidence. Opted-in renders revalidate the `index.html`/`continuity.json` digest before and after the CLI, stage one MP4 on the destination filesystem and replace the prior output only after verification; failure/cancellation cleans the staging directory. This is not an immutable snapshot of every referenced asset. Platforms lacking safe no-follow directory operations and locking return structured infrastructure-unavailable instead of weakening link protection. Bounds are 24 beats, 180 seconds and 64 KiB per plan, at most 23 fixed preview paths per project and at most one transient scratch file during a check, with reserved scratch reclaimed under the directory lock after worker settlement. No persistent pool, scheduler or idle work is added. These are sampled diagnostics, not an artistic score or a new default `produce_video` mode: ordinary scenes are unchanged and the optional `production` plugin remains opt-in. **Alternatives considered:** independent-clip concatenation cannot preserve the same stage; a separate renderer or automatic continuous direction in `produce_video` would duplicate machinery or expand the existing contract. The implementation and starter are original; no OneTake source or assets are copied. **Focused tests:** `tests/motion_video/test_motion_video_continuity.py` (unit) and `tests/visual/test_motion_continuity_capture.py` (visual).
## Failure semantics
- Unsupported/oversized/malformed input: reject before task creation.
- Page parser failure: preserve page identity and surface diagnostics; follow the declared isolation/fallback policy.
- Duplicate source: return/reuse canonical identity without duplicating state.
- Invalid model-derived content: fail the stage and retain the last complete checkpoint.
- Abort: stop publication and settle the task once.
- Artifact storage failure: terminal persistence error; do not return a dangling URL or phantom success.
## Invariants
- One PDF extraction authority and one file-router decision point.
- Owner identity is explicit for source rows, derived rows, and artifacts.
- Shipped/default Paper tool results obey 8k/24k model-visible budgets without exemptions; an explicit legacy experiment control remains bounded and request-local.
- A full-paper wire budget never removes a capability from its owner-scoped Tool Search execution catalog.
- Report/deepen in-flight reuse requires an exact model+config fingerprint; long-agent policy requests never read or mutate canonical derived caches.
- Metadata commits atomically; file candidates survive unconfirmed publication outcomes (see [storage](../STORAGE.md#commands-queries-and-idempotency)).

Local publication rollback — Problem: document metadata encoding could fail after source/visual writes but before the publication handler, leaving unreferenced files. Decision: the store's publication boundary includes all preparation after visual ownership returns, plus media source rename and metadata construction.
