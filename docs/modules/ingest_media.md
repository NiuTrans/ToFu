# Ingest, papers, translation, and media
This domain turns uploaded or remote source material into validated text, durable paper/library state, derived reports, translations, audio, images, and video artifacts. It owns content-specific pipelines; generic task execution, storage, and model transport remain separate domains. The enabled `generate_image` schema preserves incremental source editing, exact saved-reference reuse, project/server and multi-root routing, aspect/resolution choices, and optional sibling SVG tracing.

## Ingest flow
1. Validate type and source authority before expensive work.
2. Stream or stage bytes through the upload boundary; never trust a filename as a storage path.
3. Select one parser through the file router.
4. Preserve page/section provenance and isolate page-level parser failures.
5. Canonicalize extracted text and metadata.
6. Commit the source row and required derived metadata atomically.
7. Start optional report, translation, podcast, or video work through a declared task runtime.

Remote fetches cross the shared URL/egress safety boundary. Parser fallback is explicit and diagnosed; it must not silently return an empty successful document.
## Chat attachment state
The owner-scoped Knowledge repository is the single persistence authority for chat documents/videos: one original, parsed chunks, and derived visuals. The chat layer has no parallel PDF-text store, video directory, or frame registry.

Scopes are `draft`, `attachment` (explicit ref), `library` (global retrieval), and `shared` (both, one source). Digest reuse changes scope instead of copying bytes; removing one side of a `shared` document demotes it to the other scope, and source plus derived assets are deleted together only when neither surface retains it.

New Turns carry complete server-resolved ref lists in `projection.attachments` and image ref lists in `projection.images`, never text, transcripts, frames, originals, or base64; missing/foreign IDs are rejected. Frozen historical inline images are not rewritten — only the conversation `refs` view swaps eligible duplicate bytes for an authenticated owner/revision/index-fenced lazy URL, leaving `full`, persistence, and model reconstruction unchanged. Native MCP image results are owner-scoped `attachment` documents: each image is capped at 8 MiB, each Turn at 40 MiB, and persistence failure does not fail the tool's text result. Continue/checkpoint-resume preserves existing image refs; regenerate owns a fresh list. At model-request time, relevant text shares a 96k-character request budget while bounded document visuals/model-aware video frames become request-local blocks. `att_media_<document-id>` and `/api/v4/media/attachments/<id>/source` reopen owner-authorized content without exposing its disk path.

That browser link has one builder, `lib/media_attachments.py::attachment_source_url`: attachment `sourceUrl`, MCP image `preview` and `read_tool_artifact` media tiles all use it, and clients render it verbatim as `<img src>`, outside transport path rewriting. Problem: a handler-local copy pointed artifact tiles at the retired v1 metadata route, and its test pinned that string. Decision: one builder, specified by fetching the emitted `sourceUrl` through the mounted routes. Alternative rejected: rewriting legacy image URLs in the browser, which would hide server drift. Tool rounds already persisted with the old link are frozen history and are not rewritten.

Attachment text allowance is allocated in transcript order. Adding an attachment does not redistribute an older attachment's already-sent text. Exhaustion emits an explicit marker and recovery reference; the aggregate/per-document ceilings remain enforced. Completed-task replay retains admitted text and rechecks source availability before reuse. Tool screenshots use the same immutable media source store, with bounded `toolModelContent` references distinct from UI display text; model hydration checks the owner and returns a detached image block projection.
## Chat archive drops (stored, not extracted)
A `.zip`/`.tar(.gz)`/`.tgz`/`.tar.bz2`/`.tar.xz` (or single-file `.gz`/`.bz2`/`.xz`) dropped on the composer goes to `POST /api/v1/media/attachments/archive`. `lib/chat_workspace.py::store_archive` copies the bytes verbatim into a fresh, auto-suffixed `uploads/workspaces/<stem>/<archive>`: only a printable basename with an archive suffix is accepted, bytes land in a part-file that is fsynced and renamed, and the directory is removed on any failure or empty upload. The client mounts that directory as a project root through the normal `set_paths` path, so the model sees the archive in its workspace and inspects or unpacks it with `run_command` when a task needs the contents. The chip stays `parsing` until the mount settles, and a send waits for it (bounded) because the turn captures project roots before submission; the chip never enters a document lane. Unlike `POST /api/v1/project/upload-archive` (which extracts into an already-attached root), this works with no project set.

Problem: eager extraction wrote one file per member, refused or rewrote archives the extractor could not represent, and decided the archive's meaning before the model saw the request. Decision: store the upload as sent; the model already owns workspace tools for listing and extraction. Alternatives rejected: extraction by default with an opt-out (more policy surface for something the model does on demand), and indexing members into the knowledge store (multiplies the per-document write cost described below). The TeX paper-preview hint that followed extraction no longer fires on drop; preview discovery applies once a TeX tree is unpacked.

## Composer document uploads
A dropped, picked or pasted document shows its chip immediately in the `parsing` state, like a PDF. Removing the chip aborts the request, and a reply that still lands releases the server copy; a failed upload removes the chip with a visible reason. A send captured while a document is still uploading waits inside the send pipeline after the optimistic turn appears. Afterwards a document with an `attachmentId` joins the `attachments` lane, and one that failed or never finished is dropped with a warning rather than reaching the model as an empty legacy document. In-flight chips and archive labels are not persisted across reload because an interrupted upload cannot resume.

Known limit on native TofuDB: one document create publishes every derived search posting in a single transaction, and commit fsyncs each new block file and shard directory while holding the writer. A 133,550-character mixed CJK/English `.txt` (94 chunks, about 53,000 postings) took 10–19 s on an isolated certified-engine authority, against 0.05 s at about 11,600 postings, and exceeded the 60 s command budget on the production volume. Other writes, including Turn submission, wait for the duration. The composer changes keep the UI truthful but do not shorten that write; the remedy belongs to the engine commit path.

Documents commit before `ready`. Videos take an owned processing handoff with no capacity count, TTL-reclaim scratch, and commit the original before analysis; turns may reference `processing` video. Frames/storyboard/transcript replace atomically; durable status survives worker registry expiry/restart. Transcript and storyboard calls each mint a bounded request-only model-routing v2 group for the attachment owner, hard-pin provider-only dispatch to that group, and dispose it after the background stage; they never borrow a process-global credential. Historical `pdfTexts`, `videos`, and `/api/videos/<filename>` are read-only compatibility. Classic local PDF extraction tracks unfinished work without count admission; independent pooled parses start in separate one-worker processes on demand. The fixed `TOFU_PDF_PROCESSES` hint governs idle reuse, while explicit parser/output policy stays at the parser boundary. Future timeout does not release still-running work or start a second parse; only construction failure before publication permits an inline fallback. An ambiguous submission joins its own executor before release. Knowledge holds that same lease across validation, text, OCR, visual/source persistence, and repository commit; per-image and input validation remain separate policies; aggregate visual bytes are file-backed and knowledge supplies no private extracted-text ceiling. One document create/replace publishes records, asset references and derived search terms in a single storage transaction. Aggregate search terms have no private transaction-write quota or proportional trimming; storage format validation and atomic rollback retain their own authority. VLM PDF transcription starts independent whole-document work on demand; fixed worker hints govern idle reuse. Separate page-call/rendering policy, task deadlines, actual 429 attempts and owner-scoped cancellation remain, while fresh terminal results are retained for their retrieval TTL without count eviction. Optional knowledge-asset vision descriptions start independent opted-in owners on demand. The fixed `TOFU_KNOWLEDGE_ENRICH_WORKERS` hint governs idle reuse, each owner turn claims one durable asset, and restart recovery traverses every exclusive-owner-ID inventory page. Same-owner deduplication and stop/revive ownership remain; surplus idle carriers retire immediately. Before claiming an asset, each worker verifies the owner's runnable v2 vision routes; its paid description call uses a bounded request-only group under a hard pin and disposes that group in `finally`. This keeps image bytes in the repository instead of a memory queue and prevents one large corpus from starving another owner. Single-page classic fallback, expansion bounds, line/math normalization and cleanup live once in `text._extract_classic_page`; the caller retains document locking, global heading inference, admission, ordered progress and whole-document truncation. Problem: page jobs need identical page policy. Decision: share the serial helper; duplicating worker fallback/normalization risks diverging extractor provenance. This refactor alone changes no scheduling or defaults.

**Browser report reopen ownership.** Problem: a method-absence branch repeated
live/preferred/fallback resolution in the browser beside the server resolver.
Decision: `report-runtime.ts` calls `Api.paper.reportResolve` once. The shipped
`createEndpointRegistry` always constructs that method alongside `reportLookup`

The paper library and derived records are owner-scoped Sidecar state. Normal browser shelf reads use one fail-open file snapshot, hydrate one owner/id detail, and retain two. Reader detail omits legacy Babel; metadata/QA writes serialize; hashes stay canonical. and checkpoint readers remained beside the aggregate reopen path, and focused

`routes/paper_pkg/_common.py::_project_prefetched_report_siblings` is the one

Long pipelines checkpoint at semantic stages (see Invariants). Abort closes runtime state and prevents later background callbacks from overwriting a terminal result. Auto-research overlaps its two independent primary judges behind a two-call ceiling; only material disagreement adds a third call, and final repository publication retries after every model-backed checkpoint. The survey boundary treats `open_gaps[].id` as a mechanical cross-stage handle: missing or duplicate model-authored handles are repaired deterministically after evidence verification, while the stage gate rejects any artifact still lacking a usable handle before ideation begins.

A completed auto-research direction opens an owner-scoped Research Foundry program. `contracts/research_program_v1.schema.json` is the authority for its falsification protocol, capability bindings, run/claim caps, LaTeX source tree, and compile/publication receipts. `PUT` uses compare-and-swap (409 on stale); submission readiness is derived, never a stored percentage. `research-action` jobs (`experiment`/`analyze`/`manuscript`/`compile`/`publish`) reuse the guarded Paper Agent loop with a narrower least-authority epoch: an MCP tool runs only when its exact namespaced name + schema hash are saved under a capability, and deterministic settlement requires a successful call receipt (model prose cannot assert a passing run/compile/publish). Shipped/default paper tools budget through an internal `ToolResultEnvelopeV2`, then put only its sparse semantic projection in the model message and retain the bounded evidence sidecar on the round. ## Translation

**Candidate quality ownership — Problem:** one retry loop mixed transport
recovery with repeated quality feedback and acceptance policy, making a new
content check easy to give a separate budget or inconsistent cache behavior.
**Decision:** `lib/translate/engine/_engine.py` owns dispatch, the shared failure
counter, deadlines and final commit; `_candidate.py` assesses one result and
applies feedback/refusal effects; `_quality_checks.py` owns pure ordered checks.
Empty exhaustion, optional partial acceptance and typed content refusal retain
their distinct outcomes. Provider feedback and refusal-store errors propagate;
audit/status notifications remain best effort. Quality timing ends with each
assessment. General text and paper translation use the same engine; paper
slicing/publication stays with its existing owner. **Alternatives rejected:**
separate retry loops per verdict (multiply paid attempts), a second paper
translator (duplicate policy), or merely moving the repeated branches to a new
file (retain inconsistent extension points). Specs:
`tests/translate/test_translation_quality_boundaries.py`,
`tests/paper/test_paper_translation_budget.py`.
The SDK agent entry accepts `text`, `source_lang`, and `target_lang`, and forwards language options to the same asynchronous translation executor as the browser. It rejects invalid option types before task creation. A per-request `model` override is unsupported and returns HTTP 400 explicitly; the route does not advertise or silently ignore a model selection that the executor cannot honor. Translation retains its configured provider policy.

The shared work lane starts independent translation and whole-PDF jobs on demand. Fixed worker hints size only idle reuse; local task queues and translation-provider calls have no count admission quota. Fresh PDF results remain available for their retrieval TTL rather than being evicted by a burst. Actual provider health/billing policy, request deadlines and ownership remain authoritative. The lane detaches cancelled not-yet-picked-up jobs under its scheduler lock, then invokes Future callbacks after releasing that lock. Removed jobs complete the executor cancellation notification handshake, so `wait()` and `as_completed()` observe their terminal state even though no worker will consume them. Direct Future cancellation and lane shutdown use the same notification owner; cancellation racing worker pickup is counted once.

Translation separates language/direction detection, segmentation, LLM work, validation, and durable commit. Segment caches key canonical content plus source/target language and relevant policy. A refusal, wrong-language result, truncated or over-generated result is invalid and never cacheable. Literal `<think>` mentions in source documents are protected placeholders; only a leading MiniMax reasoning wrapper is stripped from a completion so a documented tag cannot truncate the rest of the translation. Incremental idle retirement and terminal consumption atomically close queue admission; late finalizers are rejected so the coordinator uses its whole-turn fallback instead of acknowledging work without a consumer.

**Reasoning off — Problem:** only the non-streaming `smart_chat` path disabled reasoning, and only by its default. The streamed whole-turn path and strict-model calls sent no reasoning intent, so the reasoning-effort wire used the model's declared default rung. The cheap tier includes kimi-k3.1-pro, which always thinks, and it ran at `max`: a 3,236-character reply took 92 s to first content and 105 s in total. **Decision:** every translation dispatch passes `thinking_enabled=False`. Models that can disable reasoning turn it off; models that cannot fall back to their lowest rung (`low` for Kimi K3, or an enabled thinking control when the destination has no
disable control). **Alternatives rejected:** excluding thinking models from translation (most of the cheap pool are thinking models with an off or low rung); an explicit `lowest` depth (would keep reasoning on for models that can turn it off). Spec: `tests/translate/test_translation_reasoning_off.py`.

**Whole-document budget — Problem:** the terminal translation of a settled answer is ONE provider call, but its total budget was a flat 90s while the same call authorized a 180s transport timeout for large inputs. On a real 7,244-character answer the provider took 23s to first content and was still streaming at 90s, so the engine aborted a nearly-finished translation and committed nothing — the reader saw "translating" and then a failure. Chunking was re-measured and rejected again: two-way parallel halves took 78s and four-way took 96s wall against 28s for the single call, because the extra concurrent requests contended for the same cheap tier and rotated onto 429 fallbacks (77s and 84s single-chunk dispatches). **Decision:** derive the total budget from the same size table that picks the attempt timeout (90s floor, 2x the attempt timeout above it, engine 600s ceiling), classify a retryable transport failure (`ResponseReadTimeoutError`) as transient instead of deterministic, and publish the streamed deliverable translation under the stable `text:terminal` block id so the pending turn renders it while it arrives. Measured on the same answer: 28s end to end, 26s of which is provider time-to-first-content — the remaining latency is provider queueing, not local work. **Alternatives rejected:** fanned-out paragraph batches (measured slower), a flat longer budget for every size (parks a worker on a stalled provider), and committing an aborted prefix (would persist a half answer behind `_translateDone`).

**Deadline classification — Problem:** a long settled turn spends its enrichment ceiling on the first sequential batches, and every later batch used to be dispatched with a zero deadline. The engine then gave up before any dispatch and raised the same `ValueError('Empty translation result…')` as an empty model reply, so never-sent segments were logged as failed batch dispatches. That ValueError also hid deadline aborts behind `last_err=None` and projected as an `internal` task error. A deadline that expired right after a guard rejected a candidate returned and cached the refused candidate as the translation. **Decision:** the engine accepts only an explicitly accepted candidate. When the caller's deadline ends the loop it raises `TranslationDeadlineExhausted` (a `TimeoutError`) carrying the dispatched-attempt count, where zero means "not dispatched". Whole-turn settlement projects it as retryable `timeout`, and segment enrichment admits calls against its pass budget instead of dispatching remnants. **Alternatives rejected:** keeping the ValueError with a better message (callers still cannot branch on it); raising the 180s ceiling (long turns would still exhaust a larger budget, and it parks a lane worker for longer); dispatching small remnants (a 3s non-stream read timeout fails by construction).

**Preview deadline — Problem:** incremental previews and terminal reasoning shared one flat 30s budget (60s distributed). From 2026-10-20 to 10-25 it cut 724 previews (WARNING logs; 570 sized from their settled transcripts); 213 had lost 20s of the 30s to one silent slot's fixed response-header wait, leaving the rotated slot 10s. In the retained per-attempt timelines (2026-10-24 07:19 to 10-25 01:14) the miss rate grew with the source (2% under 500 characters, 9% at 0.5-2k, 14% at 2-4k, 24% at 4-8k, 76% at 8-16k, every preview above 16k); of those 102 misses, 48 were healthy streams still producing at the cut and 54 were reasoning models with no visible content yet. A cut stream was also counted as a dispatch failure (`1 dispatch fails, last_err=dispatch error`), blaming a healthy provider. **Decision:** the knob is the floor (45s personal, 60s distributed) of a size-derived budget: one response-header bound plus 1s per 180 source characters (the slowest decile's ~100 output chars/s at the p90 0.55 output/source ratio), capped at 120s and computed from constants only (`fixed` class, no hardware input). Every attempt's header wait is at most half of the remaining budget, so a silent slot can no longer starve its replacement; budgets of 40s or more keep the full 20s bound. A stream stopped by the caller's deadline is a deadline stop, not a dispatch failure. Replayed on the 724 misses, the sized ones get 45s (283), a size-derived budget (238) or the 120s cap (49), and every header-starved replacement attempt gets 25-100s instead of 10s. In the timeline window, all 44 cut streams of known size finish inside the new budget at their observed first-content time and the model's median output rate (38 at its slowest-decile rate and the p90 output ratio); the 54 still-thinking cases gain 15-90s (outcome not observable in logs); 92% of successful previews stay at the floor. **Alternatives rejected:** one larger flat deadline (still cuts every 16k+ source while holding small stalled previews longer); the terminal size table (90-360s budgets a deliverable, not optional enrichment); a shorter header bound for every caller (cuts the 2.5% of healthy headers that arrive after 15s even when the budget affords them).

**Preview circuit recovery — Problem:** three consecutive preview misses retired previews for the rest of the turn, and each missed block stayed in the source language until settlement. The 2026-10-27/28 logs hold 7 preview circuit trips; after 5 of them another task's preview succeeded within 3–28 s, so the provider was serving again while the tripped turns stayed untranslated (the other two waited 191 s and an idle overnight 6,412 s). The same logs record 112 incremental translation failures, 52 of them upstream 429s after the single allowed attempt and at least 39 deadline expiries; no failed preview block was retried while its turn ran. **Decision:** three consecutive misses of one preview kind (narration or reasoning, counted separately; see Live per-segment previews) pause that kind's previews for 60 s, doubling per failed probe up to 600 s. The pause lives in task-local state on the monotonic clock, so idle worker retirement cannot reset it. After a pause the next block of that kind probes the provider; a success clears that kind's failure count and pause. A failed block, and a block submitted or dequeued during a pause, keeps its source in a task-local anonymous file and re-enters the queue behind the next accepted submission, with at most three provider attempts per block. A newer submission of the same block supersedes its deferred source. Terminal handoff and cancellation release deferred sources; the settled-turn enrichment pass still translates any block left without a preview. Terminal reasoning keeps its own budget and never moves the preview circuit. **Alternatives rejected:** retiring previews for the turn (most trips were transient); retrying at once in the worker (repeats a rate-limited call while the provider is still saturated); a timer or sleeping worker per paused task (holds a thread through tool waits, which the idle-lifetime decision removed); unlimited per-block retries (keeps paying for blocks the provider rejects). Specs: `tests/translate/test_incremental_preview_retry.py`, `tests/translate/test_incremental_preview_rehydration.py`.

**Live per-segment previews — Problem:** each assistant segment should be translated as soon as it finishes generating, so the reply is already translated when the turn ends. Three paths broke that. A fixed 256-character floor (`TOFU_INCREMENTAL_TRANSLATE_PREVIEW_MIN_CHARS`) silently skipped shorter narration: in one measured running turn only the first narration segment (284 characters) got a preview, while 19 others (56–197 characters) stayed in the source language until settlement. Narration (`text:` keys) and reasoning (`thinking:` keys) shared one FIFO and one consecutive-failure circuit: on 2026-10-31, 120 of 121 preview failures were reasoning blocks and caused 31 pauses that also deferred narration, whose deferred blocks re-queue only behind the next accepted submission. Completion submitted the final reply once more as a preview keyed `text:<attempt>:llm-N`, but the reply's projection segment is `text:terminal`, so that paid preview was never shown or stamped while the durable whole-turn job translated the same reply again. **Decision:** the floor is deleted with its launch setting, so every completed narration segment costs exactly one preview call (19 more calls in the measured turn). The backlog hands out the oldest pending narration before any reasoning; each kind stays FIFO and repeated keys still coalesce. Narration and reasoning keep separate failure counts, pause windows and deferred retries with the unchanged constants above, so a reasoning failure never pauses or defers narration and vice versa; reasoning is still translated because the UI renders it. Completion submits no translation: the durable whole-turn job, which already streams under `text:terminal`, is the reply's single translation, and settled-turn enrichment excludes the deliverable segment. **Alternatives rejected:** a lower floor (still an arbitrary cutoff whose benefit exists only at a tuned value); batching short narration into one call (holds each segment until a batch window closes and adds a window knob); a second queue or worker per kind (another thread per turn for the same provider, where handout order in the existing buffer suffices); dropping reasoning previews (the UI renders reasoning); re-keying the completion submission to `text:terminal` (two writers stream one block and the reply is still paid twice). Specs: `tests/translate/test_incremental_translate.py`, `tests/translate/test_incremental_preview_retry.py`, `tests/translate/test_terminal_translate_durability.py`, `tests/tasks_pkg/test_native_completion.py`.

**Accepted-input ownership — Problem:** the turn command translated the human's text inside the HTTP request before the Turn existed, so acceptance waited on language detection, the provider and the translation-cache write (2026-10-27: `turn_command_total` p50 18.8 s, max 34.8 s; one send spent 12.0 s in `cache_store` for a 4.1 s provider call), and a restart in that window lost the input. **Decision:** the command persists the authored text and records `_deferredInputTranslation` in the accepted attempt config (server-authored; a client value is dropped). `start_conversation_attempt_executor` starts the translation before model-context assembly, so it overlaps registration, worker entry and workspace binding; the worker joins it just before the root or Flow runner reads its model view (`lib/tasks_pkg/input_translation.py`), shows the `translationWait.turn` phase while it waits, and substitutes only the authored segment (after quote/reference prefixes, before inline documents). The job never writes: the worker that joins it records the verdict as the input Turn's only writer before its first model request (`record_input_translation_verdict` in `lib/translate/commit.py`: the first verdict wins, and a Turn whose content no longer is the authored text keeps the edit), and a restarted attempt reuses a recorded verdict. A steer still translates synchronously because it enters the live model at once; a queued input keeps the deferral and translates when its own attempt starts. Stop, a failed translator or a hook-rewritten input leave the authored text in the model view. Translation-cache writes are reconstructible and run off the caller's thread (`translate_cache.put`). **Alternatives rejected:** acknowledging before executor start and translating in that background start keeps a single model-view source but changes the acknowledgement into an unbound pending attempt that the browser presents as executor preparation; translating inside the worker without an early start adds the whole translation after workspace binding. Specs: `tests/conversation/test_deferred_input_translation.py`, `tests/translate/test_translate_cache_store.py`.

**Input verdict ordering — Problem:** a background commit of the verdict from the translation job raced the worker, while a Coordinator request account pins the human source Turn's exact `projectionRevision`: an account bound at registration saw the commit advance that revision about a second later, and its first model dispatch was refused (2026-10-29; dispatch then charged the refusal to healthy keys and the fallback model, see `docs/modules/llm_io.md`, Authority refusals). The job also wrote after a Stop, so a stopped attempt could rewrite an input under a later attempt's account, and it could overwrite text edited in the meantime. **Decision:** the worker records the verdict before its first model request, as above; an attempt that owes a deferred translation binds its request account at worker entry (`lib/tasks_pkg/spawn.py`), after that verdict and against the revision it settled (`bind_source_account(expected_input=…)`); an input edited in between refuses. The same step re-pins the model replay proof the command read before this verdict (`rebind_history_proof`; see Model continuation lifecycle in `docs/LLM_COST_OPTIMIZATION.md`). Every other attempt still binds at registration. The verdict's single Turn CAS therefore precedes the first model request instead of following it. Whole-turn display translation, including the boot/open sweep, never writes a human input Turn. **Alternatives rejected:** relaxing the revision fence (it is what detects a human edit); pinning a digest of the authored text instead of the revision (changes the dispatch source contract and every grant and Worker pin); translating synchronously in the command for Coordinator sends (restores the acceptance latency removed above); keeping the job's background commit and having binding wait for it (a stopped attempt's job still writes later). Specs: `tests/conversation/test_deferred_input_translation.py`, `tests/project_mod/test_coordinator_request_budget.py`, `tests/tasks_pkg/test_task_start_ownership.py`, `tests/translate/test_terminal_translate_durability.py`.

**Completed-segment handoff — Problem:** five-minute idle retirement discarded validated preview translations, while whole-turn provider failure prevented reconstruction. **Decision:** the existing task-local preview state retains only completed source/translation pairs across worker retirement, under the same Turn call ceiling (32 preview entries on the reference personal profile, plus one terminal reasoning block). Sources are bounded at 32,000 characters, outputs at twice that; 33 maximal pairs retain at most 3,168,000 text characters, not the full task or an idle thread. Idle retirement best-effort commits only to a settled, owner-scoped Turn; a live Turn or transient write failure keeps that bounded cache for terminal handoff without another provider request. Stable attempt-scoped block IDs plus source equality are rechecked on every CAS retry, so edited/replaced blocks never receive old cached translations. Empty or already-translated deliverables still hand off cached segments. Finalize transfers the cache and cancellation invalidates it even if the queue already closed. **Alternatives rejected:** extending worker TTL retains threads for tool waits; editing live Turn projections bypasses executor authority; retaining an unbounded global cache or depending on whole-turn success recreates the loss. Live previews remain reconstructible, not durable-before-visible; process restart uses the owner-scoped bounded boot sweep (32 recently active conversations, seven-day age, up to 16 missing translations each), not the volatile cache. Settled-turn enrichment excludes translated/target-language/protected/cache hits and batches 16 segments or 6,000 source characters per call. Whole-turn success commits before task settlement; whole-turn failure records its durable `_translateFailed` verdict and terminal error first. Either outcome may then re-admit independent narration/reasoning enrichment behind the owner's existing bounded translation queue, with no independent durable lifecycle. Explicit abort and identity-invalid work do not schedule it; queued enrichment skips a Turn that has resumed generation. A segment-only commit never creates `_translateDone`, clears `_translateFailed`, or converts the failed task to success. It receives one work-scaled wall budget (15s floor, +1s per 80 source characters, 180s ceiling), the configured upstream-429 budget per call bounded by that same wall clock, and immediate-only shared-contention admission. The pass's first provider call always runs (the floor may sit below the header bound); a later call starts only while the remaining budget still funds the engine's 20s response-header bound. Work the budget cannot fund, or that the engine's typed deadline stop cuts mid-call, is counted in one INFO summary as skipped (not dispatched / cut at the deadline), never as a dispatch failure, and a later pass may translate it. Saturation may drop it; only a provider response that damages placeholder order/ownership may fall back to isolated validation, while dispatch/capacity failures skip the optional batch without fan-out and can never change the whole-turn task from success to failure. General, PPTX, settled-turn whole-output, and paper translation share one owner-fair lane (personal resource-probed root capacity (1..48 workers)/4..32 pending; distributed 16/128; idle retirement 60/600 seconds). The worker value FIFO-caps active MT/LLM calls across that lane, synchronous send work, and incremental accumulators; the queue value also caps provider waiters, with retryable fail-fast saturation and no local redispatch. Cache/identity/protected fast paths take no slot. Tasks remain `pending` until entry and queued abort frees capacity. A dispatch allows 4..8 actual rate-limit responses in personal mode (16 distributed, hard ceiling 64); capacity polls are free, exhaustion stops the workflow and later paper chunks. Non-terminal incremental previews additionally yield before transport to an already-active shared-contention gate; their call count, per-kind consecutive-failure circuits (three misses of narration or of reasoning pause that kind's previews; see Preview circuit recovery) and deferred retry sources live on the Task/Turn across idle accumulator retirement, while terminal reasoning, final/send translations, and interactive Agent dispatch retain their ordinary user-cancellable wait policy. Each LLM translation candidate also enters request-local strict billing-stop admission. A recorded key-wide 402 or matching model quota stop wins over a persistent manual-ON override for this optional work only; it cannot be last-resort promoted or bypassed through `smart_chat`'s direct default-key fallback. Healthy sibling models/providers remain usable, while a wholly rejected pool terminates before an upstream request, 300-ms cooldown poll, outer backoff, or per-segment fallback fan-out and projects as retryable `no_slot`/503. Attended Agent calls retain the ordinary Settings user-supremacy contract.

Paper and general translation share validation/cache/MT primitives but keep distinct provenance stores. Paper work packs 8,000-character semantic slices under 1,000,000-character, 128-slice, and two-hour ceilings; validated output stops at 2,000,000 characters/4,000,000 UTF-8 bytes, chunks retain only progress plus replay deltas, the browser renders the complete artifact once, and terminal polling carries either its done event or its caught-up snapshot rather than both. Automatic-model work may reuse cache/MT; `force` skips cache reads, while an explicit model stays strictly pinned. LLM slices fail closed on empty/no-op/wrong-language/truncated/over-generated output; a rejected slice, abort, deadline, or unconfirmed owner-repository write fails the whole task. Canonical reports require a non-empty body and confirmed write; request-local experiment arms explicitly suppress that write. Measured cost evidence stays in `CHANGELOG.md`.

General-translation route registration retains only constants, pure prompt transforms, the typed refusal identity, and the shared task authority. The `lib.translate` and `lib.translate.runtime` compatibility facades resolve the LLM/MT engine, worker, incremental commit path, and PPTX translator only when that operation starts. Adding a package-level export must preserve this focused import boundary; route discovery is not authority to initialize an engine.

## Failure semantics
- Unsupported/oversized/malformed input: reject before task creation.
- Page parser failure: preserve page identity and surface diagnostics; follow the declared isolation/fallback policy.
- Duplicate source: return/reuse canonical identity without duplicating state.
- Invalid model-derived content: fail the stage and retain the last complete checkpoint.
- Abort: stop publication and settle the task once.
- Artifact storage failure: terminal persistence error; do not return a dangling URL or phantom success.

The upload route still accepts only `VIDEO_EXTS` and sniffed video containers. `read_files`' binary refusal on both read paths, fetch_url's staged `audio/*` note and the page-media footer name `inspect_video` for audio. **Alternatives considered:** a separate `inspect_audio` tool was rejected: it adds another eager schema to every request and a second pointer to keep routed. Renaming `inspect_video` was rejected: it would churn the public tool contract and the recorded replay fixtures. Known gaps: the UI inventory copy still describes video only, and sentence-form Chinese audio queries do not rank in local Tool Search without a shared `audio` capability concept. Keyword queries such as `音频 转写` do rank.
