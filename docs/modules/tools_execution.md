# Tools and execution
This domain defines tool visibility, model schemas, validation/dispatch, and result projection; MCP/plugin setup lives in [`../TOOL_PLUGINS.md`](../contracts/TOOL_PLUGINS.md) and [`../TOOL_SEARCH_EXECUTION_GATEWAY.md`](../contracts/TOOL_SEARCH_EXECUTION_GATEWAY.md). The always-on `inspect_image` schema retains original-source rendering, upload/path routing, single-region cost guidance, grid, mixed-unit, and read-only semantics. Its coordinates use the visible frame after EXIF orientation and explicit clockwise `rotate`; explicit `crop` wins, while centre `zoom` runs only without a crop. `sourceSize` is EXIF-normalized, `encodedSourceSize` is the stored pixel matrix, `cropBox` is post-rotate, and the browser applies no further crop. Its searchable read-only sibling `inspect_video` returns a video's timestamped key frames as the read_files image batch plus probe facts and an optional transcript; its decision record is [Video inspection tool](ingest_media.md#video-inspection-tool-inspect_video).

## Ordered batch completion

`lib/tasks_pkg/handlers/_adapter.py` preserves one ordered result per input
occurrence, including duplicates, and emits progress when requested. **Problem:** an abort
skip and a successful empty result both returned `None`, so skipped retrievals
were reported as successful. **Decision:** the worker carries its execution
outcome separately from its value. Skips, submission failures and worker errors
report `ok=False`; a successful `None` remains `ok=True`. Started siblings still
join and retain their results. Progress observer errors cannot change settlement.
**Alternative rejected:** inferring success from result truthiness misclassifies
valid empty results. Worker reuse hints remain separate from active concurrency.
Verify `tests/tasks_pkg/test_batch_abort_outcomes.py`, per-item visibility and
the search/fetch, paper and Artifact batch suites.

Python ranking decision: **Problem:** without the native wheel, ranking called `networkx.pagerank`, which NetworkX 3 implements only through SciPy. ## Execution flow
1. The task policy resolves an explicit visibility allow-list.
2. The registry builds schemas for only those tools and rejects name collisions.
3. The model returns an ordered list of call occurrences with opaque, provider-batch-local IDs and JSON arguments.
4. The gateway validates the name, visibility, arguments, and capability.
5. A focused handler executes with the authenticated request environment.
6. The gateway normalizes success/failure and timestamps.
7. Settlement emits the canonical tool result and adds exactly one matching model-context result.

Tool schemas describe capability; handlers implement it. Bare relative project paths remain under primary regardless of file existence; explicit rootname paths select another root. The per-round assembly itself still runs, so plan, selection, owner grants and in-place config changes (`mcpEnabled`) apply exactly as before. A reconnect whose config changes `disabled_tools` now invalidates the projection too; before, the rows cache kept the previous grant. Bridges without generations (test doubles) keep a per-call copy. Alternatives considered—skipping the whole refresh while its inputs are unchanged: the inputs include the mutable task config, so an exact key needs a deep snapshot of that config every round, which costs what the skip saves; a per-task copy cache keyed by task id needs an eviction owner tied to task lifetime; read-only mapping types break JSON encoders and `isinstance(..., dict)` consumers. Specs: `tests/mcp_protocol/test_mcp_catalog_generation.py`.

**web_search query length (decision 2026-10-27):** Problem—a 3,510-character slide brief sent as a search query (15.9-16.4 KB request URLs) was refused by every engine (HTTP 414/400, a transport failure), and the repeated failures opened every engine's circuit breaker for 120 s. Decision—`WEB_SEARCH_MAX_QUERY_CHARS` in `lib/tools/search.py` (400 characters, surrounding whitespace excluded) is enforced per query by both the serial handler and the streaming prefetch through `oversized_query_refusal` in `lib/tasks_pkg/handlers/search/_presentation.py`. The model receives the query's length and the limit and is asked to shorten it to keywords; a batch's other queries still run. A single-query refusal precedes search-runtime activation and is non-cacheable, so the serial handler settles that exact occurrence. tofu-search's `perform_web_search` refuses the same bound (`query_too_long`) for direct callers such as production research; evidence and measurement live in `packages/tofu-search/docs/free-search.md`. The host keeps its own constant because it must run against the published tofu-search 0.12.25, which lacks it; `tests/tasks_pkg/test_web_search_query_limit.py` pins equal behavior. Alternatives rejected—silent truncation changes what is searched without the model knowing; a schema `maxLength` makes argument admission reject the whole batch and is dropped by the Kimi MFJS projection, so it cannot express a per-query refusal.

Bounded `tool_wire_projection` evidence records ordered final names, tokens, and an opaque fingerprint without full schemas; names or token counts do not prove byte stability.

`list_dir` is absent from new epochs; its bounded historical reader backs `run_command` fast paths. Filesystem `grep` segments keep pipeline placement. Directory-only relative `ls` scans 10,000 entries, returns 1,000, and formats at most 64 KiB. Shell `find` translates a GNU-faithful subset in-process: one relative root; basename `-name`/`-iname` globs (singly or as a same-case `-name a -o -name b` union); optional `-type f`/`-type d`; `-maxdepth`/`-mindepth` bounds; trailing `-print`; and whitelisted stream tails (`| head [-n K]`, `| wc -l`, `| sort` in combination). The bounded walker emits GNU pre-order/readdir order, so `| head -n K` subsets and `| wc -l` counts are exactly the shell pipeline's; an exact-total walk that exhausts the entry/deadline budget falls back to the native find segment. Listings cap at 500 paths including hidden/ignored files; unrecognized predicates, expressions, mutation, expansions, and other tails keep shell semantics. Fast-path results use `$ cmd … [exit code: N]` (reader failures exit 1), so task, metadata, and frontend classifiers treat them as executed commands; permission-denied targets keep the real shell. Direct real-`find` segments receive a 40-second host-compatible timeout before the ancestor/FUSE verdict; other recursive scanners require a narrow target or explicit timeout. Kill switches are `TOFU_RUN_LS_FASTPATH=0` and `TOFU_RUN_FIND_FASTPATH=0` (walk budget `TOFU_FIND_FASTPATH_SCAN_ENTRIES`/`TOFU_FIND_FASTPATH_DEADLINE_S`). Filesystem `grep` segments are spliced spawn-free in place (2026-09; the Python helper shim is retired): argv shapes proven GNU-equivalent become an rg argv (`grep_rg_translate`, `RIPGREP_CONFIG_PATH=/dev/null` neutralized, explicit multi-file operands pinned `--threads=1` for order), everything else keeps native GNU with only `--exclude-dir` injected. Accepted deviations are documented in `grep_rg_translate.py`: rg's ignore-aware traversal, recursive order, in-walk binary files skipped silently (GNU `-I` semantics), and `-c` staying GNU (rg ≥14 has no `--with-zero-count`). An absent caller timeout becomes a host-probed coreutils-`timeout` wrap (exit 124). Stream filters are never intercepted; sudo/builtin-wrapped greps refuse with a translation hint. Kill switches: `TOFU_RUN_GREP_GUARD=0` (layer off), `TOFU_GREP_REDIRECT=0` (refuse-always), `TOFU_GREP_RG=0` (GNU splice only), `TOFU_GREP_FORCE_GNU=1`/`TOFU_GREP_EXECUTABLE` (binary override). A lone `cp` runs in-process via the parallel copy engine (`copy_engine.py`; measured 2.9x on FUSE tree copies where tar-pipe/rsync are neutral-to-slower), and standalone cp segments inside compound commands splice the same engine as a helper; undo snapshots, read-only-root, and destructive analysis apply unchanged. The proven surface is `-r -R -a -p --preserve -f -v -d -P -u -n -x --one-file-system --strip-trailing-slashes` with multiple sources, preserving mode/timestamps/symlinks/hardlinks(-a/-p/-d)/sparse holes/xattrs (best effort)/ownership (root only); interactive/linking/deref/backup/target-directory forms keep native cp byte-for-byte. Idle reuse derives from the shared launch probe with `TOFU_CP_WORKERS` override; independent copies start without a count window; `TOFU_RUN_CP_FASTPATH=0` disables both entries. A `search_files` tree-index hit always remains eligible. When no index can serve a directory and a real rg/GNU scan times out, an owner-scoped `(target, include)` circuit skips equivalent live walks for 300 seconds by default; a narrower target, different include glob, different authenticated owner, or ownerless legacy call remains independent. The skipped result states that no scan ran and never reuses file content or partial results. State is content-free and process-local, retains 256 entries by default with a 1,024 hard ceiling, and expires on cooldown or equivalent success. `TOFU_GREP_TIMEOUT_COOLDOWN_S=0` disables it; the cooldown is capped at 900 seconds and `TOFU_GREP_TIMEOUT_CIRCUIT_ENTRIES` cannot exceed 1,024. The shared tree index keeps its 45-second base refresh and 900-second hard trust boundary. A complete rebuild whose sorted path and size columns exactly match the prior in-memory snapshot schedules the next refresh at 90 seconds, then at most 180 seconds; any candidate difference immediately resets to 45 seconds, and a disk-loaded/process-restarted snapshot also starts at 45. `TOFU_TREE_INDEX_STABLE_REFRESH_MAX_S` may tune the stable ceiling only within 1..900 seconds and never beyond 80% of the hard trust age when that age is coherent. Index-backed grep/find results older than the base interval expose compact `age/scheduled` evidence: existing grep contents are still read live and Tofu write tools synchronize or invalidate candidates, while external path/size changes may not yet be reflected. A background warm first restores an evicted local blob: a base-fresh snapshot suppresses the project walk, while a stale-but-trusted snapshot is served during the unchanged refresh. When a synchronized write has invalidated that blob, LRU eviction atomically checkpoints the current in-memory columns first; revision validation prevents an older asynchronous persist from reinstalling superseded columns. A clean or over-budget entry adds no write, while checkpoint failure keeps the blob absent and preserves the rebuild fallback. A plain Python script/`-m` on a network workspace may receive an owner/workspace/interpreter-scoped host-local `PYTHONPYCACHEPREFIX`; unsafe/inapplicable environments stay unchanged. Under a managed server the command inherits the server's own prefix instead, which this cache never overrides. The reconstructible cache has no size quota and shares the server cache's retention ([infra_runtime.md](infra_runtime.md#host-local-bytecode-caches)): namespaces in use survive; others go after the seven-day TTL (`TOFU_RUN_PYTHON_CACHE_TTL_DAYS`), when their workspace or interpreter was provably removed, or while the volume is below the shared free-space reserve; a detached sweep removes bytecode of removed source directories. Default `auto` activates after repetition; `TOFU_RUN_PYTHON_CACHE=1|0` forces/disables it.

Eligible single-destination Git HTTPS/SSH and curl/wget commands race lightweight direct/configured-global-proxy probes before spawn, project only the winner into the child, and execute the original command exactly once. Git HTTPS cold races prefer a real smart-HTTP response over a faster SSO redirect and stop as soon as that stronger evidence arrives. Health keys include protocol, host, and port. Explicit proxy/SSH routing, multiple targets, recursive submodules, and unparseable shell shapes retain original semantics; protocols are never rewritten and side-effecting work is never replayed. HTTP(S) uses a child-only proxy/no-proxy overlay; SSH requires a bounded unauthenticated CONNECT probe and the internal ProxyCommand bridge. Credentialed pool rows remain vault-scoped; shell routing uses its existing environment/config proxy plus credential-free global rows. Proxy credentials stay out of command text, argv, metadata, and logs. Exhausted routes return not-run, while result markers distinguish route, auth/client, network, and pipeline-masked failures. `NO_PROXY` is the normal HTTP default; command auto-routing may challenge it with a configured global proxy, except loopback/link-local. `TOFU_RUN_NETWORK_RESPECT_NO_PROXY=1` makes it strict; `TOFU_RUN_NETWORK_ROUTE=auto|inherit|direct|proxy` selects the master mode. Connect/read/race defaults are 2/3/5.5 seconds, with eight lazy workers, four proxy candidates, and 64 cached protocol origins.

### Configuration-proven Python package routing

**Problem:** installers use implicit registry destinations, so explicit-URL command detection cannot prepare their network route. **Decision:** `lib/project_mod/package_network.py` admits literal named-distribution `uv tool install`, `uv pip install`, `pip install` and `python -m pip install` profiles to the existing network owner. It requires one known index, the final child mapping, and config-neutral inputs. Only the original installer executes, once, through the normal approval, writer and cancellation boundaries. No installer, transport, timer, persistent cache or credential authority is added.

Discovery reads bounded metadata, never config contents or secrets. Per the [uv configuration contract](https://docs.astral.sh/uv/concepts/configuration-files/), `uv tool` ignores local configuration; `uv pip` checks the physical working directory and its ancestors. Resolution errors and unknown user/system/project configuration keep inherited behavior. Pip's actual interpreter owns site configuration, so routing requires the caller's existing `PIP_CONFIG_FILE=os.devnull`, which [pip documents](https://pip.pypa.io/en/stable/topics/configuration/) as disabling all config files; Tofu never injects that setting. Unsupported options, file/VCS/requirements sources, multiple indexes, shell expansion/compound destinations, explicit proxy/client-TLS settings, and ambiguous or CIDR bypass rules likewise keep inherited semantics without probes.

Package routes respect configured index bypasses and preserve the child's internal `NO_PROXY` list. Probe metadata contains only the anonymous index origin. A selected proxy may serve artifact/build traffic, but the annotation proves only index reachability; installer outcomes never update index or proxy-pool health. That proof is not an install-success claim.

**Alternatives rejected:** hardcoded PyPI probes misidentify private indexes; automatic config suppression overrides user authority; an installer-specific retry/transport duplicates lifecycle and can replay writes; attributing CDN/build failures to the registry corrupts shared health. **Expiry:** this conservative detector assumes no maintained client-owned effective-config/destination plan exists. Replace it only when such a plan preserves configuration, bypasses, redaction and no-replay behavior; recheck when pip/uv configuration semantics change. Verification: `tests/project_mod/test_package_network_routing.py`, including physical-cwd configuration and one real-child execution.

Normal tools remain model-synchronous: one result; bounded progress is presentation-only. `ToolExecutionContext` wraps task abort, scoped cleanup, deadlines, progress, and output. HTTP/push Stop share one owner-checked manager path; commands use TERM/grace/KILL/reap. Detached lifecycles stay unchanged. See [`../EVENTS.md`](../contracts/EVENTS.md). High-level `produce_video`, `produce_report`, `produce_slides`, and `produce_research` are explicit detached producers. A successful handler stamps one accepted-task receipt; after the whole tool batch settles, root chat uses the established clean-finish path (`finishReason=stop`) and emits a deterministic acknowledgement. The background task runtime—not another model round—owns polling, progress, completion, error, and artifact-quality truth.

## Visibility and authority
Tool availability is per request. Installed does not mean visible. Multi-user deployments default to an explicit allow-list; a dedicated operator may expose more tools through declared configuration. Plugins, MCP servers, request-level custom tools, and built-ins all cross the same name/visibility gate.

Project and filesystem tools receive a resolved workspace/root capability; exact UI reconciliation of primary/root/access state is side-effect-free, while any drift follows the normal prune/register path. They do not infer authority from the process working directory. **Edit target decision — Problem:** requiring `path` on every edit item made the common "one file, several hunks" request inexpressible in the shape every other harness teaches (name the file once, then list hunks); models encoded it as a blank or omitted item path, which the contract rejected pre-execution, costing a full re-emission round per occurrence. **Decision:** `edit_file` declares a batch-level `path` that supplies the file for every edit that omits its own; an item `path` overrides it for a multi-file batch. Neither level declares `path` in `required`, because the two accepted forms are "batch path, no item paths" and "item paths": a root schema combinator would express that choice but hard-400s providers that reject root combinators (the same 2026-09-06 write_file ``oneOf`` incident). Coverage is therefore a cross-level rule in `lib/tool_input_repair/_ingest.py`: a batch that names no file anywhere fails closed before execution — filling it would mean guessing a file to write — and the rejection names the missing rule plus the declared files. Repair still distributes a single declared file onto blank items, the executor resolves each edit through the batch path, and the file-change projection reports the resolved path. **Alternatives rejected:** inheriting the previous item's path (a blank then means either "same file" or "unknown file", and the wrong guess writes the wrong file); silently dropping blank items (partial batches with no signal); requiring a per-item path and relying on the retry message (measured as the original recurring failure). Verify `tests/tool_input_repair/test_edit_batch_blank_path_diagnosis.py` and `tests/project_mod/test_edit_file_atomic_preflight.py`.

`edit_file` preflights the complete sequential batch by default (`atomic: true`), including canonical destinations and tracked journal admission, before publishing files; explicit `atomic: false` retains partial mode. `SKIP`/missing/ambiguous per-operation receipts never render as successful writes. This is not cross-file rollback after I/O failure; see `docs/PROJECT_FILE_UNDO.md`. Write tools use shared path validation, freshness, atomic replacement, and write-set attribution. Read results never grant a subsequent write automatically. **Recovery decision — Problem:** legacy Git retry flattened compound shell source, and unknown namespaces aborted entire read batches. **Decision:** prepare Git compatibility before running the body, preserve separators/cwd and disposable indexes without replay; isolate read-root errors per item and include the available registry and primary root. Absolute local reads need no root registration and grant no write authority. **Alternatives rejected:** quoting an entire shell program as argv loses control syntax; guessing roots or falling back silently reads the wrong repository. Verify compound commands in synchronous/interactive modes, unchanged indexes, valid/unknown/missing reads and structured error items with `tests/project_mod/test_tool_failure_recovery.py`.

Project read freshness comes from host-owned, descriptor-pinned per-item observations of the source bytes, not a filesystem reread after rendering. Tokens bind full-source SHA-256 and semantic-root identity even for ranged reads. Failed, unsupported, out-of-bounds or undisplayed reads cannot mint evidence. Modern serial read rounds retain observed-path receipts; streaming reads forward snapshot evidence through the common token owner. Ambiguous historical multi-read text cannot satisfy read-first by counting `File:` headers inside untrusted content; it requires a fresh read. Single successful legacy reads remain compatible. When snapshot recording is explicitly disabled, streaming multi-read text alone is insufficient; use an observed serial read or a successful single read. This changes read/freshness evidence, not filesystem authorization.

Plan Mode is a stricter request policy layered over this boundary. Initial wire exposure and the Tool Search catalog remove mutating or unproven schemas; the final dispatch check independently requires the exact call to be proven read-only. Unknown and caller-defined tools fail closed, MCP tools require an explicit `readOnlyHint: true` or a host-reviewed catalog read (below), and mixed desktop tools expose and accept only their read branches. This also applies to caller-supplied `tools=[...]`; unknown schemas are removed and the framework-owned canonical `ask_human` schema is present so within-turn clarification cannot be disabled accidentally. The policy owner is `lib/tasks_pkg/plan_mode.py`. Long-running tools normally keep one-call/one-result model semantics: `ToolExecutionContext` scopes sequenced/coalesced UI progress, bounded reconnect state, task-abort fanout and TERM→grace→KILL→reap; overflow spools outside the project under a shared task budget, persists as an opaque owner-scoped expiring artifact, and returns bounded head/tail (partial on cancel/timeout/interrupt), while startup reclaims abandoned spools. Local `run_command` registers its PID/PGID before any spawn callback, then uses a 350 ms live-start grace: a command that settles inside the window emits only its authoritative terminal result, while a command that outlives it (or produces at least 4 KiB early) asynchronously publishes the spawn clock, opens live output, and checkpoints the running round for reconnect recovery. When an attended conversation receives a durable `user-steer` while a real subprocess is running, the handler closes the outstanding tool-call/result pair with one provisional background receipt and immediately releases the model loop to consume the steer. The worker owned stdout/stderr from process start, so handoff cannot strand a pipe; it stops foreground progress, preserves timeout/whole-task Stop, cwd/index/file-diff finalization, and queues the bounded authoritative result as a passive durable completion receipt. A live turn can consume it at the next model boundary; an idle conversation waits until all known background commands have published, then starts one collective completion turn, including after restart. Explicit stdin waits remain foreground-owned. Procfs stdin detection is an optional stateless sensor: blocking syscall reads run outside the command-control loop, at most one sensor per command and a process-wide capacity derived from the cached `TOFU_AGENT_WORKERS` envelope, with no queue or eager workers. A closed command fences late samples before releasing its descriptors; blocked sensors retain their physical slots until return and hold no task state or delivery callback. Stop, explicit command deadlines, interrupt and output draining continue while sensing is unavailable. Problem: procfs syscall reads can stall command control. Decision: keep sensing outside that loop with physically bounded ownership. Alternatives rejected: disabling input or abandoning an unbounded set of task-owning readers. Lazy initialization starts zero threads; a capacity-one fault check retains one blocked worker, refuses eight additional sensors and returns to zero only after release. Interactive prompts render bounded stdout/stderr buffers through their canonical render ports. Swarm and Flow workers run as child invocations: each `run_command` publishes its pid/pgid into its own worker task's foreground-command registry (`lib/project_mod/foreground_command_slots.py`), so the stuck-task reaper interrupts the silent command instead of force-failing the worker, and Stop and a pid-stamped `_cmd_interrupt` reach exactly that command while its siblings keep running.
**Default tool exposure (decision 2026-11-01).** **Problem:** `ToolSpec.discovery_policy` defaults to eager, so rare domain tools (`browser_download_url_to_server`, the longest built-in name, and `repo_map`) paid schema tokens and Sankuai tool-name budget on nearly every request. Request routing also dropped *searchable* families (project integration/messages, scheduler, skill install, working facts, retained agents, exploration, rich responses) from every provider surface: native Tool Search could not find them and `tools.toolSearch=off` hid them with no discovery path; it also routed away the declared-eager `inspect_tool_effect` recovery tool. **Decision:** every built-in and bundled name has one reviewed default exposure derived from existing declarations (`discovery_policy[_by_name]`, `pin_on_exposure`, `direct_wire_tools`) and shown in the generated inventory's `exposure` column. Eager core: read/search/edit/write/shell, web search/fetch, tools named by model-visible prompts, results or recovery pointers (`inspect_image`, `inspect_video`, conversation references, memory search/create, skill reads, artifact continuation, `inspect_tool_effect`, swarm launch/result), the Coordinator role surface (router and channel tools only for the owner's Global Router, watchdog tools only for the Router Watchdog; [ROUTER.md](../ROUTER.md) R1/R7), `evolution_source`, and toggle-gated `ask_human`. The Coordinator surface includes `update_task_progress`: the role prompt and `report_to_user` name it as the human's only progress view, so deferring it would leave a dead-end pointer on every Coordinator turn; eager costs nothing elsewhere because the family is built only for the bound Coordinator and its coordinator-mode continuations, Worker grants deny it, and headless or storage-free runtimes never resolve the role. Pinned: `poll`/`kill`. Direct: `timer_create`, `await_device` (both end the turn on a deferred completion) and the evolution coordinate/artifact/review completions. Toggle: desktop; browser stays deferred when enabled. Everything else (domain, admin/settings, approval, coordination/messaging, rare maintenance and bundled domains) is deferred. `inspect_video` is eager and routed with `inspect_image` (`routing._ALWAYS`) because `read_files`' video/audio refusal, fetch_url's staged video/audio note and the page-media inventory footer point to it; its private search hints still rank it under a schema budget. Routing narrows eager families only (`_wire_visible`); a searchable family always stays a provider candidate, so local search keeps it behind `search_tools`, provider-native search marks it `defer_loading`, and search-off sends it direct. Only an explicit exposure preference (composer toggle or settings gate) keeps a family off the search-off surface; it stays executable by exact name under `executionScope=available` and discoverable through local search. Availability still precedes exposure: since routing no longer hides searchable families, the registry withholds every `ToolSpec.saved_conversation_tools` name from a request without a saved conversation before routing or Tool Search run, so it joins neither that request's wire nor its catalog ([HEADLESS_API.md](../contracts/HEADLESS_API.md), "No saved conversation"). **Alternatives rejected:** making tools a provider cannot see unexecutable breaks exact-name and replay admission; search-off-specific routing, caps or caches add machinery; deferring core or pointer-named tools creates dead-end pointers and extra rounds; flipping the dataclass default would silently change third-party plugin exposure. Local admission measures the initial projected local surface; native projects its actual wire before admission and reuses it for dispatch. Search-off retains the full direct catalog even when a provider's external name/cache constraint cannot be met. Rebuilt attempts reuse the round's orchestration-decision row rather than appending a second adoption verdict. Alternatives rejected: charging admission for deferred schemas can refuse a fitting 32K request; counting the native catalog before projection diverges from the actual request; duplicating retry decisions misreports adoption. Specifications: `tests/tools/test_tool_exposure_policy.py`, `tests/tasks_pkg/test_deferred_tool_admission.py`, `tests/tasks_pkg/test_native_context.py`.

## MCP boundary

**Failure classification and reconnect replay.** Problem: matching transport words inside protocol error
messages both misclassified healthy error responses and missed the installed SDK's reworded timeouts.
Decision: `client/_errors.py` reads structured request-timeout/connection-closed codes before its legacy
text fallback. A valid peer error response proves liveness and clears the consecutive-timeout streak;
both the first attempt and a retried read settle health through one owner. A configured deadline of `None`
remains unbounded, including timeout diagnostics; it is never formatted as a numeric duration.

`MCPBridge.call_tool` defaults `retry_on_disconnect` to `None`: automatic reconnect replay requires a
server-owned explicit read declaration with a captured identity/fingerprint, and rechecks that declaration,
enabled state and owner cancellation after reconnect. A write or unproven tool's ambiguous failure is
returned without replay. Explicit host `True` retains the controlled retry port for callers that establish
repeatability themselves; explicit `False` disables reconnect replay. This option is not a model argument.
The direct and progressive MCP adapters let transport failures reach common executor effect settlement;
SDK timeout errors normalize to Python `TimeoutError` there. An uncertain write retains its occurrence ID
and inspection guidance. Alternatives rejected: retrying every disconnected call can duplicate writes;
disabling all recovery would make safe reads needlessly manual; flattening exceptions to strings loses
effect evidence.

Dynamic MCP execution contracts derive permission and recovery from the live catalog's matching schema
and explicit `read_only_hint`, across inline, progressive and delegated exposure. Missing, conflicting or
stale metadata compiles as write/reconcile; it does not inherit the static wrapper spec's read default.
The assembly-local map clears with the allowed catalog on disconnect or failed assembly. This keeps
common executor settlement consistent with MCP write partitioning without another recovery state machine.
The map is bounded by the allowed catalog and rebuilt only during assembly, with no new RPC or persistent
cache. A 2026-10-21 Python 3.12 probe (eight input fields per tool, distinct equal schemas) measured
1,000 tools at 1.065 ms median and 26,032 bytes retained for the map; 10,000 tools used 11.277 ms and
207,616 bytes. Keys and boolean values reuse catalog objects.
Verify classification, disconnect recovery, production contract assembly and real handler settlement tests.

**Conversation declaration authority.** Problem: pressure clearing, TTL/LRU eviction and missing body checkpoints reselected MCP schemas from latest intent, rotating the prefix. Decision: `lib/storage/mcp_declarations.py` freezes one ordered wire (explicit `[]` differs from absence) in configured conversation settings with atomic CAS; concurrent writers return the winner. JSON text preserves nested key order. Owner+conversation identity prevents copied settings inheriting a wire. Registry reads precede search and body replay; legacy checkpoint `mcpWire` is not an authority. Disconnected catalogs retain declarations, never execution grants; dispatch uses the live allowed catalog. Non-adaptive modes retain baseline tools on catalog outage and clear partial MCP grants/search metadata; an initial adaptive declaration fails visibly. Initial search/storage/corruption/over-budget failures raise `MCPDeclarationError`, never broaden the catalog or silently change wire. One slot per conversation has a 128-definition / 256-KiB encoded ceiling, no resident conversation-wire cache, per-turn history or TTL; deletion removes it. `MCPDeclarationStore.reset` is an explicit owner operation, not memory-pressure cleanup. Task-only scopes keep launch-probed TTL/LRU bounds; inline/delegate/disabled overrides remain. Rejected alternatives: another database, lifecycle-free records, unbounded frozen RAM and checkpoint-only restoration. `lib/conversation_sync/settings_policy.py` hides the private slot from public projections and ignores client-supplied values before atomic merge, including create/append/queue defaults; only trusted freeze/reset CAS can change it. Verify with `tests/mcp_protocol/test_mcp_declaration_lifecycle.py`, `tests/storage/test_mcp_declarations.py` and `tests/storage/test_private_conversation_settings.py` (SQLite and native backends). The 100-conversation fixture measured 587 encoded bytes per wire / 58,700 total, zero resident conversation wires and two selection entries under a two-entry LRU. This is logical/resident footprint, not physical backend WAL/receipt storage. MCP lifecycle, discovery, health, and transport live under `lib/mcp/`. Configuration and bridges require an explicit owner; only personal bootstrap may claim the legacy shared configuration, with a durable claim preceding the copy. Requests never migrate credentials. Owner bridges have no count quota and never evict another owner's transport to admit a request. Shutdown retires existing owners without creating new bridges. Loop creation/submission and shutdown admission share one lock; completed handshakes cannot publish into a later lifecycle generation. The owning loop thread cancels pending tasks and drains transport, async-generator, and executor cleanup before closing its loop and retiring physical resources. The caller joins for at most five seconds; slower cleanup remains referenced and retains its retired owner generation, including across repeated shutdown calls. Cross-thread submission failures close unsubmitted coroutines. Shutdown-wait deadlines cancel their own waiter without cancelling the transport owner's shared completion future. The registry normalizes the full search/execution authority while active schemas are a smaller wire projection. Auto exposure is owner+conversation scoped and reuses prior calls on low-signal turns before fallback; search cards are not wire evidence. `MCPBridge.get_enabled_tool_summary()` is the sole compact browser/status projection: under the bridge lock it counts only enabled tools on live or parked handles, sorts server names, copies no description or schema, and never performs discovery; API owners may attach it to an existing response, but summary failure cannot fail the owning config/catalog/mutation. Native MCP `ImageContent` stays out-of-band on a string-compatible result carrier until the task adapter decodes it under per-image, count, and aggregate byte ceilings. The owner-scoped media authority persists each original; tool metadata and model context retain text only, while the authoritative Turn projects bounded attachment references for the existing browser image renderer.

`MCPBridge.call_tool_document` returns complete application JSON independently of display truncation. Documents are bounded to 256 KiB encoded, 8,192 nodes and depth 32; malformed/oversized structured data cannot fall back to success text. Exact legacy JSON uses the original text. Callers supply a 1..300-second SDK timeout (the thread-side cap adds 10 seconds) and may cancel through `is_set()`; timeout/cancellation cancels the SDK request, and ambiguous transport failures are not replayed. **Handshake deadline scope (2026-10-30).** Problem: the connect path passes the handshake budget (`MCP_CONNECT_TIMEOUT`) as the session-level `read_timeout_seconds`, and the MCP SDK applies that session value to every later request whose own `read_timeout_seconds` is `None`; every un-budgeted call (`budget=none`) therefore ended at 30 s, a 90 s 学城 CIBA login could never complete, and the resulting streak tripped the degraded breaker for the whole server. Decision: `initialize` and the bounded `tools/list` keep the handshake budget; `_release_handshake_read_deadline` clears the session-level deadline before the session is published, so only an explicit per-server `timeout` bounds a call. Alternatives rejected: a large per-call default is still a wait deadline (and a new knob); wrapping the SDK client's `__aenter__` in an outer `wait_for` can cancel mid-enter and leak its transport. Verify with `tests/mcp_protocol/test_mcp_handshake_deadline_scope.py` (real in-process SDK client; pins the SDK fallback premise) and `tests/project_mod/test_no_backend_timeouts.py`.

Display titles come from one composer, `lib/tasks_pkg/tool_display` `compose_mcp_display`: resource + container, plus up to two curated operation chips (`method`/`regex`/`field`/`node_id`/`dry_run`) so same-resource parallel calls (e.g. two `get_log_file` reads with different regexes) never share one row title. The live tool line and the persisted results-row title both use it; chips are whitelisted so tokens/payloads can never leak into a title. At settle, `handlers/mcp.py::_settle_mcp_round_display` refreshes the round with whatever the result taught it: `lib.mcp.project_names` harvests id→name/title pairs and resource URLs (a `read_doc` row swaps the bare contentId for the article title the moment the read lands), the label is re-composed with the same composer, and `_mcpLinks` is re-keyed to the fresh label so the hyperlink still wraps the exact rendered substring. Link hrefs come from `get_project_url`/`get_doc_url`, which prefer a verbatim harvested URL and otherwise synthesize from a learned-or-default base (`www.overleaf.com`, `km.internal.example.com`). MCP error strings settle as an `error` verdict on the round (preserved by `_finalize_tool_round`'s verdict protection, rendered via the failed lane) — there is deliberately no `<server>` / `<server> (error)` badge chip, since the label already names server/tool and success/failure is the round status's job.

**Provider-safe MCP tool names (2026-11-01).** Problem: the namespaced name `mcp__{server}__{tool}` copied the raw MCP tool name. Kingsoft Docs names 574 of its 630 tools with dots (`sheet.get_range_data`), and Anthropic and OpenAI reject any function name outside `^[a-zA-Z0-9_-]{1,64}$`: one such definition 400s the whole request, and a model call using the dotted name is dropped as malformed at ingest. Decision: `lib/mcp/types.make_namespaced_name` projects the tool part into that contract (unsafe characters become `_`; a tool part too long for 64 characters is shortened with an 8-hex digest of the raw name), and `namespaced_tool_names` resolves projection collisions per server independently of listing order (an exact name keeps the plain form, every rewritten member gains its digest). The bridge index keeps the raw name for dispatch, per-tool disabling and search text; names already inside the contract are unchanged, and server ids are not projected. Alternatives rejected: a request-time alias map (every transport, history replay and receipt would need the reverse map) and dropping offending tools at wire preflight (Kingsoft would silently lose 91% of its catalog). Verify with `tests/mcp_protocol/test_mcp_provider_safe_tool_names.py`.

**Host-reviewed MCP reads (2026-11-01).** Problem: Kingsoft Docs annotates every one of its tools `readOnlyHint:false, destructiveHint:true`, pure reads included, so under the conservative default each read needs write approval in Manual mode, disappears in Plan Mode and is never replayed after a disconnect. Decision: a curated catalog entry may carry `read_only_tools`, raw tool names a reviewer verified as pure reads against the live catalog (dated in the entry). `lib.mcp.registry.reviewed_read_only_tools` applies them only when the configured server's URL and transport equal the entry's endpoint, and the bridge ORs them into `read_only_hint`; it never demotes a tool, and the server's own annotations stay recorded unchanged. A changed review rebuilds the index even for a byte-identical catalog, and reviewed names missing from the live catalog are logged as vendor drift. Alternatives rejected: name or `destructiveHint` heuristics (a `get_` prefix proves nothing), a user-editable override in `mcp_servers.json` (any custom configuration could grant itself read authority), and waiting for the vendor to fix its annotations. Verify with `tests/mcp_protocol/test_mcp_online_docs_catalog.py`.

**Connector setup guidance (2026-11-01).** Problem: a user who asks about Tencent Docs (腾讯文档) or Kingsoft Docs (金山文档), or pastes one of their links, had no route to the installable connector. An anonymous fetch of `docs.qq.com/sheet/…` returns a JavaScript shell (four visible characters) and `kdocs.cn/l/…` redirects to a login page, and a Tool Search for the product returned an empty page, so the model could only report "cannot read". Decision: catalog entries declare `aliases` (distinctive product names) and `document_url_prefixes`, and `lib/mcp/connector_guidance.py` projects the entry's token route (`obtain_url`, `obtain_steps`) plus the owner's MCP configuration (not installed / disabled / installed) into read-only evidence. Generic words never match, an unknown owner or unreadable configuration produces no claim, and no bridge is started. In Settings, the same `obtain_url`/`obtain_steps` render as the install modal's token link, and featured self-serve entries appear in the empty-state suggestions. A catalog install whose connect fails appends the entry's token page to the error: the MCP SDK reports Tencent's HTTP 401 at initialize as a generic JSON-RPC `-32603`, so a rejected token cannot be told apart from other server errors. Alternatives rejected: an intent detector over user messages (measured at 60% false positives, see `_mcpSelfServeSuggestions` in `frontend/src/runtime/sections/settings/mcp.js`), always-on prompt text listing uninstalled connectors (tokens on every request for every user), and falling through to the anonymous or browser-rendered fetch (canvas-rendered sheets yield no cells, and the user never learns about the connector). Verify with `tests/mcp_protocol/test_mcp_connector_guidance.py`.

Remote content is untrusted tool output. Resource links, text, images, audio, `structuredContent`/annotations preserve declared types and size bounds; the partition keys off `readOnlyHint`, plus the host-reviewed catalog reads above.

**Child launcher PATH and Node ABI.** Problem: `~/.local/bin/node` can exist, satisfy `shutil.which`, and still be unrunnable — official builds need glibc >= 2.28 while this class of host runs 2.17, so every `npx`-launched stdio server printed `GLIBCXX_3.4.21 not found` and died in the initialize handshake (2026-10-21: `github`, `12306-train` failed every boot; 26s of retry each). Existence is not runnability, and a bare-name spawn cannot express the difference. Decision: `apply_tool_paths` prepends `<repo>/.tofu/node-toolchain/bin` (a musl Node 20 the project verified against this host) ahead of the home directories, and `lib/tools/process_environment.node_executable()` is the single resolver for callers that spawn Node by name (product `node --check`, the frontend test bundler). The tier is discovered, not assumed: an absent tree contributes no PATH entry, so exports and contributor checkouts behave as before. Alternatives rejected: pinning an absolute launcher in `mcp_servers.json` breaks every deployment without that tree; diagnosing the ABI at spawn time costs a subprocess per launch. Verify with `tests/tools/test_bundled_toolchain_path_precedence.py` and the `tests/mcp_protocol/` launcher contracts.

**Package-index negative cache is egress-scoped.** Problem: the disk-backed "index unreachable" marker is a fact about the EGRESS PATH, but it was keyed only by time — a marker written while no proxy was configured suppressed every vendored pre-warm for the rest of its six-hour window even after the pool started serving traffic (2026-10-21: marker at 10:46, product working by 13:52, pre-warm still skipped). Decision: `_prewarm_note_unreachable` stamps a credential-free egress fingerprint (scheme/host/port/user, never the secret) and `_prewarm_unreachable_reason` discards any marker whose stamp differs or is absent. ## Invariants
- One registry for names and schemas; one gateway for execution verdicts.
- Visibility is request-scoped and default-deny.
- Tool call IDs are batch-local correlation only; one history index repairs them to unique IDs independent of bounded diagnostic receipts, and historical pairing is adjacent and occurrence-safe.
- Content equality never proves duplicate execution; only a stable-slot transport retransmission can be suppressed before dispatch. Fresh observers execute again and may compact only their redundant model projection.
- Every call settles once on success, failure, timeout, cancellation, or abort.
- An accepted detached producer ends the root model loop; it never authorizes model-driven sleep/curl polling.
- Writes use explicit root authority, freshness checks, and atomic operations.
- Handler exceptions become typed tool failures, not successful text.
- Tool results are bounded before model context and logging.
- `compactionLayer='L0'` means content was actually withheld from the model (truncated V2 envelope, legacy placeholder spill, or hard clamp); lossless envelope re-serialization of a complete result is never stamped, so the COMPACTED pill cannot claim a placeholder for a result the model fully saw.
- Artifact references are owner-scoped, expiring, content-addressed, and never reveal a database or filesystem path.
- MCP/plugin/custom-tool adapters cannot bypass visibility or egress policy.
- Generated inventory derives from the live registry.
- Inventory descriptions are authored in `frontend/src/i18n/locales/{en,zh}.json`
  and delivered through the generated locale catalogs. Problem: checking only
  currently visible rows misses descriptions for inactive, data-backed tools.
  Decision: require nonempty translations for every declared built-in family
  and tool, plus dynamically emitted built-in rows; verify the shipped catalog
  through inventory rendering and translated search. Alternatives rejected:
  duplicating a static tool list drifts from the registry, while requiring
  translations for arbitrary external tools prevents useful escaped fallbacks.

## Catastrophic-delete guard structure

Problem (logs 2026-10-26, root conv mvl63xs9yz2nyl): the third-generation
delete guard (4cc2bb30d) split command strings with an ad-hoc scanner that
modelled only unquoted top-level quoting. Quoting inside `$(…)`, a nested
`$(` inside `$((…))`, heredoc bodies outside one admission shape, and an
apostrophe in a `git commit -F-` message all desynced it, and every parse
failure refused the command as "catastrophic delete" — an `echo` timing loop,
a backgrounded heredoc commit, and a `git diff -- . ':(exclude)…'` chain were
each blocked with a refusal naming a mid-word fragment that was never a
delete operand. Worse, the per-segment state fork made `( cd / && rm -rf
mnt )` — the exact shape of every background command — invisible to the
cd-tracking rule, and substitution bodies were never parsed at all.

Decision (2026-10-26): `command_structure.py` owns a bounded recursive
shell-structure parse; the guard judges the operands of every rm/rmdir/unlink
simple command a shell would run — in the command itself, each `( … )` group,
command/process substitution bodies, a stdin heredoc read by a shell
(`bash <<'EOF'`, `cat <<'EOF' | sh`) and a literal `sh -c` string — and treats
heredoc bodies, quoted strings, pathspec magic and arithmetic text as data.
Pipeline stages and `&`-backgrounded commands run in forked state (their
bindings and `cd` hops never reach the outer shell); an unparseable fragment
refuses only when it could name rm/rmdir/unlink; the cwd's checkout Git
metadata (`.git` marker, git dir, common dir — `workspace_lease` owns the
discovery) joins the home/workspace anchors. Wrapper dequoting (`nice`,
`stdbuf`, `\rm`, `r''m`) and the bash-only `$'…'`/`$"…'` operand forms follow
the shells' own readings.

Alternatives rejected: keeping the ad-hoc splitter and adding heredoc
blanking on top (the quoted-substitution and `$(( $(…) ))` desyncs stay);
refusing on every parse failure (the original false-positive rule); executing
corpus commands to classify mutations (no safe sandbox on this host — bwrap
and unshare are blocked — so `sh -n`/`bash -n` parse-only checks classify
them instead); refusing `rm -rf .git/objects`/`.git/refs` as metadata (the
anchor owns the entry; deeper paths keep the depth rule).

## Dangerous-command guard structure

Problem (2026-10-27 .. 2026-11-02, hit repeatedly by swarm workers): the
dangerous-command guard matched `DANGEROUS_PATTERNS` against the raw command
with quoted literals blanked. Data tripped it — a heredoc writing a scratch
Python script (`executor.shutdown(wait=True)`), `grep -c shutdown
logs/app.log`, `--graceful-shutdown`, a branch named
`fix/shutdown-peer-disconnect` — while `sh -c 'shutdown now'` passed, because
blanking the quoted literal also blanked the script the shell runs. Its
fork-bomb regex matched no input at all. The safety pre-hook kept a second
substring list that refused heredoc data and `chmod -R 777 /tmp/x` and knew
only the glued fork-bomb spelling, which bash and dash reject as a syntax
error.

Decision (2026-11-02): `command_analysis.dangerous_command_rule` judges the
program word and operands of every simple command the shared
`command_structure.py` parse says a shell may run — the command itself,
`( … )` groups, substitution bodies, a shell's `-c` string, a heredoc or
here-string a shell reads (directly or later in its pipeline) and `eval`
operands — after reserved words, assignment prefixes, `sudo`/`doas`, `env`,
`builtin`, the process wrappers (`command`, `exec`, `nice`, `nohup`,
`stdbuf`, `time`, `timeout`) and `xargs`. Program rules: `shutdown`,
`reboot` (with `systemctl reboot`), `mkfs`/`mkfs.*`, `diskpart`. Operand
rules on the parsed command: `init 0`, `dd` with an `of=/…` operand, a write
redirect to `/dev/sd*`, `format X:`, `rd`/`del` with `/s` and `/q`, a
recursive `chmod` of `/`, and a defined function piped into itself (fork
bomb). Quoted arguments, plain arguments, flags and heredoc bodies fed to
other programs are data. Text the parser cannot delimit, a wrapper whose
options are not understood (`env -S`, an unknown `timeout` option) and a
program name computed by a substitution (`$(which reboot)`) get the raw
`DANGEROUS_PATTERNS` match on the unmasked text, so unknown structure fails
closed only when a pattern is present. run_command, the desktop agent
and the run_command safety pre-hook call this one judge and keep their
refusal texts (`matches dangerous pattern`, `dangerous-pattern guard`,
`Blocked dangerous command pattern: <rule>`); the pre-hook runs first in the
tool pipeline, so model calls meet its refusal and recovery guidance for
every rule.

Runners (2026-11-02, second change). Problem: programs that execute an
operand were outside the wrapper list, so `setsid reboot`, `su -c reboot`,
`ssh host reboot`, `find / -exec reboot \;`, `docker exec c reboot` and
`bash -c $'reboot'` passed although the raw guard had refused them, and the
catastrophic-delete guard kept its own program view that missed
`FOO=1 rm -rf /`, `xargs rm -rf /`, `eval "rm -rf /"`, `command -p rm` and
every runner. Decision: `command_analysis._program_views` is the one
parsed-program view of both guards. Each runner's options follow its
documented getopt grammar (`_RUNNER_GRAMMARS`; permuting GNU programs accept
options after operands) and the runner contributes what it executes: argv
runs for `setsid`, `runuser -u`, `flock FILE CMD`, `chroot ROOT CMD`,
`unshare`, `nsenter`, `ionice`, `chrt [PRIO]`, `taskset MASK`,
`docker`/`podman` `[container] exec`, `kubectl … exec` (after `--`, or the
deprecated pod operand form), every `find -exec`/`-execdir`/`-ok`/`-okdir`
up to `;` or `{} +`, and BSD `script FILE CMD`; shell text, judged as
`sh -c TEXT`, for `su`/`runuser`/`script` `-c`, `flock FILE -c`, `watch`
(its words joined, unless `-x`) and an `ssh` remote command (OpenSSH parses

`chrt` and `ionice` pointed at existing processes (`-p`, `-P`, `-u`, `-m`)

words are decoded as bash decodes them. A runner whose options are outside

(`timeout $T rm -rf /`). The delete guard judges `eval` operands in the same
shell state, then keeps its binding reset; its depth, anchor and containment
rules are unchanged. The list is defined by what each program's manual says
it executes, not by observed usage.

Privilege wrappers (2026-11-02, third change). Problem: the sudo/doas unwrap

### Invocation phase ownership

**Problem:** the tool pipeline mixed admission, cached delivery, worker
collection and ordered replay in one thousand-line function, making lifecycle
and authority ordering hard to review. **Decision:** `_pipeline` remains the
shared admission/settlement/replay coordinator. `_reuse` owns freshness-checked
cache delivery; `_execution` owns admitted worker execution and collection.
Its immutable batch carrier borrows the existing invocation dictionaries and
explicit ports retain the executor, heartbeat, collector and settlement seams
used by ordinary and native callers. No parallel task state or dispatcher is
introduced. **Alternatives rejected:** copying flows per caller would drift;
moving imports blindly would bypass existing fault-injection boundaries.

A pre-submit cache-generation failure becomes an error Future for the original
occurrence, preserving its exception and preventing handler entry. This keeps
one result/error path even when failure precedes executor submission. Verify
`test_tool_result_collection`, `test_tool_parallel_deadlines`, outcome finality,
write approval/freshness, and tool settlement across all lanes.

Pool ownership begins at acquisition, before heartbeat setup and the first call starts.
Every exit shuts down the acquired pool; unexpected dispatch failure cancels
and joins this invocation's accepted siblings before propagating the original
exception, without cancelling another invocation sharing the task. Normal
collection expiry retains its finite wait policy, while explicit Stop joins
resource owners. Collector-gap harvesting follows shutdown so completed
receipts remain available. Protecting only the collection loop misses earlier
failures; verify both startup and effect-call faults in `test_tool_worker_cleanup`.

Identity admission consults argument signatures only when a call ID collides
with historical IDs. Fresh IDs and same-response duplicates retain the normal
claim/remint path; canonical signatures are still published by settlement.
Serializing every fresh argument here duplicated later receipt work. The
retained `benchmarks/tool_call_identity_compare.py` compares frozen source,
complete mutated carriers and diagnostics before alternating CPU/wall samples.
Its synthetic 32-call large-argument case measured admission CPU at 16.01 ms
before and 0.017 ms after; historical-collision work stayed at roughly 0.12 ms
per eight calls. This is an identity-admission measurement, not tool execution
or end-to-end task speed. No new signature cache or stale-argument assumption
is introduced. Verify positional recycling and history/cache mutation specs.

## Tofu-side time around tool calls

`debug/tool_overhead_audit.py` measures, per tool type and from one task's
committed events, the intervals a faster tool cannot remove: stream end to the
`tool_exec` phase (`dispatch`), to effect intent (`entry`), effect intent to
the command's first exec (`spawn`), `tEnd` to `tool_complete` (`settle`),
`round_end` (`close`) and the next model request (`next`).
`benchmarks/tool_dispatch_overhead.py` drives the real pipeline per tool on a
managed-lane task against a disposable SQLite sidecar and reports pre/handler/
post clocks plus synchronous non-event storage operations per call.

Problem: a production root task with 91 `run_command` calls measured p50
dispatch 997 ms, entry 62 ms, spawn 566 ms, settle 46 ms, close 621 ms and
next 902 ms against a 3.3 s median span; Tofu overhead was comparable to the
commands' own work. Decision: remove the fixed costs owned
here and measure the rest. Spilled-result alias claims became version-guarded
single writes (see `docs/STORAGE.md`, "Alias claim cost"; 9 → 4 storage operations
per spilled `search_files`). Both per-command `timeout` probes share
`grep_redirect.resolve_timeout_binary`, cached per server `PATH` value and
revalidated with one `os.access` (2.1 ms → 2 µs per probe on this host's
24-entry PATH). Alternatives rejected: caching coordinator role lookups or the
skills environment overlay changes their freshness/authorization semantics.

Concurrency: every call of one turn, writes and `run_command` included,
enters its handler together through the real dispatch path
(`test_parallel_dispatch_overlap`; owner decision 2026-10-28 in
`docs/contracts/TOOL_EXECUTION_POLICY.md`); streaming prefetch starts each
read when its call completes (`test_streaming_and_prefetch`).
Not owned here and measured as the dominant remainder: the `tools_in_flight`
and `ready` `checkpoint_invocation` barriers (`model_in_flight` no longer
waits for pending frames; `docs/TASK_EVENT_DELIVERY.md`) and each
attempt-scoped `TOOL_EFFECT` wait for the task's FIFO to commit one
structural frame per storage transaction (logged slow barriers average
1.8–2.2 s with 2–9 pending frames). Both storage authorities
batch only `delta`/`program_output`/`tool_progress` frames; group-committing
consecutive structural frames is the storage and event-delivery owners'
change. Per-call coordinator `record.get`, skills overlay scans, foreground
command records and write-tool fsync chains are the next in-process costs.
