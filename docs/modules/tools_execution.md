# Tools and execution
This domain defines tool visibility, model schemas, validation/dispatch, and result projection; MCP/plugin setup lives in [`../TOOL_PLUGINS.md`](../contracts/TOOL_PLUGINS.md) and [`../TOOL_SEARCH_EXECUTION_GATEWAY.md`](../contracts/TOOL_SEARCH_EXECUTION_GATEWAY.md). The always-on `inspect_image` schema stays within 350 tokens while retaining original-source rendering, upload/path routing, single-region cost guidance, grid, mixed-unit, and read-only semantics. Its coordinates use the visible frame after EXIF orientation and explicit clockwise `rotate`; explicit `crop` wins, while centre `zoom` runs only without a crop. `sourceSize` is EXIF-normalized, `encodedSourceSize` is the stored pixel matrix, `cropBox` is post-rotate, and the browser applies no further crop.

## Execution flow
1. The task policy resolves an explicit visibility allow-list.
2. The registry builds schemas for only those tools and rejects name collisions.
3. The model returns an ordered list of call occurrences with opaque, provider-batch-local IDs and JSON arguments.
4. The gateway validates the name, visibility, arguments, and capability.
5. A focused handler executes with the authenticated request environment.
6. The gateway normalizes success/failure and timestamps.
7. Settlement emits the canonical tool result and adds exactly one matching model-context result.

Tool schemas describe capability; handlers implement it. Bare relative project paths remain under primary regardless of file existence; explicit rootname paths select another root. Declared server-local MCP file admission lives in `lib/tasks_pkg/handlers/_mcp_local_paths.py` and follows [execution policy](../contracts/TOOL_EXECUTION_POLICY.md#local-mcp-file-paths); verify with `tests/tasks_pkg/test_mcp_local_paths.py`. Native write receipts retain the resolved absolute file path and root identity. `ask_human` normalizes batch questions before presentation. If fewer than two valid questions remain, it consumes the batch selector and delegates once to single-question handling (or its missing-question error), without rewriting the original tool arguments. The advertised project tool-name set is not an execution-owner set: background command check/kill remain owned by their command handlers and must not be reclaimed by the generic project dispatcher. Normal registry assembly is covered by executable dispatch tests. Schemas stay free of task runtime/HTTP; search activates on first valid use. Once resident, its explicit-domain enum remains capability-derived, while prompt prose keeps only each domain's 96-character bounded purpose and any partial-availability warning; identifier rules and examples have one static owner, and the fully loaded `web_search` schema stays within 1,000 tokens. Runtime-built `fetch_url` retains remote/local routing, authenticated-browser server staging, final-destination verification, batch behavior, and optional whole-page relevance semantics within 400 tokens when the filter is on and 300 when off. The optional relevance gate skips pages below 6,000 characters, selects at most 6,000 query-focused characters, and emits a 32-token verdict. Its irrelevant sentinel is not a wire stop; one upstream 429 ends fail-open review, and rewrite remains opt-in. The server-wide `update_search_settings` schema stays within 550 tokens while retaining pure-read-first, profile, override, trade-off, clamp, global-write, and result-honesty semantics; approval metadata enumerates both profile/override and legacy knobs so a global mutation cannot masquerade as a read.

Decision—direct `fetch_url` bypasses excerpt cache (`max_chars=0`); web search retains bounded previews. Rewrite retains original source. `extract` is one `capability='text'` model pass (not cheap-pinned or necessarily the conversation model), selecting up to 48k relevant windows and warning when non-exhaustive; pre-execution yields to the serial handler for extract/rewrite. Tool availability is per request. Installed does not mean visible. Multi-user deployments default to an explicit allow-list; a dedicated operator may expose more tools through declared configuration. Plugins, MCP servers, request-level custom tools, and built-ins all cross the same name/visibility gate.

Project read freshness comes from host-owned, descriptor-pinned per-item observations of the source bytes, not a filesystem reread after rendering. Tokens bind full-source SHA-256 and semantic-root identity even for ranged reads. Failed, unsupported, out-of-bounds or undisplayed reads cannot mint evidence. Modern serial read rounds retain observed-path receipts; streaming reads forward snapshot evidence through the common token owner. Ambiguous historical multi-read text cannot satisfy read-first by counting `File:` headers inside untrusted content; it requires a fresh read. Single successful legacy reads remain compatible. When snapshot recording is explicitly disabled, streaming multi-read text alone is insufficient; use an observed serial read or a successful single read. This changes read/freshness evidence, not filesystem authorization.

Plan Mode is a stricter request policy layered over this boundary. Initial wire exposure and the Tool Search catalog remove mutating or unproven schemas; the final dispatch check independently requires the exact call to be proven read-only. Unknown and caller-defined tools fail closed, MCP tools require an explicit `readOnlyHint: true`, and mixed desktop tools expose and accept only their read branches. This also applies to caller-supplied `tools=[...]`; unknown schemas are removed and the framework-owned canonical `ask_human` schema is present so within-turn clarification cannot be disabled accidentally. The policy owner is `lib/tasks_pkg/plan_mode.py`. Long-running tools normally keep one-call/one-result model semantics: `ToolExecutionContext` scopes sequenced/coalesced UI progress, bounded reconnect state, task-abort fanout and TERM→grace→KILL→reap; overflow spools outside the project under a shared task budget, persists as an opaque owner-scoped expiring artifact, and returns bounded head/tail (partial on cancel/timeout/interrupt), while startup reclaims abandoned spools. Local `run_command` registers its PID/PGID before any spawn callback, then uses a 350 ms live-start grace: a command that settles inside the window emits only its authoritative terminal result, while a command that outlives it (or produces at least 4 KiB early) asynchronously publishes the spawn clock, opens live output, and checkpoints the running round for reconnect recovery. When an attended conversation receives a durable `user-steer` while a real subprocess is running, the handler closes the outstanding tool-call/result pair with one provisional background receipt and immediately releases the model loop to consume the steer. The worker owned stdout/stderr from process start, so handoff cannot strand a pipe; it stops foreground progress, preserves timeout/whole-task Stop, cwd/index/file-diff finalization, and queues the bounded authoritative result as a passive durable completion receipt. A live turn can consume it at the next model boundary; an idle conversation waits until all known background commands have published, then starts one collective completion turn, including after restart. Explicit stdin waits remain foreground-owned. Procfs stdin detection is an optional stateless sensor: blocking syscall reads run outside the command-control loop, at most one sensor per command and a process-wide capacity derived from the cached `TOFU_AGENT_WORKERS` envelope, with no queue or eager workers. A closed command fences late samples before releasing its descriptors; blocked sensors retain their physical slots until return and hold no task state or delivery callback. Stop, explicit command deadlines, interrupt and output draining continue while sensing is unavailable. Problem: procfs syscall reads can stall command control. Decision: keep sensing outside that loop with physically bounded ownership. Alternatives rejected: disabling input or abandoning an unbounded set of task-owning readers. Lazy initialization starts zero threads; a capacity-one fault check retains one blocked worker, refuses eight additional sensors and returns to zero only after release. Interactive prompts render bounded stdout/stderr buffers through their canonical render ports. SubAgent tool proxies (swarm workers and FlowExecutor leaf workers) bridge the cooperative control fields across their isolation membrane: a live `run_command` subprocess pid/pgid is mirrored proxy→parent so the stuck-task reaper arms the gentle `_cmd_interrupt` watchdog instead of force-failing the whole parent (an autopilot run), and a planted interrupt is transferred parent→proxy only while the stamped pid matches, reaching the command's read loop; the parent copy is retracted once the read loop consumes it, and a consumed flag is never re-transferred.

## Invariants
- One registry for names and schemas; one gateway for execution verdicts.
- Visibility is request-scoped and default-deny.
- Tool call IDs are batch-local correlation only; one history index repairs them to unique IDs independent of bounded diagnostic receipts, and historical pairing is adjacent and occurrence-safe.
- Content equality never proves duplicate execution; only a stable-slot transport retransmission can be suppressed before dispatch. Fresh observers execute again and may compact only their redundant model projection.
- Every call settles once on success, failure, timeout, cancellation, or abort.
- An accepted detached producer ends the root model loop; it never authorizes model-driven sleep/curl polling.
- Writes use explicit root authority, freshness checks, and atomic operations.
- Handler exceptions become typed tool failures, not successful text.
- Tool results are bounded before model context and logging.

- MCP/plugin/custom-tool adapters cannot bypass visibility or egress policy.
- Generated inventory derives from the live registry.

  and delivered through the generated locale catalogs. Problem: checking only
  currently visible rows misses descriptions for inactive, data-backed tools.
