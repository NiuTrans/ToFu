# Project coordination communication

Responsibility: explicit coordinator binding, passive same-project messages,
consideration receipts and their optional model-input boundaries. This describes
the source contract in this checkout, not deployment status: an isolated tested
candidate does not prove canonical integration or live backend loading.

## Owners and contracts

| Concern | Sole owner / authority |
|---|---|
| Coordinator metadata | `lib/conversations/project_coordination.py`; `contracts/project_coordination_v1.schema.json` |
| Passive originals and consideration | `lib/conversations/project_messages.py`; `contracts/project_messages_v1.json` |
| Child-run messages | [RETAINED_AGENTS.md](RETAINED_AGENTS.md); `contracts/swarm_messages_v1.json` |
| Optional input budget / witness | `lib/tasks_pkg/message_input_{budget,receipts}.py` |

| Demand-only drawer | `frontend/src/features/project-{coordination,message-receipts}.ts` |

The strict message DTO and enums are generated by
`scripts/gen_project_coordination_contract.py`. Binding starts no execution.
The existing conversation/turn/task and Git publication authorities remain
separate; neither the drawer nor ProjectWorkItem is an assignment executor.

## Passive project conversation messages

Problem: `_peerNoWake` guards only some legacy queue drains; restoring its sender
can trigger paid work and default synthetic input to human attribution.
Decision: portable record CAS stores passive originals and consideration without
a dispatchable queue source, resident worker, polling thread or automatic wake.
The existing natural root round acquires optional input after complete tool pairs.
Alternative rejected: heartbeat-only guards cannot protect startup/completion drains.

`reference/consult/report/question/assign/steer` classify context, not execution
grants. Explicit accepted/rejected/deferred/conflict decisions use message revision
CAS, independently of input confirmation. Accepted is a stated commitment, not
executor birth or delivery. Causal replies must identify an actual incoming
message from the addressed sender. Queries never read private transcripts.

Owned current metadata is checked before send/acquisition, at logical-call
admission, and at the canonical prepared-input physical-attempt boundary. This is not a persistent conversation
project-generation fence: returning to the original project can make retained
originals eligible again. Different-project mailboxes never inherit those records.
Restored witness carriers are validated even when fresh acquisition fails; child
bootstrap removes previous-run mailbox carriers from its copied checkpoint, not
from durable evidence. The exact same mailbox/run retains confirmed carrier
context during recovery, subject to live dispatch validation. Conversation-mode
children retain parent context text but strip its mailbox receipt authority.
Unknown/mismatched authority fails before dispatch; a new authorized turn remains
the execution owner.

## Input receipts and recovery limits

Exact carrier text is matched only in input-bearing fields. A request-local
observer composes with the existing model-budget attempt lease, and revalidates
scope against sealed translated input after dispatcher waits and before provider
ingress, including floor resends. This adds no second budget/dispatch owner.
Tool descriptions, routing and metadata cannot prove consumption. Only matches
from the selected verified response become eligible for ACK; failed/dropped input
cannot inherit previous IDs. Unobserved custom transports produce no physical
receipt. This does not independently prove serialized-wire identity after every
possible downstream adaptation. Credential recovery, when present, must wrap
per-attempt receipt validation, never the reverse. Local delivery failures retain
the original cause, not a provider fallback; the shared-runtime composition
specification executes only where those owners are present.

Validation is not atomic with the network send: a revocation immediately after
checking can race ingress. Relay/proxy-internal retries need their own enforcement
and are not claimed here. A scope-denied floor resend records already-known paid
usage as non-authoring discarded rounds; it cannot trigger another route or ACK.

Receipt ACK loss remains unknown: no persisted successful-request pending-ACK
outbox exists. No new paid request is purchased to reconcile a receipt. The exact
turn/attempt/task occurrence is recorded where available. Neither input confirmation,
consideration, task completion nor canonical delivery implies the other facts.

## Conversation execution identity boundary

Problem: carrying only a tenant and reconstructing every principal as a user can
silently turn a future system dispatch into an attended human executor.
Decision: `contracts/conversation_execution_identity_v1.json` defines a private,
server-stamped envelope in the existing accepted-attempt config. Public create,
resume and plan-execution config cannot supply identity, attendance or task
scopes. Authenticated subject/owner/tenant are retained; task scopes stay empty
rather than inheriting API scopes as durable tool grants. The executor validates
the envelope before context construction or registration, including recovery.
Present malformed, wrong-owner, wrong-tenant and nonhuman envelopes fail closed.
Alternative rejected: `_attended=False` alone is neither provenance nor a grant.

This is a safety prerequisite, **not automatic dispatch**. System principals are
rejected until project grant, revocation, scope/tool and cost admission exist.
Only absent legacy envelopes retain the existing explicit-owner user path;
explicit nonhuman/false-attendance markers cannot take that fallback. Existing
numeric-owner internal Goal continuations retain their existing semantics; this
boundary does not retroactively certify them as new project grants. No new loop,
thread or resident worker is added. Guard:
`tests/conversation/test_execution_identity.py`.

## Bounds and cost

One original owner/project/recipient mailbox holds at most 128 originals, each
4096 characters / 16384 UTF-8 bytes, plus a 2048-character consideration note.
Worst-case body content is 2 MiB before JSON/framing and notes. This is a lifetime
history cap, not unread backlog. Overflow rejects without eviction, even after
consideration; no archive/rollover command exists. Pagination does not reclaim
capacity. Durable segmented history is needed for unbounded ongoing responsibility.

Each active configured project round performs scoped metadata and a point read,
not an owner-wide scan. A directory shows 20 previews of 256 characters with a
stable-ID backward cursor; exact-ID tool lookup retrieves the original. Input
selection defers whole messages using token/headroom and escaped-byte budgets.
Final canonical prompt admission still owns total cost. Idle adds no executor.

## Public surface and verification

The public `/api/v4/project/coordination` GET, `/bind` POST and `/messages` GET
use the conversations scope. Binding requires `expectedRevision` and an
`Idempotency-Key`; receipt projection is read-only and strictly schema-bounded.
The drawer reads on disclosure, fences late project/conversation results and
separates input/decision/delivery. Prototype data are explicitly demonstrations;
Chromium rendering is not proof that the production service loaded a candidate.

Guards: `tests/project_mod/test_project_messages*.py`,
`tests/api/test_api_v1_project_coordination.py`,
`tests/swarm/test_run_messages*.py`, and
`tests/tasks_pkg/test_message_input_{receipts,budget}.py` plus
`test_child_message_checkpoint_fence.py`, `test_message_input_physical_attempts.py`
and `test_message_runtime_composition.py`. The repository uses existing record CAS;
real disposable SQLite Sidecar tests do not independently prove native/Postgres
parity. Automatic paid assignment/wake and full P2/P3/P4 remain pending in
[the implementation specification](../designs/project-coordination/README.md).
