# Automation contract

Responsibility: rule admission, trigger evidence, durable runs and fenced steps;
entry points are `lib/automations/`.
Authorities: [automation v1](../contracts/automation_v1.schema.json),
[action I/O](../contracts/automation_actions_v1.json), [execution owners](modules/scheduling_ops.md).

## Definition admission

`prepare_definition` validates the schema, closed action registrations,
dependency order, evidence references, IANA timezone, cron bounds, and budgets.
Conditions are bounded JSON comparisons, conjunctions, disjunctions, or negation;
they never evaluate code. A reference uses `$source` with an event/preceding-step
source and an RFC 6901 pointer. Resolved arguments are validated again against
the original action schema before an effect is dispatched.

`ActionRegistry` is immutable. Each action names its exact version, input/output
schemas, required scopes, effect classification, and recovery policy. Remote
schema resolution is forbidden. Installing a skill cannot register a callable
action or grant a capability. Write/Agent actions must reconcile unknown effects;
only declared read/presentation actions are replayable.

Browser types and action I/O maps are generated by
`scripts/gen_automation_contract.py`; `--check` verifies parity.

## Calendar slots

The schema's `x-schedule` policy and `lib/scheduler/calendar.py` own automation
slot lookup. An immutable `CronSchedule` uses the existing five-field parser and
its day-of-month/weekday AND semantics. Impossible month/day combinations fail
admission; leap days can resolve beyond a year. Queries take explicit aware
clocks and return exact UTC instants. Local minutes in a timezone gap are skipped;
both instants in a repeated minute remain distinct, including half-hour and
historical date-line changes. Historical second offsets retain exact UTC identity.

`next_after` is lower-exclusive; `latest_between` is (after, through]. Catch-up
`latest` selects one latest slot without replaying downtime; `skip` admits only
a slot in the current UTC minute, allowing ordinary polling latency within it.
A slot identity uses its UTC timestamp rather than an ambiguous local label.
Queries jump selected months/days within one Gregorian calendar cycle; finite
datetime exhaustion returns an explicit missing slot. The calendar starts no
worker or timer. Atomic publication owns subscription indexes and canonical clock
jobs; production producer/worker composition remains required before enablement.

## Durable identities and ownership

`AutomationRepository` carries an explicit `PrincipalContext`. Logical record
keys isolate both owner and tenant on every supported authority; the repository
does not select a backend, construct SQL, or access database files. Management,
reads, and execution have separate scopes.

Definitions use revision CAS. Retirement preserves the definition, disables new
automatic triggers, and retains history. A logical occurrence identity is the hash of
rule identity, event kind, and producer event identity: revision is deliberately
excluded. Concurrent/redelivered events resolve to one durable aggregate;
conflicting evidence under the same producer identity is rejected.

The occurrence freezes the definition, action contracts, dependency order,
trigger evidence, causal chain, deadline, and stable per-step effect identities.
Editing or retiring the rule cannot replace that snapshot. `admit` returns
the durable occurrence, not a speculative `created` flag; dispatch must always
deduplicate through its stable effect identity.

Draft definitions and cursors use generic CAS. Published definitions have a
separate atomic owner. Lost acknowledgements require exact revision/digest
readback; an unavailable or different record never implies success.

## Atomic execution admission

`AutomationExecutionRepository.publish` narrows the authenticated publisher's
scopes into a definition-bound execution grant; it never carries `admin` into
a worker. Each required action scope must be held by the publisher. Publishing
an authorized rule is distinct from saving a non-executable definition draft.

[Automation storage operations](../contracts/automation_storage_v1.schema.json)
provide the same transaction contract in native TofuDB and the SQL Sidecar.
`automation.definition.update` publishes, pauses or retires a scoped revision,
replaces its event subscription and deletes the prior canonical clock job in one
transaction. An enabled schedule gets one future UTC slot in a revision-bound
`automation-clock` job; event indexes are scoped by owner, tenant, event, origin
and optional project. Job and subscription payloads bind the exact revision,
digest and grant. Draft writers share publication's definition lock and cannot
overwrite a promoted grant; generic writes refuse subscriptions/published rules.

Prepared source/action JSON proves the primary digest without assuming identical
float spelling across language encoders. The backend verifies identity, closed
action versions, dependency order and exact grant; rule interpretation stays at
`prepare_definition`. State changes may only disable the existing rule, retaining
its actions/history and updating its digest. Pause cannot resurrect retirement.
Pause/retire requires management authority without reacquiring action scopes.
The first publication request identity and digest stay in the current revision;
exact expected-revision replay returns the first timestamps and clock slot.
Changed evidence under that identity conflicts. Lost ACK recovery reads the
current revision once and never blindly republishes.

`automation.run.admit` guards the current definition revision, digest, enabled
state and exact grant, then inserts the frozen run, canonical worker job and
compact active/history pointers together. Definition edits racing admission
conflict. A new scheduled occurrence also proves its published clock job's live
lease/fence and zero cancellation sequence in the same transaction. Expired,
reclaimed or superseded producers cannot admit a new run. Re-delivery resolves
the existing occurrence even after retirement or producer expiry.

`automation.run.advance` checks the current job's owner, tenant, live lease and
fencing token inside the same transaction as progress CAS and index settlement.
Expiry alone revokes write authority; no competing worker needs to reclaim
first. Immutable snapshot/evidence/grant fields cannot change. Exact readback
of expected revision + 1 and identical progress acknowledges an earlier commit
without rewriting state or extending the old worker's authority. Both operations
use natural replay and avoid a permanent command receipt for every progress tick.
Recovery reads bounded compact active pointers, independent of terminal history.
Generic record put/delete refuse run and active/history namespaces; these
records have only the atomic execution mutation owner.

Sidecar progress holds the canonical worker row until transaction commit.
PostgreSQL claimers skip that locked row; SQLite already serializes its writer.
Thus takeover cannot occur between checking a fence and publishing progress.
Native OCC checks the same current-job dependency before committing.

Lease proof uses the storage authority's advancing UTC clock and current volatile
backend epoch. `now_ms` from a caller remains bounded observation/evidence; it
cannot prove a lease, extend it, or make a queued job due. The clock retains the
highest UTC offset while monotonic elapsed time continues through wall-clock
rollback. Read replicas and SQL sessions share their owning backend's clock and
native/SQLite event-read epoch. PostgreSQL uses a lazy server-shared random clock
epoch scoped by database OID, so separate Sidecars retain each other’s live claims.
Its optional server module and fail-closed admission are owned by
[storage operations](STORAGE_OPERATIONS.md).
Store restart invalidates previous-epoch and legacy empty
claims; indexed recovery adopts them through the same queue and increments their
fencing token. One clock snapshot carries separate advancing lease time and
current UTC. Queue availability uses UTC, so a lease high-water after a rollback
cannot claim a future calendar slot or spin a retry suspension. UTC is sampled
before monotonic elapsed time; probe scheduling pauses cannot inflate the offset. Migration preserves a source epoch exactly without granting target
execution authority. No production clock override exists.

Problem: a delayed timestamp could revive an expired holder before takeover, and
clock rollback could retain a crashed holder's future deadline. Decision: engine
clock plus lifecycle epoch, with bounded existing-index recovery. Alternatives:
trusting caller time leaves the expired-write gap; adding a durable clock row,
lease scanner or recovery queue adds writes and another lifecycle. Native probes
at most four lease ranges per advertised kind, each limited to one pointer; SQL
uses three epoch ranges with kind filtering before each limit. The native lease
key adds 33 bytes (marker plus epoch); JSON epoch metadata exists only after a
claim. One clock is shared per backend; no new resident worker or waiting thread.
Verification: worker lease authority public/SQL contracts, native worker and
migration unit tests, then automatic event/suspension/producer recovery neighbors.

## Canonical clock dispatch

`AutomationClockHandler` consumes the schema-owned `tofu.automation-clock/v1`
payload through the existing synchronous worker. Explicit application composition
injects storage and clock; importing the module registers no kind or pool.
Current definition/revision/digest/grant and the published job ID must match.
Replacement/retirement removes that transport without cancelling accepted runs.

The durable queue cursor stores the last consumed observation in UTC milliseconds;
zero starts at the original publication clock. Each claim selects one latest
eligible slot, or only the current UTC minute for `skip`. Trigger identity is
`utc:<slot milliseconds>` and its evidence is the exact scheduled UTC instant.
A restart after admission but before suspension reuses the accepted occurrence's
frozen envelope, including its original project. No retry clock enters that
trigger digest. Admission reads a fresh execution clock to prove the current
lease rather than reusing the earlier calendar observation. Backwards wall-clock
movement never rewinds the cursor or creates an already consumed occurrence.

A proved admission returns durable suspension at the next exact UTC slot, with
no retained heartbeat thread. A transient storage failure keeps the cursor and
retries after the contract-owned delay; an unconfirmed initial claim remains
recoverable through lease expiry. Rule replacement racing admission or suspension
revokes the old job; its worker observes lost authority and stops. Clock retirement
needs no external effect cleanup: its only effect is the atomic admission of
separately owned run jobs under the same definition lock or native OCC dependency.

The handler's explicit registration proves its own storage/cancellation contract;
production composition remains disabled pending operational run adapters. It does not implement another queue,
model loop, scheduler scan or background timer.

## Actual task-start events

The physical worker captures its owned tenant, controlled initiation origin and
explicit causal lineage at task creation, before prompt hooks/config mutation.
`turn.attempt.start` freezes the service-owned `startedAt` at the first
pending-to-running transition. In that same transaction it probes at most four
owner/tenant event/scope/project subscription prefixes, each limited to one row.
An unsubscribed start creates no transport. A subscribed start enqueues one
`automation-event` job containing the first task/attempt/turn/conversation IDs,
actual timestamp, origin and lineage. Its principal is a narrowed system identity;
actual execution still requires each definition's approved action grant.

The natural producer identity hashes attempt and task IDs; its queue identity also
binds owner and tenant. An already-running replay preserves the first timestamp
and never creates or rewrites transport. Enqueue failure rolls back running state
and its status event. Generic queue producers cannot forge this reserved kind.
Malformed controlled initiators acquire no trigger authority. Transient tasks
retain their storage-free lifecycle; a separate declared producer is still needed
before exposing automations for tasks without durable attempts.

Task elapsed time adopts the durable start; reaper/dispatch heartbeats stay fresh.
`presentation.show_task_start_time` uses frozen starts, IANA zones (default UTC), and ISO offsets for folds.
Problem: saving formatter output alone leaves it invisible. Decision: fenced
`automation.run.advance` publishes an identity-only conversation/attempt index
with successful output; the immutable run remains its sole content authority.
The producer identity, owned canonical attempt, task/turn/conversation and exact
physical timestamp must agree. Replays add no reference; partial publication
rolls back; definition retirement preserves the accepted output. Generic record
writes cannot publish or change references, and published time steps are immutable.
Alternative rejected: injected transcript messages or a push-only content store.
Owned per-attempt pages hydrate at most eight references. Mounted turns cancel
reads on navigation and refresh on owned hints; browser clocks never alter output.
No model/thread/conversation is created. Project IDs require owned server selection, never paths/browser config.

`event_delivery.AutomationEventHandler` reads at most 64 indexed subscription
rows per claim and persists only a bounded prefix/key/count cursor in the existing
job payload. Missing legacy cursors mean the initial position. Frozen event and
principal fields remain immutable, as does the original enqueue request digest.
After checkpointing, the canonical worker suspends the same job and joins its
heartbeat; no companion cursor records, retry receipts, timers or waiting threads
are created. Background event priority is 200; lower numeric priorities win, so
ordinary priority-100 work runs first.

A target must still have the subscribed revision/digest, be enabled, carry its
approved owned grant, and have been published by the event timestamp. A causal
ancestor cannot trigger itself. Canonical task-start admission atomically proves
the event job's live owner/tenant/worker/token and exact frozen event. Accepted
occurrence replay is observational after producer expiry or retirement. Unaccepted
subscriptions edited during delivery are skipped; new publication never applies
retroactively to an old event. Management API composition must expose manual
admission only; noncanonical trusted internal fixtures are not public producers.

`automation.event.settle` validates the frozen source, monotonic bounded cursor,
and live fence in one native OCC or SQL transaction. Exact applied checkpoints
replay observationally. Success requires all scoped prefixes to be consumed;
cancellation requires persisted owner intent. The worker's optional registered
completion port runs after monitor teardown and uses this operation to remove
pure event transport plus claim/idempotency indexes. Accepted runs remain under
their separate lifecycle. Permanent failure first writes one bounded owned
`automation.event-failures.v1` diagnostic in the same transaction. These diagnostics
are durable user evidence and generic record mutations cannot overwrite them.
Lost terminal acknowledgements and actual authority restarts preserve accepted
runs and allow remaining transport to recover. An isolated native four-rule event
measured a 766-byte frozen payload and claim times of 154.34, 57.01 and 23.76 ms
(including admission, suspension and retirement), with zero added idle threads
or model calls and no retained successful event transport. This is local logical
latency, not physical allocation or steady-state throughput. This registration remains explicit
and disabled in production until operational actions are integrated. Tofu-DB source-matched native recovery is the primary acceptance
path; SQL tests enforce the same storage contract.

## Ordinary task-start validation cost

Problem: ordinary task-start admission imported the optional full schema engine
inside its storage transaction. Decision: `contract.py` evaluates a closed small
vocabulary directly from `taskStartedContext`; unfamiliar semantics fall back to
the full validator. Canonical bounds, owner checks and failure behavior remain.
Alternatives: eager loading taxes startup; copied limits create another authority;
a validator-only Rust port leaves the measured transport waits unresolved.
The process caches one schema/support tuple, adds no workers or durable growth.
Full-schema differential tests and SQLite/native automation neighbors pass.
The 2026-10-13 HTTP cohort improves warm median time, but cold p99 is 2.072 times
Python; separate unique-VM RSS/PSS improve. This fails default admission.
Raw observations, source digests and scope limits are in
`system_native_start_context_fastpath_20261013.json`.

## Step lifecycle

Pure transitions accept a claim fence proved by the canonical durable worker.
They do not implement another claim queue, lease timer, model loop, or clock.
Fenced documents are then committed through repository CAS. A reclaimed job
cannot regress its token or let the former worker settle a step.

`prepare_step` records arguments and effect identity before invocation. A false
guard skips its branch; skipped dependencies propagate to their descendants.
This is a bounded guarded sequence, not a replacement graph engine: complex
branch joins, subflows, or convergence remain orchestration responsibilities.

Agent dispatch is `waiting_agent`, never success. Required verification failure
retains its evidence and fails the run. Missing comparison evidence is an error,
not `false`; an explicit `exists` predicate is the exception. Safe read retry
attempts are bounded by policy. An interrupted write remains
`reconciliation_required` until an adapter supplies authoritative evidence.

`automation.run.cancel` requires `automations:manage` on an explicitly bound
owner/tenant repository. One transaction records the first cancellation command,
cancels or wakes the canonical worker job, and updates run/history/active indexes.
The command retains its bounded ID, reason and timestamp. Repeating its ID with
a different reason conflicts; later commands preserve the first evidence. A
terminal run is an observational no-op, leaving a worker still completing alone.
Lost acknowledgements require authoritative run/job readback; there is no blind
replay or separate permanent cancellation receipt.

Cancellation is immediate when no external effect has been dispatched. A running
worker retains its lease until it accounts for settlement; a suspended worker is
woken without terminal accounting. An active/unknown effect enters `cancelling`;
only authoritative settlement makes cancellation terminal. Claim takeover keeps
that cancellation state and reconciles interrupted effects without redispatch.
Action failures retain their evidence even when the final outcome is cancelled.
Deadline expiry prevents further dispatch and cannot relabel an owner command.
Self-causal triggers and excessive lineage are rejected before occurrence creation.

The canonical [worker lifecycle](../contracts/worker_job_lifecycle_v1.json)
supports durable suspension for Agent, permission and reconciliation waits.
It releases the lease and every executor/heartbeat thread rather than keeping
one thread per waiting automation. Cancellation wakes the same job for domain
cleanup; a registered cleanup handler must prove external settlement before
worker terminal accounting. Production registration remains explicit.

`AutomationExecutionHandler` now supplies an explicitly composed `automation-run`
registration. `ExecutionRegistry` binds exact frozen action contracts to installed
ports; unknown/mismatched ports fail before invocation. Each step's arguments and
stable effect key commit through the live run/job fence before dispatch. Terminal
run state commits before worker accounting; a lost terminal acknowledgement can
recover without invoking a settled action again. Pure replay actions reuse the
original effect key after takeover. External actions require a reconciliation
port; an unknown result suspends rather than redispatching. Cancellation remains
`cancelling` until the external result is settled, with the original error kept.
Agent queued/running results release the worker into durable waiting.

Problem: approval can arrive between a permission wait and worker deferral.
Decision: `automation.run.approve` proves owner/tenant, current action scopes,
expected revision and exact request, then atomically commits reviewed argument/
action digests plus the canonical wake. Frozen principal/effect key stay intact;
no lease is granted. Cancelled/expired waits fail. Lost ACK/terminal replay proves
the same command. Worker progress keeps frozen step IDs, approval and external intent.
Claims capture wakeSequence once; heartbeat never acknowledges it. Older deferral
retains the wake floor; progress CAS conflicts suspend for immediate takeover.
Alternatives rejected: another queue duplicates authority; availability alone
loses wakes; resetting intent or replaying unknown writes duplicates effects.

The supplied presentation port persists `task.show_time` output using frozen
actual-start evidence. Worker/all roles install clock, event and run handlers
through `lib/automations/runtime.py`; import performs no I/O. The runtime contract
uses launch-probed task capacity, lazy executor growth and one idle queue poll.
Shutdown revokes dispatch, awaits effects/heartbeats, then defers the owned claim
before storage closes. Native/SQLite/PostgreSQL tests prove immediate recovery
and unknown-write reconciliation. Owned time publication is installed; skills/Agent/Flow ports remain unfinished.

## Authenticated management

`routes/api_v1/automations.py` is projected into `/api/v4/automations` by the
shared release boundary. The [management schema](../contracts/automation_management_v1.schema.json)
owns public requests/DTOs; generated browser types and `api/automations.ts`
consume it. Closed credentials admit management and catalogue action scopes;
read/manage/execute are checked before application work.
Publish/pause/retire use revisions/request IDs; manual admission owns human
origin/time, freezes the revision and recovers the first event on concurrent retry.
History hydrates at most eight runs through a definition-scoped descending index.
Responses omit private grants, principals, fences and worker IDs.
Project rules use the installed owned-binding resolver; missing/retired bindings
are 404. An explicitly unavailable injected resolver remains 503.
This API creates no pool/timer. Settings UI remains separate work;
`test_management*` and `test_api_v1_automations.py` verify native-primary boundaries.

## Bounds and verification

Schema-owned limits bound definition bytes, record bytes, JSON depth/nodes,
trigger ancestry, and page size. Large evidence is represented by existing
artifact references. Durable definitions/runs are user state and are not evicted
as caches. These primitives start no thread, timer, subprocess, or model call on
import; action descriptors alone are not an operational execution adapter.

Focused gates: `pytest -q tests/automations tests/scheduler/test_automation_calendar.py`, plus the native repository gate with
`TOFUDB_BIN` pointing at a matched artifact. The native gate checks concurrent
occurrence admission, stale CAS rejection, cancellation races, lost acknowledgements,
and exact state after authority reopen. SQL gates cover SQLite/PostgreSQL; differential gates compare cancellation and
replay with native TofuDB, including late cancellation after run success.

Project acceptance runs the native parameter of
`tests/automations/test_project_responsibility_worker.py`, the seven native
cases in `tests/automations/test_projects.py`, and both cases in
`tests/storage/test_native_project_dispatch.py`. Select the candidate through
process-only `TOFUDB_BIN`; require its actual `--build-info` source SHA to
match the tested application source. With concurrent writers, test a frozen
source/application snapshot and report checkout drift separately: snapshot
acceptance is not acceptance of a subsequently changed checkout or deployment.
A synthetic four-step run measured 6,741 definition and 7,699 run bytes in client
JSON, with one occurrence after four concurrent deliveries. These are logical
sizes, excluding physical disk usage; no resident concurrency is added. Atomic admission adds one canonical worker job and two small
index pointers per occurrence; progress replaces pointers and terminal settlement
removes the active pointer. Logical history is retained durable user state;
natural replay avoids a permanent receipt on every progress write.

Worker suspension and cancellation update the existing job/run; they add no
resident thread, appended polling job, or permanent retry receipt. SQLite samples
retained zero heartbeat threads; bounded cancellation metadata stays with history.

Five warm samples on this host measured calendar next/latest pairs at 24.353 ms
for minutely UTC, 27.293 ms for minutely Shanghai with 129 years of catch-up,
and 0.075 ms for a sparse leap-day/Monday plan spanning 2016 to 2044. Separate
warm queries traced at most 4,858 Python bytes, excluding the compiled plan,
imported modules and native timezone data. These are local synthetic query
measurements, not a throughput or process-memory guarantee. They add no resident
worker/thread or persistent record.

An isolated SQLite publication measured 1,841 event-definition bytes, a 252-byte
subscription value, 1,873 schedule-definition bytes, and 1,063 queued clock-job
bytes, in compact client JSON. First request metadata occupied 216 bytes. Resident thread count did not change. These logical sizes
exclude physical storage/index allocation. Publication replaces its subscription,
and schedules one canonical job per enabled revision; it adds no retry receipt.
Publication removes obsolete clock documents, availability/lease indexes and
idempotency references atomically. The latest failed clock retains only job ID,
revision, failure time and a contract-bounded kind in `lastClockFailure`; draft
metadata cannot forge this evidence. Durable definitions and run history remain.
Generic `worker_job.enqueue` rejects automation clock/run kinds: only their typed
publication/admission boundaries may create them.
An isolated SQLite sequence of eleven publications retained one live clock
document (1,159 compact JSON bytes in that fixture); pausing left zero. It added
no resident thread or GC job. These logical measurements exclude physical storage.

Five isolated SQLite clock cycles reused one job with an unchanged 492-byte
payload; its compact logical document was 1,063 bytes queued and 1,089 suspended.
Full claim/calendar/admission/defer cycles measured 29.47–53.99 ms on this host;
no heartbeat thread remained between cycles and five distinct UTC occurrences
were retained. These are local synthetic measurements, not throughput, physical
storage or steady-state memory guarantees. Waiting changes the existing queue
cursor/availability rather than appending a clock job or retry receipt.

Problem: fixed polling pools consume idle capacity and grow command receipts.
Decision: one receipt-free idle claim with demand-driven bounded execution.
Alternatives rejected: per-rule threads, a new queue, and abandoning live effects at shutdown.
## Decision

Problem: timing, readiness checks and Agent execution need one explainable record.
Decision: use one versioned data contract and closed action catalogue over existing
scheduler, worker, invocation and Turn authorities. Independent browser timers,
arbitrary hooks and a second Agent runtime lose durability or duplicate authority.

Calendar lookup compares UTC instants and jumps matching days; minute enumeration,
one-year horizons, wall-time identities and gap normalization lose scale or slots.
Publication commits definition/subscription/clock replacement together: separate
commands lose triggers, and generic drafts must never erase a grant.
Task-start transport commits inside physical start; callbacks can lose events and
submission clocks include queue residence. No subscribed event means no transport.
Event fanout checkpoints and retires its pure queue job atomically; independent
cursor documents, generic payload writes and retained successful transport weaken
fencing or grow reconstructible history. Failure evidence and accepted runs remain.
Obsolete pure clocks retire inside publication; per-edit retained jobs or a new GC
loop add growth/lifecycles. External run effects still reconcile before settlement.
Cancellation commits run intent and job cancellation together; separate requests
lose crash boundaries and must never corrupt already terminal success.
External waits suspend through the canonical queue: per-wait threads waste idle
capacity, and premature cancellation loses authority over external cleanup.

Problem: global project selection and evictable recency are not durable ownership.
Decision: `automation.project.update` owns one bounded binding in the existing
owner/tenant target namespace. `project_ + sha256(canonical root)` provides direct
root lookup without a second index. Registration requires read/manage scope and an
available canonical directory; this metadata confers no filesystem write grant.
Root/owner/tenant identity is immutable; labels and active state use revision CAS
and exact request replay. Retirement preserves metadata and history. Registration
and replay use the same public record envelope (`value`, `version`,
`updated_at_ms`) in every backend; internal record keys are not reply fields.
Root movement requires a new explicit binding/rule revision; general project relink does not
silently retarget a rule. Generic writes/deletes cannot forge or erase bindings.
Retirement names the registered root without following changed filesystem aliases.
Publication and first run admission prove an active binding in their transaction;
scoped trigger evidence must match it. Existing occurrence replay and accepted
runs retain their original snapshots after retirement.
Alternatives: path-as-public-identity leaks routing details; recent-history lookup
allows eviction to revoke identity; random IDs plus mutable root indexes require
multi-record consistency and silently change scope on rebind. None is used.

Task admission freezes the authenticated tenant into accepted execution config;
public config claims are overwritten. An explicit owner-only execution-config
query reads the accepted attempt before physical dispatch, queued activation or
recovery. The default attempt query/public DTO never includes this private config.
The task manager resolves the accepted primary root against registered bindings
before freezing its task-start context. Unregistered roots confer no scoped
trigger; browser project IDs and global project selection cannot confer ownership.

Typed remote workspace locators remain owned by `lib/desktop/remote.py`; optional
local automation capture leaves those ordinary chats unscoped without consulting
local binding storage. An explicit automation project still requires its owned
canonical local-root binding. Rejecting remote tool routing as an invalid local
root would let optional automation metadata prevent otherwise valid chat entry.
No pool/timer or cache eviction is added. `test_projects.py`, owned project HTTP
contracts and conversation/task ownership tests cover replay, isolation and capture.
