# Native repository discovery and admission

Reference for the owning domain map; shared resource policy remains in [RESOURCE_CONTROL.md](RESOURCE_CONTROL.md).

## Native Git discovery boundary
Problem: Git startup dominates small scans, and successful empty Git/ripgrep results used to fall through to walks that ignored excludes. Decision: Git success and ripgrep no-match exit 1 are authoritative, including empty lists; actual errors retain fallback. The optional repository wheel provides locked gix discovery, sparse-index expansion, raw path bytes and call-local C ABI buffers. API/status details live in the [package contract](../packages/tofu-repo-kernel/README.md).

Problem: cooperative C ABI deadlines cannot interrupt blocked filesystem I/O. Decision: explicit `load_discovery_process()` owns one Rust child per request, changes cwd after exec, and kills/joins on timeout, cancellation or caller error. Deadline, cancellation and exit remain independent facts. Malformed/nonzero responses publish no paths. Repeated interrupts cannot bypass child cleanup. No background worker, pool, queue or repository cache is introduced.

Problem: metadata checks missed same-size executable replacement. Decision: Linux loads verified bytes into one sealed memfd; each launch duplicates it under the close lock. Close refuses future launches; acquired launches retain their bytes. Package replacement requires restart. Other hosts refuse the process API while keeping the C ABI available. Release builds strip symbols and certify installed C exports and process execution.

The child receives declared local Git/path/config inputs, including indexed `GIT_CONFIG_KEY_n`/`VALUE_n` entries, without unrelated application credentials or dynamic-loader hooks. Alternatives rejected: host cwd changes race roots; abandoned threads retain filesystem work; per-call pathname hashing leaves an execution race; a persistent pool adds an unnecessary resident lifecycle. `test_native_discovery.py` and `test_native_discovery_process.py` verify actual Git layouts/raw names, relative config, concurrent roots, blocked FIFO cleanup, replacement, acquisition failure and credential isolation.

The C ABI study and process study retain real transient tool/publication cohorts and their failed guards. Native discovery remains explicitly invoked; these studies admit no default switch or whole-project completion. Untracked-file fixtures do not measure large indexes. Separate memory workers retain wait4 child peaks, sealed-image bytes and parent RSS with a conservative sum. The child lifetime high-water mark can inherit pre-exec parent RSS, and shared pages can be counted twice; it is not Rust-only RSS or physical PSS. Cold RSS remains parent-only. No wait hook enters timing workers. `test_child_memory.py` covers short-lived peaks and missing-exit refusal.

Problem: Python-only scans initialized the optional grammar catalog just to recognize `.py`; excluded metadata files could do the same. Decision: built-in Python, excluded extensions and extensionless paths resolve before optional catalog access. Other extensions retain the installed catalog and real parser selection. Alternatives rejected: eager parser warmup taxes startup/idle; a copied language map can drift from the installed grammar package. The `test_parser_catalog_laziness.py` public scans preserve file lists, tags and references, reject excluded content, and initialize JavaScript on first use.

The cross-checkout study compares the frozen prior source/Git path with this admission change plus the explicit Rust process, using the same installed CSR package in both arms. All 1,060 workers preserve output and joined cleanup. Warm P50 ratios are 0.435–0.688; Python first-operation P50/P99/CPU ratios are 0.780/0.499/0.847. This cumulative comparison does not isolate the two changes. Ranking cold P99, incremental-edit cold P95/P99 and cold-scan P99 still exceed the unchanged 1.05 guard. Native discovery remains explicit; the parser admission improvement does not authorize its default selection. Memory retains the conservative scope above, and the other 25 common-gate cases remain outside this study.

Native repository application/child and full-model installed qualification is recorded in `system_repository_model_loop_20261015.json`. It covers public v4 completion/Stop on all three tested storage transports and wheel-only two-task reuse/teardown; it adds no performance/default admission.

Native repository stream v3 preserves the Git → rg → walk discovery choice. Problem: exported/plain projects were refused and rg/walk have different membership rules. Decision: a directly owned sibling execs rg after native Git failure; only failed/unavailable rg selects the native walk. Both PIDs share the task deadline and join before code retirement. Alternatives: a nested helper can outlive a killed stream; always walking changes ignores, depth and symlinks; always embedding a different ignore engine loses rg configuration semantics. Measured lifecycle: one PID for Git, two during blocked fallback, both exited with closed pipes on Stop/deadline. Successful empty results never fall through. The walk reuses canonical ignore/depth/count policy; no default promotion or latency/memory improvement is asserted by this functional change.

`system_repository_nongit_20261015.json` records exact rg/walk membership, configured hidden paths, authoritative empty results, Stop/deadline sibling joins, installed-wheel model/child rounds and public v4 behavior on SQLite plus both native TofuDB transports.

Repository byte-path decision: Problem: Unicode-only source requests could conflate invalid-byte walk names with replacement-character filenames. Decision: discovery declares its canonical decoding mode; source requests and responses use validated discovery-table indexes, and Rust opens the original walk bytes. Tags carry no alternate path and acquire their selected path only in the parent. Git/rg retain canonical replacement behavior; only Git deduplicates decoded names, while rg preserves collisions and repeated tags. Walk retains surrogateescape. Alternatives rejected: lossy conversion can read the wrong file; refusing every invalid-byte name excludes valid POSIX projects; raw bytes in JSON duplicate path identity and increase request size. These changes add no resident worker, cache or global selector and retain the same task deadline/retirement owner.

The shared renderer quotes non-printable, backslash and quote-bearing filenames as JSON string literals. Scan/rank identity remains unchanged; displayed byte names round-trip through their escaped spelling and remain valid UTF-8 in model results and event publication. Ordinary printable Unicode paths retain their display. Passing raw surrogates failed real tool settlement byte accounting and replay, so both native and reference composition use this boundary.

`system_repository_byte_paths_20261015.json` retains both discovered failures, corrected domain/installed/native HTTP results, source-matched artifacts and the remaining performance/default limitations.

Repository runtime measurement now has a retained worker at `benchmarks/repository_index/native_extraction_runtime_worker.py`. Problem: diagnostic profiles could carry hardcoded clean-clock flags. Decision: report actual legacy hooks, thread defaults, CPython monitoring registrations/events and tracemalloc state at both cohort boundaries; reject instrumented clocks through the unchanged collector. Checking only `sys.getprofile()` misses modern monitoring-based cProfile; global event masks alone miss code-local tools. `system_repository_runtime_diagnostics_20261015.json` records real rejected profile/allocation cohorts, exact source/output identity, joined cleanup and three current 100-sample Python workload pairs. These pass the scoped warm guards but do not explain the retained historical failure or qualify complete cold, memory, application or default admission.

The retained `native_extraction_runtime_measure.py` collector covers all five repository fixtures with three 100-operation timing/memory pairs and 100 fresh cold pairs per fixture. Source metadata Git runs outside observed workers; workers validate the frozen commit's actual source/artifact bytes. Independent exit observations must match each memory worker's child journal before RSS qualification. Timing and memory remain separate, and the RSS sum is conservative, not physical peak PSS. Checked runtime/test sources may be reused only across reviewed collector/guide-only changes; fresh checks reject skips and failures. Problem: incomplete or instrumented observations cannot establish migration gains. Decision: retain every raw observation and report unchanged standard guards. Warming activation, reusing timing processes for memory, and dropping failed pairs are rejected alternatives. `system_repository_owned_full_20261015.json` records complete repository coverage, retained cold CPU/tail failures and matched output/cleanup evidence. Coverage is five of the system contract's thirty cases; neither the remaining domains nor application/default admission follows from it.

Cold activation keeps `StreamLimits` a frozen dataclass while defining its small value methods explicitly. Problem: first use compiled methods unrelated to the scan. Decision: avoid that generation while preserving fields, equality/hash, copy, replacement and input refusal. Preloading outside the operation clock or replacing its dataclass API are rejected alternatives. Nested phase diagnostics are always marked instrumented; only separate clean workers admit clocks.

Application task scopes preserve canonical file-local grammar failures and references, while owned measurement scopes remain strict by default. This separates application error semantics from complete-work measurement admission; malformed frames, invalid configuration, artifact failures and cancellation still fail the tool. A whole-scan reference fallback would hide native failure and is not introduced. Installed model-loop fixtures join their provider even when configuration validation fails. `system_repository_cold_activation_20261015.json` records the API/installed checks, rejected copy prototypes and a complete targeted cold cohort that still exceeds the CPU guard. Defaults remain unchanged.
