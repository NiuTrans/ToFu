# Media source admission and complete evidence

Reference for the owning domain map; shared resource policy remains in [RESOURCE_CONTROL.md](RESOURCE_CONTROL.md).

## Video source demand
**Problem:** browser, HTTP and scratch-receive 512 MiB quotas refused valid video sources, while a fixed 180-poll client window marked still-running work as failed after 12 minutes. **Decision:** complete sources reuse local scratch and the existing owner-scoped media repository/processing handoff, with request overflow owned by the shared HTTP buffer. The picker accepts the source and shows actual processing status until server settlement or explicit attachment removal. File format sniffing, owner isolation, actual I/O errors and worker publication failures remain strict; duration/extraction policy is separate and remains under review. The retired `TOFU_VIDEO_MAX_BYTES` knob and old size-limit locale strings are removed. **Alternatives considered:** larger quotas move refusal; truncating video bytes corrupts the source; a polling cliff cannot prove backend failure. Guards include real-browser picker dispatch/rendering, complete 513 MiB HTTP transport, existing video-route failure/owner tests and completion beyond 180 polls plus stop-on-removal.

## Uploaded image source admission

**Problem:** the image route refused sources above 32 MiB and its HTTP policy refused JSON bodies above 46 MiB, while the directory lifecycle still exposed an unused 2 GiB admission quota. **Decision:** remove these byte quotas and their configuration knobs. Multipart intake reuses the parser-owned seekable file; JSON base64 is decoded in aligned chunks into one request-owned anonymous file. Header validation and existing preview resizing read this file directly; unchanged formats are copied to their final path in 64 KiB chunks. Temporary files close on return or error, and failed output writes remove partial files and return the existing error envelope. Orphan quarantine remains independent of upload admission. **Alternatives considered:** raising ceilings retains refusal; materializing the complete decoded source adds another large RAM copy.

Verification admits a real 36,750,054-byte BMP through both JSON and Multipart and checks exact saved hashes. A padded PNG verifies bounded source reads; an injected write failure verifies error settlement and partial-file cleanup. This measures admitted bytes, not process RSS or production throughput. JSON parsing still materializes its encoded string. Pixel/decode validation, SVG exclusion, filename sanitation and existing resize behavior remain separate policies; remote image fetch limits are outside this change.

## Remote image file ownership

**Problem:** generation history dropped remote images above 10 MiB and stopped active downloads at a fixed total deadline; its receive list and final join retained multiple decoded copies. **Decision:** remove the image fetch byte knob and total-duration admission. The shared public downloader writes decoded response chunks into one anonymous file; successful callers own its close, while transport and file failures close partial files before propagating. Image history encodes that file in blocks and retains only its required base64 result, preserving MIME and complete bytes. Local history uses the same encoder. Each redirect still passes public-address validation, and network connect/read timeouts still settle stalled connections. Other callers' explicit byte/deadline policies remain independently visible. **Alternatives considered:** larger byte or time quotas still discard valid sources; an unbounded chunk list retains the complete decoded source alongside the encoded model payload.

Verification includes real loopback HTTP reception of 11,599,872 bytes with and without Content-Length, checks exact digests, and closes response and file owners. History round-trips an image above the former cap; injected disconnects, disk writes and encode failures settle without leaked owners. The encoded history string still scales with source bytes; no RSS or throughput reduction is claimed from byte-count tests.

## Video duration and evidence continuity

**Problem:** valid uploads over 900 seconds failed before extraction, and storyboards/transcripts lost all characters after 30,000. A 30-minute phase could also be mistaken for a dead server, while scratch age alone allowed cleanup of a live upload. **Decision:** remove the source-duration knob and private text truncation. Positive finite duration remains required for decode. Complete storyboard/transcript text reaches the existing atomic attachment evidence replacement and its document chunker. Frame sampling and downstream model context selection remain separate policies under review.

Processing records and scratch directories carry the existing shared local process-incarnation evidence. Proven process exit settles interrupted records; active or unobservable owners retain processing status regardless of elapsed time. Terminal registry entries retain their cache TTL. Scratch reclamation requires both expiry and proven owner exit for stamped directories; legacy unstamped scratch retains its previous grace policy. Normal worker completion still deletes its scratch in finally. Unknown ownership requires recovery inspection, rather than an invented timeout failure or destructive cleanup. **Alternatives considered:** larger duration/text caps retain refusal or loss; periodic timestamp refresh can itself stall and makes elapsed time a proxy for liveness; private PID checks duplicate the shared incarnation authority.

Verification feeds a two-hour duration and two complete 80,000-plus-character texts through the pipeline, checks terminal readiness and exact payloads at the attachment commit boundary, and retains actual FFmpeg short-clip coverage. Old live/unknown processing and scratch owners survive cleanup; an obsolete process incarnation is reclaimed. Non-finite and non-positive durations still fail before extraction. These are boundary checks, not a two-hour throughput benchmark or a claim that all video/model evidence limits have been removed.

## Video frame and narration coverage

**Problem:** the 64-frame extraction ceiling discarded long-video and scene evidence, while one storyboard request thinned its input again. Chat then suppressed the storyboard whenever any raw frames survived selection. **Decision:** retain duration-scaled uniform sampling (at least 16 frames and no more than 10 seconds between sampling cells) and every nonredundant scene cut. Timestamp deduplication uses sorted neighbor searches rather than scanning all prior frames. Extracted files use numeric ordering beyond four-digit names. The downstream model hint no longer inherits the obsolete extraction ceiling.

Storyboard narration traverses all extracted frames in chronological batches. Its existing request output window and model hint size each call; they never limit the total evidence. Each batch loads only its own image bytes. A failed, unreadable or empty batch settles narration as failed, so partial text cannot be acknowledged as complete. All batches reuse the same owner-pinned route group. Chat includes full narration whenever its request selects fewer raw frames than were extracted. **Alternatives considered:** increasing a fixed count loses evidence again on longer sources; one unbounded model request exceeds provider context/output limits; presenting partial narration as ready hides missing evidence.

Verification extracts 70 real JPEG frames (16,030 JPEG bytes) from a 700-second 32×32 synthetic clip, including its final sampling cell, retains 200 nonredundant scene timestamps, and sends all 193 storyboard inputs across multiple requests in order. A late batch failure returns failed with no partial successful text. Request projection keeps full narration alongside a partial frame selection. Durable evidence and metadata grow with sampled duration and scene changes; the attachment owner and its existing deletion lifecycle retain those artifacts. These tests do not claim frame-by-frame capture, model narration accuracy or production throughput.

## Complete Turn attachment lists

**Problem:** client-ref resolution silently examined only the first 20 inputs, so invalid or duplicate early entries could hide valid later attachments. The Turn contract separately rejected image and attachment arrays above 20. **Decision:** resolve the complete list in input order and remove these count limits from the canonical contract and generated Python/browser validators. Each ref still passes owner-scoped canonical lookup; invalid, missing and duplicate identities grant no authority. Commit-time retention covers every resolved attachment, while model evidence selection stays independent. **Alternatives considered:** raising 20 postpones loss; widening the schema alone still silently drops the tail during resolution; trusting client metadata bypasses the existing ownership boundary.

Verification resolves and retains 33 real document attachments despite early invalid/duplicate inputs, with exact canonical names and ordered identities. A real settled Turn and HTTP snapshot preserve 33 image refs plus 33 media refs; an invalid status after the former cutoff still fails schema validation. Turn metadata grows with retained refs, without copying original document bytes into the Turn. Existing attachment deletion owns durable source cleanup.

## Knowledge index term continuity

**Problem:** application ingest retained an obsolete 14,336-write quota after the authority stopped enforcing that limit. It proportionally erased index terms and refused documents whose overhead alone exceeded the quota. Separate 256-term application and 4,096-term storage ceilings also removed or rejected late evidence inside a chunk. **Decision:** index every valid source term and remove aggregate trimming plus SQL/native chunk-term count admission. Query token/page windows remain explicit retrieval operations; normalized term shape, identity, owner scope and atomic publication/rollback retain their authority. **Alternatives considered:** raising ceilings loses evidence on larger sources; proportional trimming preserves chunk rows but makes omitted facts unsearchable; publishing multiple independent transactions weakens all-or-nothing ingestion.

Measurement: a 139,999-byte text produces 95 chunks with all 20,000 distinct source terms searchable, including its last word. Replacement retains 14,400 small chunks, then a single 5,501-term chunk, without changing its original source bytes. Native restore/replay/reopen separately preserves a 5,501-term chunk. Index postings grow with distinct valid terms and remain owned by the document's existing deletion lifecycle; these counts do not measure RSS or production throughput. Upload byte, asset-count and other domain limits remain separate work, so this is not a claim of complete unlimited document ingestion.

## Complete media evidence publication

**Problem:** duration-scaled video extraction could produce more than 200 frames, but media evidence replacement rejected the entire result before persistence. **Decision:** remove that application asset-count gate. The existing replacement owner still copies one frame at a time, publishes the complete asset rows and timestamp references atomically, then reclaims replaced files. Failed writes remove every newly written file and preserve the previous committed evidence and original source. Asset read pages remain retrieval windows with offsets; their page size grants no ingestion quota. **Alternatives considered:** raising 200 repeats rejection for longer sources; truncating the list discards scene evidence; per-page independent commits make partial evidence visible before the video is complete.

Measurement persists 257 real JPEG frames / 162,582 JPEG bytes through the video completion boundary, pages past 200, and verifies every stored byte and timestamp. An injected failure on write 213 leaves prior metadata/files and the original unchanged; document deletion removes the complete committed asset set and source. This uses synthetic frame files, not a 43-minute FFmpeg throughput benchmark. Native storage's separate higher corpus bounds remain under audit; this removes the application's 200-item refusal specifically.

## Complete document upload admission

**Problem:** unified document intake refused files above 50 MiB both in its route and the shared HTTP policy, even when parsing would produce a small valid index. **Decision:** remove that route byte ceiling and admit complete media upload bodies through the existing request-owned spill transport. Multipart files retain their parser ownership until the request closes; the current document parser still materializes one full byte input. Receive failures now enter the route's existing indexing-error envelope. Existing type validation, owner-scoped digest reuse, immutable source persistence and atomic rollback remain. **Alternatives considered:** increasing 50 MiB preserves refusal; reading only a prefix corrupts the source and digest; reporting upload success before indexing can leave an unusable attachment.

Verification uses a real ODT package with a 51 MiB uncompressed resource. The actual route indexes searchable content, exposes an exact original by hash, reuses the same owner-scoped digest on repeat upload and deletes its source through the existing document lifecycle. This is byte-admission coverage, not a claim of constant parser RAM or unlimited extracted-text indexing. Other parser and Office package policies and ingestion surfaces remain separate work.

## Complete knowledge text extraction

**Problem:** knowledge silently sliced extracted text at a default 12 million characters and clamped configuration to 50 million, leaving the preserved original with an incomplete searchable projection. **Decision:** retire the knowledge text quota and knob. Existing integer-based parser APIs receive the addressable string boundary rather than a private admission/output ceiling. Format-specific parsing, provenance, immutable original and atomic index publication remain with their existing owners. Other callers' explicit output lengths still select bounded projections independently of source ingestion. **Alternatives considered:** raising the limit silently omits later evidence again; preserving only the original makes discarded text unsearchable; storing a truncated index as complete obscures missing source facts.

Measurement indexes 12,000,058 characters into 8,027 chunks, preserves the exact original hash, and retrieves a unique marker beyond the former default via search and the final chunk page. Text/chunk/posting storage grows with the parsed source and remains tied to document deletion. This is corpus coverage, not a claim of constant parser memory; extraction still builds its full text string, and other format/storage policies remain under audit.

## Office package source admission

**Problem:** OOXML/ODF/EPUB type identification refused packages above 20,000 members or 256 MiB declared expanded bytes, and rejected high compression ratios even when most members were never required. **Decision:** remove these aggregate resource admission checks. ZIP metadata identifies the existing format owner; parsers read required members and image extraction keeps its existing one-asset-at-a-time owned spool. Unused binary resources are never eagerly expanded merely to admit the document. ZIP/member integrity, XML parsing, per-image validation and source/index rollback retain their authorities. **Alternatives considered:** raising fixed totals preserves refusal; expanding all members up front spends resources on irrelevant payloads; swallowing required-member corruption publishes a misleading index.

Measurements cover a real 20,004-member ODT (2,355,126 source bytes), an ODT with 269,484,812 declared expanded bytes (262,747 source bytes), and a required XML member in a 34,603,678-byte expanded package (34,360 source bytes). Each indexes its final marker, preserves its complete source hash and deletes via the document lifecycle. Required-member CRC damage fails before publication. These tests establish admission and integrity, not constant parser RAM: XML parsing still materializes required XML, and image/format policies remain separate audit work.

## Archive reception and complete extraction

**Problem:** chat/project archives refused uploads above 128 MiB, more than 512 files, a member above 32 MiB, or a tree above 64 MiB. Project single-file reception added a 64 MiB spool limit, and 64 directory-name collisions refused otherwise valid imports. **Decision:** complete reception and extraction use owned files and one private staging tree with no private byte/file quotas. Project HTTP upload prefixes admit complete file-backed input. Production callers and the spool helper no longer carry hard byte admission caps. Every regular file copies in 1 MiB windows. Actual EOF before the declared member size fails the archive, removes staging and cannot become a successful byte receipt. Skipped-member receipts retain all entries. Existing root/read-only authority, path/link validation, exclusive file creation and same-filesystem publication remain unchanged. **Alternatives considered:** raising ceilings rejects larger future sources; truncating members corrupts projects; eager expansion into RAM consumes memory for the whole tree; acknowledging short reads hides incomplete source data.

Measurement extracts 1,101 files and a complete 65 MiB member/tree, receives and hashes a 129 MiB spool, and publishes after 71 name collisions. Both chat and attached-project archive routes retain a complete 33 MiB member. Injected short reads remove every staged file. These are synthetic byte/count cases, not throughput claims. Paper build snapshot limits and path constraints remain separate audit work.

Paper build source snapshots and explicit records have no private file/byte admission quota. Descriptor-validated chunk copying preserves complete input and immutable snapshot identity; browser preview observes every committed change. See [paper source snapshots](PAPER_BUILDS.md#complete-source-snapshots) for measured inventory, lifecycle and remaining compiler policies.

Knowledge library upload — Problem: browser and route quotas rejected batches above 20 files, individual sources above 50 MiB and aggregate input above 200 MiB. Decision: receive complete files through the shared file-backed HTTP transport and index each under the authenticated owner; remove preflight and route quotas and the advertised maximum-size hint. One source at a time enters the existing bytes-based parser; this does not claim constant parser RSS. Per-file parser/write errors retain their visible batch receipts, and immutable source/hash deduplication plus rollback remain owned by the knowledge store. Alternatives: increasing limits merely postpones refusal; dropping files loses evidence; eagerly concatenating the batch duplicates every source in memory. Tests index 33 actual documents plus 51 MiB and 201 MiB ODT sources through the HTTP route, verify searchable tail/source digest, deduplicate and reclaim the stored source.

Office source demand — Problem: document uploads borrowed a remote-fetch byte ceiling and the generic HTTP 50-MiB ceiling; default extraction clipped text at 2,000,000 characters, spreadsheets clipped rows/columns and stopped at blank gaps. Decision: complete source upload uses owned file-backed HTTP transport, and parser defaults extract all text. Explicit positive `maxTextChars` remains a caller output budget with truncation provenance. Read-only spreadsheets ignore advisory dimensions, traverse actual XML rows and preserve separated blocks in robust mode; legacy XLS traverses every declared data row. Receive errors retain the HTTP error envelope. Alternatives: higher caps fail later; silent partial success loses evidence; treating advisory dimensions as data emits empty tails. Tests cover 5,000 rows, 250 columns, a long blank gap, complete default text above two million characters and a 51-MiB real source through the document endpoint. This measures extraction completeness; parsers still own a bytes-based input and do not claim constant RSS.

Sparse table rendering compares dense-grid and coordinate-list output cost before padding ragged rows, retaining every nonempty value without materializing missing cells across the whole rectangle. A 1,000-row/2,000-column sparse fixture keeps its far-column evidence in under 100,000 output characters. Table row numbers are extracted-table ordinals, not claims of original worksheet row IDs. Workbook ownership closes on both successful traversal and parser failure.

## Complete PDF source admission

**Problem:** a shared 200 MiB source ceiling rejected valid PDF uploads, arXiv downloads, harvest ingestion and extraction before their actual parser could inspect the document. **Decision:** those paths consume the complete source. `/api/pdf/parse`, `/api/pdf/vlm-parse` and `/api/paper/upload` use the shared file-backed HTTP body transport without a private byte ceiling. Paper uploads copy into owned staging, fsync, validate, then atomically publish; failed reads, writes and validation remove the staging file without replacing a prior valid source. Harvest downloads spill their receive spool to disk and close the response on every exit. A verified malformed PDF is non-retryable; real network failures retain their existing retry policy.

**Alternatives considered:** raising the fixed ceiling would leave the same valid-source refusal at a larger size. Treating malformed PDFs as retryable would waste provider calls without repairing their bytes. The parser still materializes complete bytes, so staging does not imply constant parser RAM. Explicit extraction/page policies remain with the parser. The independent 200 MiB URL-title metadata probe may fall back to the filename; it does not control source ingestion.

Verification: `tests/paper/test_pdf_source_demand.py` uses a real valid PDF with a 201 MiB uncompressed stream, actual text extraction and HTTP parsing, and SHA-256 comparisons of the complete downloaded/stored source. `test_paper_upload_atomic.py` and `test_paper_harvest_download_budget.py` cover failed receive cleanup, invalid-source behavior and response teardown. A missing parser backend is a skip, not validation evidence.

## Native local-file reader admission

Problem: `lib/file_reader` duplicated 50 MiB PDF/Office and 20 MiB image ceilings even after their source/upload boundaries accepted complete input. Its fixed 50 MiB character request also cut Office extraction before the shared result layer could retain it. Decision: supported native bytes pass to their reader without these private quotas. Office uses complete default extraction; PDF delegates to the owning parser policy. The router no longer exports unused byte/character admission constants. Original image reads and both file/byte crop inspection paths keep native decoding, compression and view pixel policies; a preview does not overwrite the original.

Office parser results with zero actual text are explicit read errors even when they contain diagnostic placeholder strings. Missing and malformed parser inputs cannot become successful document observations. Actual file/decoder failures, native format support and caller path/owner authority remain separate boundaries. Alternatives considered: raising constants repeats valid-source refusal; retaining only a preview at the producer destroys evidence before result retention. Materialization remains proportional to source bytes and extractor output; this change adds no resident worker or cache.

`tests/file_reader/test_native_file_source_demand.py` validates a real 201 MiB PDF, a DOCX above 50 MiB with over 50 MiB actual paragraph text and exact text SHA-256, and a 36 MiB BMP whose corner detail is decoded by both crop entry points. Source hashes remain unchanged. The suite also checks failed/missing Office parsers; the image, façade and range suites pin neighboring contracts. The PDF test requires a working real parser and never treats a skip as evidence.

## Complete default PDF text

Problem: classic PDF extraction applied a launch-derived text ceiling and a 64 MiB hard clamp, stopping valid default observations before the result retention boundary. Even a larger positive caller limit was silently lowered. Decision: default/zero text extraction traverses complete admitted text. `TOFU_PDF_MAX_TEXT_MIB` is retired and ignored, with no generated/probed default. A positive `max_chars`/`max_text_chars` remains the explicit caller cut and is not resource-clamped. Parsed response `limits.maxTextChars` is zero for the complete default, preserving a usable client value instead of a platform extent.

Alternatives considered: larger constants move the same omission; retaining only the clipped string cannot recover skipped evidence. Existing native strategy selection, page ranges, cancellation/time policy, model image previews and result token projection retain their owners. Complete text materialization is proportional to extracted content, not constant memory. `tests/pdf_parser/test_pdf_text_source_demand.py` uses a real 220-page PDF with text beyond the retired configured 1 MiB ceiling, verifies every page's marker and the final line through extraction/core parsing, and preserves an explicit 1,200,000-character cut. Policy, page-isolation and range/limit neighbors remain required; missing native parser support is a skip, not extraction evidence.

 Classic PDF explicit figure selection — Problem: image count was silently clamped to 64 and width to 2,048 pixels; a separate fivefold render zoom clamp also reduced requested detail. Decision: preserve the caller's nonnegative image count and positive maximum width through extraction and rendering. Zero count still disables optional figures; malformed widths retain the 1,024-pixel default. Default preview selections remain caller policy, and explicit page ranges, figure detection and white-border cropping retain their semantics. Alternative rejected: larger fixed ceilings still silently change larger requests. Real PDF guards in `test_pdf_classic_bounds.py` retain figures from all 75 selected pages and decode a requested 3,500-pixel figure above the old width and zoom ceilings. Source bytes remain unchanged. Table detection — Problem: pages without table captions expand unused glyph bounds. Decision: classify first and call find_tables only for table captions. Figure crops, table fallback/continuation and embedded-image extraction retain their paths. Alternative: sharing Markdown results confuses lines_strict and visual lines strategies. Verify test_figure_table_demand.py and the PDF image/knowledge neighbors.

`system_pdf_table_demand_20261015.json` records exact output comparisons and diagnostic ingestion clocks.

 Complete PDF figure demand — Problem: core/HTTP extraction silently stopped at 20 figures; paper ingestion stopped at 30, and its cache ignored count and width. Decision: omitted image count selects all detected figures, explicit zero disables them, and positive count preserves the caller prefix. HTTP `limits.maxImages` is null for complete selection. Paper manifests version 8 record count/width and successful extraction; old, differently selected or failed manifests regenerate instead of hiding late figures. Partial page/save failures do not acquire cache-success authority. Cross-page table continuation renders at the base image scale without the old fivefold clamp. Alternative rejected: a higher default count still drops later evidence; reusing a smaller cached selection defeats later complete requests. Existing figure detection, per-request width projection, native safety lock and source authority remain. Real guards cover 75 default figures, explicit zero/prefix, limited-to-complete cache regeneration, width changes, injected page failure and retry, continuation scale, and the actual HTTP default.

 Classic PDF wait ownership — Problem: launch-probed timeouts and a 3,600-second hard ceiling ended caller waits for healthy parsers without settling their work. Decision: unset or zero `TOFU_PDF_PARSE_TIMEOUT` and caller timeout mean no wait cutoff. Positive operator and caller values are exact; when both are explicit, the earlier bound applies. Launch profiles never inject a parse timeout. Invalid caller bounds fail before publication. A caller timeout retains unfinished-work ownership until the submitted future actually settles; it does not authorize a duplicate parse or claim that the running worker was killed. Existing idle worker reuse and retirement remain separate. Alternatives considered: a larger default still abandons healthy work; releasing ownership on timeout hides live work. Verification: classic policy and pooled parsing tests cover default unlimited waiting, exact values over one hour, explicit bounds, unfinished settlement, real demand bursts beyond idle reuse, and process retirement.
