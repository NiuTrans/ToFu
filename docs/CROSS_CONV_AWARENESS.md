# Cross-Conversation Project Awareness

> How Tofu lets the model know about — and reach into — *other* conversations
> that belong to the same project, without the user having to attach anything.

This document is the design record for the three-layer feature shipped in
June 2026. Read it before changing `lib/conv_ref.py`,
`lib/conversations/project_summary.py`, `lib/tools/registry.py::has_conv_ref`,
or the digest injection in `lib/tasks_pkg/system_context.py`.

---

## Motivation

A user's history is thousands of separate conversations. By default the model
only sees the *current* one. Three mechanisms connect them:

| Mechanism | Who initiates | What the model gets |
|---|---|---|
| **`@` reference** (pull) | user attaches a conversation | its full content injected inline (`[REFERENCED_CONVERSATION …]`) |
| **conv-ref tools** (explore) | model calls `list_conversations` / `get_conversation` | discover + fetch other conversations |
| **project digest** (ambient) | automatic, in project mode | a bounded list of sibling conversations + one-line summaries |

The work is split into three layers, each independently shippable.

---

## Layer 0 — the trigger fix (`has_conv_ref`)

**Bug:** `ToolContext.has_conv_ref` enabled the conv-ref tools whenever the
literal substring `[REFERENCED_CONVERSATION` appeared in **any** message of
**any** role. A conversation *about* the feature (where the assistant quoted
the token) self-enabled the tools, diverging the per-conversation tool latch
and popping the "toolset changed" banner — with no real reference attached.

**Fix:** scan **user-role messages only**, and accept a reference only when it
is the *real* signal:
1. the structured `convRefs` / `convRefTexts` field (authoritative, on raw
   conversation rows), or
2. the server-injected wrapper signature `[REFERENCED_CONVERSATION` **and**
   `title="` (what `conv_message_builder` prepends — distinguishes the real
   block from a quoted token).

Assistant content is never scanned. Pinned by `tests/test_tool_registry.py`
(incl. an explicit "assistant prose must NOT trigger" regression).

## Layer 1 — project-aware `list_conversations`

`lib/conv_ref.py::list_conversations(keyword, limit, scope, project_path,
current_conv_id)`:

- **`scope`** — `'project'` filters on `settings.projectPath` (via
  `json_extract`, which `_sql_translate` rewrites to the PG jsonb accessor, so
  one statement works on SQLite + PG); `'all'` = everything; `'auto'` (default)
  = project when a path is present, else all.
- **content search** — the keyword matches message *content*, not just the
  title. On PG it uses the GIN-indexed `search_tsv` tsvector prefix query
  (the same index `routes/conversations_search.py` uses); SQLite and the
  no-word case fall back to a portable `title/search_text LIKE`.
- **self-exclusion** — `current_conv_id` is dropped from results.

`project_path` is threaded from the task through `execute_conv_ref_tool` →
`_handle_conv_ref_tool`. Pinned by `tests/test_conv_ref_scope.py`.

**Known follow-up:** the `settings->>'projectPath'` filter is unindexed; a
functional index would cut the residual ~1.4 s scan. Out of scope for now —
this is a model-invoked tool, not a per-keystroke path.

## Layer 2 — ambient awareness (summaries + digest)

The goal: the model should *know* siblings exist and their gist, without the
user attaching anything. Implemented as a **tiered hybrid** rather than one
artifact:

- **Title = the discovery index.** Already generated (`title_gen.py`); shown in
  `list_conversations` output and as the digest fallback when no summary
  exists yet.
- **One-paragraph summary = the awareness layer.** 1–3 sentences of
  "outcome + key decisions", generated by the cheap model and cached in
  `settings.projectSummary = {text, generated_at, msg_count_at_gen}`.
- **Bounded digest = the injection vehicle.** Top `DIGEST_MAX_SIBLINGS` (10)
  most-recent sibling conversations, each `"title" — summary [id]`, injected
  always-on in project mode as its own cache-stable system block.

### Where the code lives

- `lib/conversations/project_summary.py` — the engine:
  - `ensure_summary(conv_id, force=, blocking=)` — generate-if-stale + persist.
    `blocking=False` returns the cached text immediately and regenerates in a
    daemon thread (used by hot paths).
  - `generate_summary(messages)` — the cheap-model call (outcome-weighted
    transcript: first 2 turns + last 6, capped ~4 KB).
  - `build_project_digest(project_path, current_conv_id, limit)` — read-only,
    side-effect-free; never generates, only reads cached summaries.
- `lib/tasks_pkg/manager.py::_maybe_refresh_project_summary` — **Trigger A**:
  post-reply, project-mode-only, non-blocking.
- `lib/conv_ref.py::get_conversation` — **Trigger B**: on first read of a
  sibling, non-blocking.
- `lib/tasks_pkg/system_context.py` step 4.4 — digest injection (idempotent via
  a marker probe, like every other context block).

### Decisions (the ones explicitly chosen)

1. **Generate lazily, never eagerly.** We do NOT batch-summarize all of a
   project's conversations on a timer. Summaries are produced only when a
   conversation (a) gets a reply while in project mode, or (b) is first read by
   `get_conversation`. This bounds cost to conversations that are actually
   active or referenced.
2. **Regenerate only on material growth.** `_is_stale` regenerates when
   `msg_count - msg_count_at_gen >= SUMMARY_STALE_GROWTH` (6). A static
   conversation keeps its cached summary forever → no redundant LLM calls, a
   stable digest, and a stable prompt-cache block.
3. **Digest is always-on in project mode, but bounded.** Top 10 siblings, each
   summary hard-capped at `SUMMARY_MAX_CHARS` (320), so the injected block
   stays small and cache-friendly. It changes only as the project's recent set
   changes — its own cache breakpoint keeps it from invalidating the static
   prompt prefix.
4. **`settings`-only persistence.** `_persist_summary` writes ONLY the
   `settings` column (read-modify-write under a lock) — never `messages` /
   `updated_at` — so it never reorders the sidebar or races the message
   persist path. A rare lost update against an unrelated settings write is
   acceptable for a low-frequency, fully-regenerable cache.
5. **Non-blocking everywhere on hot paths.** Both triggers and the
   `blocking=False` path run generation in a daemon thread; the digest builder
   is read-only. An LLM call never delays task completion, the next queued
   message, or prompt assembly.
6. **Title fallback.** A sibling with no summary yet still appears in the
   digest by title — the model is told it exists even before it's summarized.

### Cost ceiling

One cheap-model call per conversation per ~6 new messages, only for active /
referenced project conversations. There is intentionally **no** path that
summarizes a whole project at once. If a bulk backfill is ever wanted, it must
be an explicit, rate-limited, opt-in script (mirroring `debug/backfill_*.py`),
never an automatic timer.
