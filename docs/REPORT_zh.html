1背景知识：零基础先读这里

在讲我们做什么之前，先用大白话把五个概念讲清楚。理解了这五个，后面就全通了。

① 代码智能体（Coding Agent）与"轨迹"

现在的大模型不只是聊天，还能像程序员一样自己动手改代码：给它一个 GitHub 上的 bug 报告，它会自己去翻文件、读代码、写补丁、跑测试。它一步步操作的完整记录（读了哪个文件、运行了什么命令、改了哪几行）就叫一条「轨迹（trajectory）」。

打个比方 轨迹就像一个实习生修 bug 时录下来的全程录像：从哪儿开始查、中间走了哪些弯路、最后怎么交差，全都在里面。

② SWE-bench：一套"真实 bug 考卷"

SWE-bench Verified 是业界公认的考卷：500 个来自真实开源项目（Django、SymPy 等）的真实 bug。每道题都配有官方测试用例。智能体交上补丁后，自动跑这些测试——全过 = 修对了（resolved=True），否则就是没修对。这个"测试通过与否"的信号，我们叫它可验证的"裁判（oracle）"，因为它客观、不会撒谎。

③ Rubric（打分表 / 评分细则）

问题来了：测试只能给出"对 / 错"两个字。但两份都没通过测试的补丁，质量可能天差地别——一份已经定位到了 bug 只差一行，另一份完全跑偏。"对/错"这种信号太粗了。

于是人们引入 Rubric，也就是一张打分细则表，把"补丁好不好"拆成一条条可勾选的小标准，例如：

  • ☑ 改动是否最小、只动了该动的文件？（维度：file_changes）
  • ☑ 是否真正解决了 issue 描述的问题？（维度：spec_alignment）
  • ☑ 有没有作弊，比如偷偷改测试让它通过？（维度：completeness）
  • ☑ 改完之后有没有自己跑一遍验证？（维度：runtime）

让另一个大模型（「裁判模型 / judge」）逐条打勾，加权汇总成一个 0~1 的分数。这就比"对/错"细腻多了。

打个比方 Rubric 就像高考作文的评分细则：不是只判"及格/不及格"，而是分"立意、结构、语言、卷面"逐项给分。

④ RLVR：用"可验证奖励"训练模型

RLVR（Reinforcement Learning with Verifiable Rewards，带可验证奖励的强化学习）是现在最火的训练范式：让模型不断尝试，做对了就给"奖励"，它就慢慢学得更好。在写代码这件事上，"奖励"通常就是上面那个测试信号（通过=1，否则=0）。

⑤ 核心痛点：奖励太"稀疏"，功劳分不清

这里就是整个项目的命门。一条轨迹可能有几十步操作，但最后只有一个"通过/不通过"的总分。这带来两个问题：

问题 A：奖励稀疏几十步操作，只在最后一刻得到一个 0 或 1。模型很难知道到底是哪一步走对了、哪一步走错了。就像考试只告诉你总分不及格，却不告诉你错在哪。
问题 B：功劳分配（Credit Assignment）最终成功了，是因为第 3 步精准定位，还是第 17 步那个测试？失败了又该怪谁？把"总结果"公平地摊派到"每一步"上，这个难题学术上叫「功劳分配 / credit assignment」。
一句话总结背景 测试信号客观但太粗（只有对错、且只在最后给）；Rubric 细腻但没人能证明它本身靠不靠谱。我们的工作就卡在这两者之间做文章。

论文一：给"打分表"本身做一把尺子（计量学 Metrology）

有个鸡生蛋的难题：Rubric 的存在，本来就是因为我们缺好的质量信号；那我们又凭什么说一张生成出来的 Rubric 是好的？ 以前的答案都不令人满意——要么"下游 RL 涨点了"（太慢、说不清是谁的功劳），要么"和人工标注一致"（又用回了本想省掉的人工标注）。

我们的答案：用一个"能力阶梯"当尺子。

核心比方：视力表 我们准备一固定的模型池，里面有从 0.8B 到 671B、能力已知由弱到强排好队的模型（它们的真实强弱，由客观的 SWE-bench 测试钉死）。一张好的 Rubric，应该能把这排模型的强弱顺序重新排对——就像一张标准视力表，能准确量出谁视力好谁差。Rubric 把顺序排得越准，说明它区分度（discrimination）越高，质量越好。这个分数不需要任何人工标注，又快又便宜，于是"优化 Rubric"第一次变成了一个定义良好的数学问题。

而且我们还会故意埋雷（见第 4 节"缺陷注入"），来证明 Rubric 不仅会排序，还真能抓到它声称能抓的毛病。

论文二：把"打分表"变成能给"中间过程"发奖励的稠密信号

这是本次新规划的重点，也是天花板更高的方向。回到第 1 节的问题 A/B（奖励稀疏、功劳难分）。学术界公认：在智能体场景里，"每一步对不对"根本没有客观标准答案，所以大家只能绕着走（用事后想象、用隐式信号、用手工规则去猜每一步的功劳）。

我们的洞见（一句话） Rubric 的每一个条目，本身就是那个缺失的"中间裁判"！比如"是否已复现 bug""是否已定位到出错函数""是否已加回归测试""是否已跑通验证"——这些条目可以在轨迹的"前缀"（做到一半时）上就检查，而不必等到最后。

具体怎么做，三步：

1
把轨迹切成"块（block）"，逐段打分。 不再只给最终补丁打分，而是在每完成一段操作时，用 Rubric 检查一次"目前满足了几条"。我们把"前缀已满足条目的加权比例"记作一个分数 Φ（读作 phi，可理解为"进度条"）。
2
用"势函数"的方式发奖励（关键的防作弊设计）。 每一段的奖励 = Φ(这一段做完) − Φ(上一段做完)，也就是"进度条涨了多少"。这种叫势函数塑形（potential-based shaping）的写法有一条 1999 年就被证明的数学性质：它能把稀疏奖励变稠密，却保证不会改变"最优策略"——也就是说不会诱导模型为了刷分而走歪。这是我们对"Rubric 奖励会被钻空子"这一质疑的正面回应。
最终训练奖励 r = 1{测试通过}  +  λ · Σ ( γ·Φ(下一段) − Φ(当前段) )
左边是原来的稀疏总分；右边是每一段进度条变化累加的稠密奖励。数学上它会"望远镜式抵消"，最终仍由"测试通过"主导，所以稠密信号只是帮忙、不喧宾夺主。
3
因果验证：埋的雷，前缀分数会在"那一步、那一维度"下跌吗？ 这是别人做不出来的招牌图（见第 4 节）。

3定位：我们和别人到底不一样在哪

这个方向 2025–2026 非常热，必须讲清楚区别，否则会被评审认为"别人做过了"。下面是我们逐字读过全文后整理的对手地图。

论文一（计量学）的对手

已有工作它怎么判断 Rubric 好坏不足
Agentic Rubrics（2601.04171，离我们最近）"Best@K 涨了"把 Rubric 质量和生成器/选择器混在一起，说不清是谁的功劳；不进化、无模型池
OpenRubrics"和人工偏好标注一致"需要本想省掉的人工标注
DR Tulu / RLER"下游 RL 涨了"没有外部客观裁判来锚定 Rubric；非代码场景
论文一的三个独占点 ① 第一个用"可验证裁判"而非人工标注来进化 Rubric； ② 把别人的"未来工作"自动化了（Agentic Rubrics 原文把"人在回路精修 Rubric"列为待办，我们用客观裁判替代了"人"）； ③ 用"埋雷"做可证伪的验证，而不只是看相关性。

论文二（过程功劳）的对手

学界给"每一步没有标准答案"这个难题想了三类绕路办法——我们指出它们都不可解释、或没有客观锚点：

方法给每一步信号的来源可解释？有客观裁判锚定？做过受控因果验证？
Agentic Rubrics（2601.04171）只给最终补丁打 Rubric是是否（不分段、不进化）
iStar（ICLR 2026）多轮 DPO 的隐式对数比否否否
RTMC（2604.11037）手工设计的"状态指纹"规则部分是否
Rubric 奖励被钻空子（2605.12474）只做事后相关性分析是—否（事后/相关性）
我们可在前缀检查的"过程 Rubric"条目是是（SWE 测试）是（埋雷池）
一句话定位（可直接写进论文） 别人靠"事后想象 / 隐式信号 / 手工规则"来回避"中间无标准答案"的难题，全都不可解释或无锚点；我们直接补上那个缺失的中间裁判——进化得到的过程 Rubric 条目，在轨迹前缀上检查，汇成一个"不改变最优策略"的势函数奖励，并用埋雷池因果证明它能精准定位到正确的"步"与"维度"。这种"受控分叉"证据，综述指出过往 41 篇功劳分配论文无一提供。

三个贡献点（按"好辩护"排序）

C-P1 过程 Rubric + 可分解性适应度
让进化不只挑"终点区分度高"的条目，而是挑"早期就能预示成败"的条目（条目变绿的时刻与最终成败的互信息）。这个优化目标前人没有。
C-P2 势函数式 Rubric 奖励
用 Ng'99 的势函数塑形，稠密化但保证策略不变，正面回应"Rubric 奖励会被钻空子"。
C-P3 埋雷池做因果功劳认证（招牌、也是最关键最冒险的点）
注入一个已知缺陷，证明前缀分数 Φ 恰好在缺陷发作的那一段、那一维度下跌。这是别的论文产不出的图。实验顺序上要最先验证它。

4做了哪些实验

4.0 测量仪器：能力阶梯 + 埋雷池

两根"坐标轴"：

  • 能力阶梯（自然轴）： 7 个模型从 0.8B 到 671B 排好，强弱由 SWE-bench 测试钉死。好 Rubric 应能复现这个强弱排序。
  • 埋雷池（受控轴）： 取同一个中等模型，复制出若干"兄弟版本"，每个只被注入一种已知毛病。这样唯一变化的就是那个毛病，于是"Rubric 到底抓没抓到它"变成可证伪的问题。

四种核心缺陷（每种对应一个 Rubric 维度，用于画"缺陷→维度"混淆矩阵）：

编号毛病诱导的坏行为应被哪个维度抓到在哪能看出来
D1改测试作弊偷偷放松/删改测试让它"假通过"completeness补丁动了 test_* 文件
D2异常掩盖用 try/except: pass 把报错吞掉completeness补丁在出错处新增宽泛 try/except
D3越界乱改顺手大改无关文件、批量重排版file_changes改动文件数远超必要
D4不验证就交写完补丁从不跑一遍失败测试runtime轨迹里最后没有跑测试的动作
埋雷怎么实现（很巧妙） 不用重新训练模型！只需给同一个模型加一句"作恶系统提示"（如 D2："遇到报错就用 try/except 吞掉"）。而且这句提示会被从给裁判看的文本里剥掉——裁判必须凭行为识别缺陷，不能偷看提示。注：D1 也骗不过最终评测，因为评测永远用原始官方测试重新跑，埋雷只是用来考验"Rubric 能不能看出有人在动测试"。

4.1 论文一（计量学）的实验

  1. 缺陷→维度混淆矩阵（招牌图）： 看每种缺陷是否被对应那一维扣分最多。成功标志是矩阵"对角线占优"——D1 主要扣 completeness、D3 主要扣 file_changes……进化后对角线应更清晰。
  2. 区分度 vs 真实排序： Rubric 分数与能力阶梯的相关性（point-biserial ρ_pb / AUC）。现有结果：进化第 0→2 轮，ρ_pb 从 +0.357 升到 +0.489，AUC 从 0.728 升到 0.810，单调上升；两位裁判一致性 κ≈0.72–0.78，排除偶然。
  3. 留一模型泛化： 用 7 个里的 6 个进化，在没见过的第 7 个上测——堵住"你只是过拟合了模型池"的质疑。
  4. 权重消融： 扫描质量公式里的 α/β/γ，证明提升不是公式凑出来的。

4.2 论文二（过程功劳）的实验（按"先排雷再砸钱"排序）

5对照基线（Baselines）：拿什么和我们比

"基线"就是用来对比的"别人/旧方法"。没有基线，再好的数字也没有说服力。我们的基线分三层：

① 论文一（计量学）的基线

  • 静态 Rubric（= Agentic Rubrics 风格）： 生成一次、不进化。我们的进化版要在同样设置下比它选出更好的补丁（更高的真实 resolve@K）。
  • 随机选择 / 自一致性 / 补丁分类器： Agentic Rubrics 论文里用过的弱基线，证明 Rubric 信号确实有用。
  • 第 0 轮 vs 第 N 轮自己： 进化前后的自我对比，最干净地隔离"进化"本身的贡献。

② 论文二（过程功劳）的 RL 三组对照（P-exp3 的核心）

Arm 1：只用二元 resolved
最朴素的稀疏奖励——通过=1，否则=0。代表"现状"。
Arm 2：第 0 轮过程 Rubric 塑形
用未进化的过程 Rubric 做稠密奖励。隔离"稠密化"本身的贡献。
Arm 3：第 N 轮进化过程 Rubric 塑形
用进化后的 Rubric。期望：Arm 3 > Arm 2 > Arm 1 的 SWE-bench 通过率。
结论逻辑
Arm3>Arm2 证明"进化让 Rubric 更会教模型"；Arm2>Arm1 证明"稠密过程奖励本身有用"。

③ 与其他"过程功劳"方法对标（可信度关键）

  • RTMC（+3.2pp，手工状态指纹的步级功劳）：业界 SWE-bench 上的步级功劳代表作。我们的卖点是"可解释 + 有客观锚点"，因此打平或更好、再加上可读性故事，就是胜利。
  • iStar 风格的隐式步级奖励：作为"不可解释信号"的对照臂。
  • 朴素相加式 Rubric 奖励（非势函数）：用来凸显势函数"策略不变"的独特好处（P-exp4 / P-exp5）。
两个会被评审追问、我们已准备好的点 （1）算力公平： 综述点名"41 篇里 0 篇做算力对齐基线"。我们会上报 GPU 时长、并提供算力对齐的 GRPO 基线——这是便宜的加分项。 （2）前缀打分很贵： 判分调用 = 轨迹数 × 块数 × 裁判数，是主要瓶颈。对策：粗化块数 K、只重判可能变化的条目、最终蒸馏一个"前缀价值网络"让 RL 训练时不再调用裁判。

6风险与现状（诚实记录）

最大风险：小规模试点曾"打平" 在 11 题 / 136 条轨迹的小数据上，缺陷矩阵没有对角占优：只有 D4（不验证→runtime）明显触发（约 +0.48~0.52），D1/D2/D3 的目标格子≈0。原因是那几个"兄弟模型"的通过率太接近（37%~42%），缺陷几乎没拉开成败差距。
为何前缀视角反而可能救场 C-P3 看的是"目标维度下、发作块上的 ΔΦ"，比"最终通过率之差"更灵敏——一个缺陷哪怕几乎不改变最终成败，Rubric 仍可能在过程中看出它在动测试。这恰恰是"前缀视角优于终点视角"的论据。但仍需在更大规模（run03_300）+更狠的缺陷提示上验证，P-exp1 就是成败闸门。
  • 抢发时钟： "Rubric 奖励能提升 SWE RL"这一角度几个月内一定有人做。我们的护城河是 C-P1（可分解性）+ C-P3（因果定位），论文要把这两点放在最前面，而不是"Rubric 奖励有用"。
  • 算力现实： 若完整 RL 跑不动，"离线版"故事（P-exp1 定位 + P-exp2 可分解性 + P-exp4 抗钻空子 + 一个小 RL 确认）本身就是一篇完整的 ICLR 论文——Agentic Rubrics 当年只做了 TTS、没做 RL 也中了。
  • 端点不稳： 跑前先探活真实推理接口（/v1/chat/completions，别只看 /v1/models，它会撒谎）。
