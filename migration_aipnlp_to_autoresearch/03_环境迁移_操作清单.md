# 文件 03 · 环境迁移操作清单

> 目标：把 `cpu_rjh` 的可用环境（启动文件 + 环境变量 + 工具链）在新 autoresearch 容器里还原。
> 数据 GB 级 → rsync。`.rustup` 建议重装（可选 rsync 后备）。

## 一、要迁的启动文件（链式）

```
~/.bashrc                                     # 容器本地，已确认内容
  └─ source …/INS/your-username/login.sh        # 个人空间
        └─ source …/INS/your-username/.bashrc   # 个人空间（真正的配置）
```

三个文件都在 aipnlp 个人空间（或容器本地），rsync 后按下方"路径替换"改前缀即可。

## 二、rsync 命令（个人空间 → 新个人目录）

> 目标 `<NEW>` = 新容器个人目录，形如 `/mnt/your-fs`（建容器后实测确认，见文件 01"建容器后必做"）。

```bash
# 主数据（代码 + 配置 + tofu 数据/记忆/日志），排除可重装的大缓存
SRC=/mnt/your-fs
NEW=<NEW>   # 替换为新容器个人目录的 aipnlp 对应前缀

rsync -a --info=progress2 \
  --exclude='your-username/.rustup' \
  --exclude='your-username/.cache' \
  "$SRC/INS/your-username/"  "$NEW/INS/your-username/"

# 个人数据根（HF cache 等按需，可重下则跳过）
rsync -a --info=progress2 \
  --exclude='.rustup' --exclude='.cache' \
  "$SRC/your-username/"  "$NEW/your-username/"
```

- `--exclude .rustup`：rust 工具链，新容器 `curl https://sh.rustup.rs -sSf | sh` 重装更稳。
- `--exclude .cache`：HF 缓存，可重下；要省下载就去掉该 exclude（会变大）。
- tofu 的 `data/`、`memories/`、`logs/` 随 `INS/your-username/tofu` 一并迁走。

## 三、路径查找替换表（7 类前缀）

> 在新容器里对个人空间的启动文件 / 配置做替换。**先备份再批量替换**（命令见下）。

| # | 旧前缀（aipnlp） | 新前缀（autoresearch 个人目录） | 出现位置 |
|---|---|---|---|
| 1 | `/path/to/your/data | `<NEW>/INS/your-username` | login.sh、`.bashrc`（miniforge3、hope、nltk、入口） |
| 2 | `/path/to/your/data | `<NEW>/your-username` | `.bashrc`（HF_HOME、RUSTUP_HOME、CARGO_HOME、alias hdd） |
| 3 | `/mnt/your-fs` | `<NEW_HDD>/your-username`（若有 hdd 个人盘，否则注释 alias hdd） | alias `hdd` |
| 4 | `/home/your-user/.codex-local` | `/home/<新本地用户>/.codex-local`（容器本地，用户同名则不变） | `~/.bashrc`、个人 `.bashrc`（CODEX_HOME） |
| 5 | `your-user`（hope `.hope` 文件 `afo.dolphinfs.otherusers`） | 新组/个人盘标识 | 各 `hope/*.hope` |
| 6 | `hadoop-nlp-sh02` / `hadoop-nlp-hl02`（数据路径，仅当不能挂载时） | 个人目录对应数据路径 | 训练/数据脚本（311+ 处） |
| 7 | `hadoop-mlp-ckpt`（hope 挂载，仅当不能挂载时） | 新 ckpt 挂载点 | `.hope` 文件 |

> #6 是**大头**（311+ 处），所以**优先争取共享盘可只读挂载**（文件 02、文件 05 待确认 A），就能**一行代码不改**。

## 四、批量替换命令（先备份）

```bash
cd "$NEW/INS/your-username"
# 备份
cp login.sh login.sh.bak; cp .bashrc .bashrc.bak

OLD1='/mnt/your-fs'
# 对新 INS 前缀
grep -rl "$OLD1" login.sh .bashrc | while read f; do
  sed -i "s|$OLD1|$NEW|g" "$f"
done
# hdd alias（若无 hdd 个人盘，直接注释该行）
grep -n "alias hdd" .bashrc
```

> 注意：`hadoop-nlp-sh02/hl02/mlp-ckpt` **不要**在这个表里替换成 `$NEW`——它们是共享数据盘，策略见文件 02/05，不是个人空间前缀。

## 五、验证步骤（新容器里）

```bash
# 1. 启动文件链可加载、不报错
bash -lc 'echo BASHRC_OK; command -v mamba; echo "MAMBA_ROOT_PREFIX=$MAMBA_ROOT_PREFIX"'

# 2. conda 环境在
mamba env list        # 应看到 tofu / sglang

# 3. 关键变量指向新路径
bash -lc 'echo $HF_HOME; echo $RUSTUP_HOME; echo $HOPE_HOME_DIR'

# 4. tofu 数据/记忆在
ls "$NEW/INS/your-username/tofu/.tofu" 2>/dev/null
ls "$NEW/INS/your-username/tofu/data"  2>/dev/null

# 5. 共享盘（若挂载）可读
ls /mnt/your-fs 2>/dev/null | head

# 6. rust（重装后）
rustup --version && cargo --version
```

任一步失败：对照"查找替换表"检查是否漏改前缀；`.bashrc` 里 miniforge3 的 `mamba shell hook` 失败会先落到 `alias mamba` 兜底，看 `mamba env list` 是否真列出环境来判定。
