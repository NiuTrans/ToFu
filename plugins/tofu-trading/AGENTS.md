# Trading plugin guidance

## Scope

This directory owns the optional `tofu-trading` distribution, including its
entry-point registration, owner-scoped storage namespace, demand read workers,
simulation/backtest engines, risk policy, and application UI.

## Editing rules

- Dependency direction is one-way: the host discovers the plugin; core code
  never imports `tofu_trading`. Do not add a second registration path.
- Durable access uses the declared `tofu.storage` manifest and explicit owner
  identity. Never import a database driver, select a backend, or open a host
  database directly.
- Outbound HTTP uses the public `lib.http_transport` host facade. It owns
  automatic proxy selection and connect-only recovery (`docs/NETWORK.md`).
- Models propose intent; deterministic risk, permission, idempotency, limit,
  and settlement boundaries authorize execution. Failure defaults to no trade.
- Read fan-out uses the generated shared demand kernel; worker counts are idle
  hints. Feed, retry, cache, simulation and transaction lifetimes retain their
  explicit owners and shut down through the plugin lifecycle.
- Historical simulation ownership lives in `docs/SIMULATION.md`: `llm_simulator`
  coordinates phases; `simulation_prompt`, `simulation_execution`,
  `simulation_ledger`, `simulation_persistence` and `simulation_reporting` own
  context, model-intent admission, accounting, settlement and presentation.
  Required records commit together before trade/completion publication.
- Host compatibility imports are migration debt and may only shrink; prefer a
  declared public facade/entry-point carrier over new `lib.*` reach-through.
- Shared equity arithmetic lives in `performance_metrics.py`; report-specific
  policies and verification are mapped in `docs/METRICS.md`.
- Web handlers use native Quart. The host projects product API blueprints to
  its active major while retaining request-time gates. The page invokes the
  public `tofu_plugin_assets()` Jinja helper; packaged `entry.js::mount(host)`
  binds shared API/Markdown ports before importing feature modules and init.

## Verification

Run `uv run --package tofu-trading pytest plugins/tofu-trading/tests`, then the
root plugin registry, storage manifest, identity, and monorepo contract tests.
For browser delivery, also run `tests/api/test_trading_native_delivery.py`,
`tests/frontend/test_plugin_frontend_delivery.py` and
`tests/visual/test_visual_plugin_frontend.py`; probe a freshly installed wheel.

`tofu_trading/_worker_executor.py` is generated by
`scripts/gen_packaged_demand_workers.py` from `tofu_workers/executor.py`.
Never maintain a private scheduler or edit the generated copy. Verify drift,
32-read overlap, per-worker repository ownership, startup faults and a fresh
installed wheel. This changes read scheduling, never trade/risk authority.
